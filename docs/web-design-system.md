# C 端设计规范

适用于 `apps/web` 与 Web 专用的 `@tsz/ui`，不适用于管理端。不重新定义品牌：以现有 C 端界面为基线，补充组件和交互约定；配套产品文档中的品牌规范仍为品牌来源。

## 1. 实现与接入

- 基础组件使用 `@tsz/ui/components`，沿用 Tailwind 与 shadcn/Radix 的实现方式；不引入另一套 UI 或表单状态库。
- 简单表单继续使用原生 `<form>`、React 状态和现有业务校验。组件负责展示与原生属性，不承担 API、权限、验证码或密码规则。
- 样式和值以 [主题定义](../apps/web/src/app/globals.css)、[基础组件](../packages/ui/src/components/ui/)为准，本规范说明使用方式，不另维护一套配置。
- 首批统一页面：登录、注册、找回密码。其他 C 端页面逐步接入，不进行全站一次性替换。
- `@tsz/ui` 根出口仍有旧 Button/Card；未迁移页面保持现状，新接入的表单使用 `/components` 出口，避免混用。

## 2. 颜色与明暗主题

| 用途                         | 语义色                                                |
| ---------------------------- | ----------------------------------------------------- |
| 页面背景、内容表面、次级填充 | `background`、`surface`、`muted`                      |
| 正文、次要说明、占位文字     | `foreground`、`foreground-muted`、`foreground-subtle` |
| 描边                         | `border`                                              |
| 主要操作、按钮文字、选中背景 | `primary`、`primary-foreground`、`primary-muted`      |
| 成功、错误及危险操作         | `success`、`danger`                                   |

- 默认品牌蓝沿用当前实现：浅色 `#0071e3`，深色 `#0a84ff`；完整色值只维护在主题定义中。
- 组件使用语义色，不写独立的浅色/深色硬编码配色。白色文字可用于蓝色品牌区和实色危险按钮，不用于普通表单正文。
- 认证页的大面积品牌区在浅色下使用 `primary`，深色下使用 `primary-muted` 深蓝底；亮蓝留给小面积强调，不用于暗黑模式的大块背景。
- 主题由现有主题模块管理，组件不读取 localStorage，也不单独修改 `<html>`。主题切换与刷新后应一致，无水合错误。
- 浅色、深色都必须检查表面、边框、正文、占位文字、聚焦和错误状态；不能只验证页面背景。
- 普通文字对比度目标为 4.5:1，较大文字为 3:1。占位文字不能替代标签；信息不能只靠颜色表达。

## 3. 字体、间距与布局

- 沿用系统字体和现有中文回退字体，不为单个页面引入新字体。
- 常见字号：辅助说明 `text-xs`，表单正文和操作 `text-sm`，普通正文 `text-base`，认证页标题 `text-3xl`。标题使用较高字重，避免把所有文字都加粗。
- 间距以 4px 为基础，优先使用 8、12、16、20、24、32px；同一层级保持一致，不用任意值微调每个页面。
- 认证表单最大宽度 400px，输入框和主按钮占满表单宽度；字段间距 20px，标签与输入框间距 8px。
- 账户资料、安全等设置页统一使用 `max-w-2xl`：返回入口独立在上，标题左对齐并使用 `text-3xl`，下方放简短说明，表单卡片与页头留出一致间距。
- 桌面保留左侧品牌区和右侧表单；小屏隐藏品牌区，表单单栏，左右留 24px。不把手机界面缩成桌面版。
- 输入框、表单操作按钮用胶囊圆角；卡片等容器继续遵循现有页面，不因按钮圆角而全部改成胶囊形。
- 验证码输入框可收缩，发送按钮不挤压文字；长提示可换行，页面不得横向溢出。

## 4. 表单字段

使用 `FormField` 组织标签、输入控件和字段提示，控件使用共享 `Input`。密码显隐按钮使用共享 `Button`，密码状态仍由页面控制。

- 标签始终可见，通过 `htmlFor` 与输入框 id 关联。标签、输入文字与提示采用同一左对齐线，标签和提示距输入框外边缘 16px。
- 输入框默认高度至少 48px。字段提示距输入框 8px，使用 12px 字号和 20px 行高。
- 帮助文字说明用户应输入什么，不罗列技术细节。错误提示说明哪里不对、怎样修改，替代同一字段的普通帮助文字。
- 提示 id 为 `<控件 id>-message`；存在提示时，输入框通过 `aria-describedby` 关联。字段无效时设置 `aria-invalid`，边框与提示共同表达错误。
- 聚焦状态清晰可见，错误字段聚焦时仍使用错误色，不用品牌蓝覆盖错误状态。
- 保留 `type`、`inputMode`、`autoComplete`、原生禁用属性和 ref；手机号、验证码、当前密码和新密码使用合适的输入和自动填充属性。
- 显隐密码按钮始终为 `type="button"`，名称在“显示密码”和“隐藏密码”之间切换，不触发表单提交；保留 20px 图标。
- 首批页面保留现有校验时机，不借组件迁移改变业务规则。登录不套用新密码的长度规则。
- 字段错误在字段下方，接口或整张表单的错误在主按钮上方并使用 `role="alert"`；后者不冒充单个字段错误。

## 5. 按钮与状态

| 类型          | 用途                                   |
| ------------- | -------------------------------------- |
| 默认主按钮    | 登录、注册、重置等主要动作，蓝底白字   |
| `outline`     | 获取验证码等次要动作，主题表面与描边   |
| `secondary`   | 不强调的独立操作，次级填充             |
| `ghost`       | 密码显隐等轻量操作                     |
| `link`        | 文本操作，保持清晰的交互反馈           |
| `destructive` | 确实有破坏性的操作，不用于普通校验错误 |

- 每张简单表单只有一个主要提交按钮。默认按钮高度至少 48px，小按钮至少 40px，纯图标按钮触控区域 44px。
- Button 保留 `variant`、`size`、`asChild` 和原生属性；非提交操作显式使用 `type="button"`。
- 禁用必须使用真实的 `disabled`，同时有可辨识的视觉状态。无法点击的原因应由字段提示、必填内容或正在进行的操作说明，不增加重复文案。
- 请求中锁定必要控件，使用具体状态文字，例如“登录中…”、“发送中…”；防止重复请求。倒计时不改变按钮宽度到挤压输入框。
- 手机／邮箱等互斥内容切换使用共享 Tabs，保持底边线与选中下划线；默认态、选中态、聚焦和禁用都使用主题语义色。
- 表单 Tabs 使用手动激活：方向键只移动焦点，回车或空格确认切换；点击直接切换。实际切换按原业务规则清空目标账号和验证码，不因仅移动焦点清空输入。
- Tab 与 panel 保持关联，包括非激活面板；只渲染当前表单，避免重复控件 id。请求中锁定切换，防止验证码目标发生变化。
- 键盘聚焦标记不能被移除。悬停不是唯一反馈，触屏用户同样能理解状态。

## 6. 反馈、图标与动效

- 成功提示说明已经完成什么及下一步；失败提示给出可操作的原因；空态说明如何开始，不把空数据写成错误。
- 涉及账号安全的错误维持后端语义，不通过文案暴露账号是否存在。组件统一不改变权限和安全规则。
- 装饰性图标使用 `aria-hidden`，图标操作必须有可读名称；图标不可替代全部文字提示。
- 交互反馈优先用轻量颜色变化，不给输入框添加位移、闪烁或循环动效。非用户触发的动效应尊重减少动态效果的系统设置。
- 账户操作菜单使用共享 DropdownMenu，不当作 Dialog；内容通过 Portal 放到 body，并使用与 Select 一致的 `z-50` 层级，不能放在页面动画容器内绝对定位。
- 菜单需避让视口边缘、超高时滚动，支持方向键、Esc 和焦点返回；异步动作先保持菜单打开，成功关闭、失败显示提示，等待中禁止重复执行。
- 弹层等复杂交互复用适合的 Radix 基础能力；未统一的组件不在本次新增实现。

## 7. 文案

- 用用户熟悉的日常说法，短句说明动作或限制，不写成接口规则或技术方案。
- 按钮用明确动词：“获取验证码”“注册账号”“重置密码”，同一动作在提示中保持同一名称。
- 设置密码的常驻提示为“密码至少 15 位”；超长、过短或后端拒绝时再显示对应错误。提示简化不改变实际密码规则，也不增加必须混合字母数字的要求。
- 业务提示不能因追求简洁丢失重要限制；详细规则仅在需要时出现，避免常驻长段说明。

## 8. 接入验收

1. 从基础组件入口使用 Input、Button、Label/FormField，不复制另一份样式或状态框架。
2. 检查空态、合法与非法输入、聚焦、禁用、请求中、显隐及接口失败；回车与非提交按钮行为正确。
3. 浅色/深色切换及刷新后检查颜色、主题持久化和控制台；手机端检查换行、按钮触控区域和横向溢出。
4. 测试 label、描述和错误关联，验证现有业务测试仍通过；组件更改不能改变请求内容和密码规则。
5. 实际构建并启动页面，用 computed styles 与截图核对效果；遵循仓库验收规范，不以类型检查替代页面验收。
