## 1. 总结论

**总体结果：有条件通过。智能词库的核心词条生命周期可用，但还不能标记为“全部功能无问题”。**

已完成真实单词和短语从检测、草稿、词形/发音、词义/例句、预览、发布、发布后修订、再次发布、归档和恢复的完整闭环；列表全部筛选项、批量归档、词性与细分词性 CRUD、重复冲突、关联词、保存重载、错误前置校验也已验证。自动化构建、前后端测试、OpenAPI 契约和 E2E 全部通过。

当前主要遗留：

1. `P1`：真实语音试听链路未就绪。默认构建未启用 `voice-editor`；显式启用后编辑器本身可用，但无可用发音人，无法生成试听；页面“获取语音/上传语音”仍是 Mock 提示。
2. `P1`：新增基本词性在同一会话中没有进入“细分词性”的父级下拉，导致新增后不能立即继续配置细分词性。
3. `P2`：390px 列表只保留词汇和操作列，表头“操作”被裁成“作”；1440px 创建人列仍明显换行拥挤。
4. `P2`：词义、词形两个核心页面文件超过 2000 行，后续修改的回归成本较高。

## 3. 问题清单

### P1-1：语音功能默认隐藏且真实试听链路未完成

**现象**

- 默认构建没有“高级语音编辑”按钮。
- 使用 `VITE_VOICE_EDITOR=true VITE_VOICE_PREVIEW=true` 重建后，按钮和编辑器出现。
- 编辑功能完整可用，但发音人列表显示“暂无可用发音人”，生成试听禁用。
- 向导外层“获取语音”和“上传语音”仍只返回 Mock 提示。

**代码证据**

- `apps/admin/src/lib/env.ts:26-33`：两个能力由独立环境变量控制。
- `MeaningsAndExamplesStep.tsx:407`：`VOICE_EDITOR` 为 false 时直接不挂载 Provider。
- `MeaningsAndExamplesStep.tsx:419-421`：只有 `VOICE_PREVIEW` 为 true 才注入真实 preview adapter。

**影响**

如果语音编辑/试听属于本期交付，当前默认部署配置会让用户完全看不到入口；即使打开前端开关，本地后端仍无法提供声音目录和生成能力。

**建议**

1. 明确测试环境与生产环境是否应启用 `VITE_VOICE_EDITOR`。
2. 配置后端 Azure Speech 与 OSS，验证发音人目录、生成、缓存、签名 URL、播放和失败恢复。
3. 将向导外层 Mock 按钮接到同一真实语音服务，或在未接入前明确标注“暂未开放”，避免看起来像可交付功能。

### P1-2：新增基本词性不能立即作为细分词性的父级

**复现**

1. 新增基本词性 `codex_full_0814`，成功提示出现。
2. 在基本词性列表能搜索、修改该记录。
3. 切到“细分词性”，打开“所属基本词性”下拉。
4. 新建项不在下拉中，无法继续给它新增细分词性。

**代码关注点**

- 基本词性列表使用分页查询；细分词性父级使用独立 catalog 查询。
- `PartOfSpeechSettings.tsx:78-82` 和 `:320-328` 完全依赖 `catalog.data.items`。
- 创建 mutation 虽然失效整个词性 query key，但本次真实操作中下拉未反映刚创建记录，需检查失效/refetch 时序或 catalog 响应一致性。

**建议**

- 为“新增基本词性 → 立即切换细分词性 → 新项可选”补集成测试。
- 创建成功后等待 catalog refetch 完成，或直接将新记录同步写入 catalog cache。
- 同时验证自定义词性 `allowed_form_types=[]` 是否应允许进入创建向导；规则必须由后端契约明确。

### P2-1：移动端和桌面列表信息密度不稳定

- 390px：筛选区可用，表格只保留词汇与操作；“操作”表头被裁成“作”。
- 1440px：创建人名称明显换行，操作列与创建人列视觉拥挤。
- 768px、1024px 的创建向导本身表现正常。

建议为 390/768/1024/1440px 加布局快照；移动端将表格改为卡片或明确的两列布局，避免残缺表头；桌面创建人使用省略号 + Tooltip 或适当增宽。

### P2-2：短语入口文案仍显示“创建单词”

从“创建短语”进入后，系统能正确识别短语并完成发布，但面包屑/页面语义仍显示“创建单词”。功能正确，文案会让运营人员误判入口。

建议在进入向导前带入期望类型，或使用中性文案“创建词条”。

### P3：稳定编码说明与真实状态不一致

修改一个 `usage_count=0` 的新基本词性时，稳定编码被正确禁用，但说明为“编码已被词条引用，创建后不可修改”。实际上该词性显示“未引用”。

建议改为“稳定编码创建后不可修改”，不要把不可变规则错误归因于已被引用。
