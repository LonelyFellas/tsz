# C 端紧凑操作尺寸试改

## 已确认方向

用户原话：

> 你改一个版本试试。本地打开，后端连接测试环境上。

此前问题：词表批量操作与钱包刷新按钮过大，排版不舒适。

本次按 `huashu-design` 的「用户本次会话明说一版就行」例外，跳过三方向初稿，直接在现有应用中试改一个版本。保持现有品牌、内容与业务流程；只调整这两页的操作尺寸、圆角、留白与视觉层级。

## 实施与验收范围

- 批量操作与钱包刷新：桌面 36px 高、14px 文字；小屏保留至少 44px 点击高度。按钮统一沿用现有胶囊圆角，尺寸不引入新的形状。
- 词表创建操作：桌面统一 40px，小屏至少 44px。
- 词表批量栏统一控件高度，收紧栏内留白。
- 新增明确的 compact 尺寸，仅由本次调整的消费者使用；其他按钮保持原有表现。
- 在本任务 worktree 生产构建并以 `next start` 运行，代理到测试环境 API；核对桌面、小屏与深色、选中/取消、移动弹窗及刷新行为。
- 不提交、推送或部署。

## 控件一致性修复

用户追加授权：

> 先修复已实测确认的表单反馈、分段布局、搜索一致性、低对比度文字和加载跳动，保留现有品牌风格。

验收范围：创建任务与修改密码的错误状态、提示关联及修正后更新；分段等宽与小屏点击高度；词表目录、公开词表、词表详情和词典的搜索框清空与 Esc 行为；浅深色辅助文字对比度；钱包刷新保留余额和布局。保持原有接口、校验规则、请求触发方式和权限，不包含未实测的模态风险。

## 偏好浮层修复

用户追加授权：

> 按你建议修正浮层互斥与偏好面板排版，保留现有保存逻辑和品牌风格。

导航、设置和账户菜单共用互斥状态，设置打开时忽略头像悬停、主动点击可切换，取消迟到加载；首页沿用相同规则。英美选项紧跟标签，难度作为只读信息行，保存按钮右对齐并明确只保存学习偏好；保存失败、在途锁定、账号切换与原有请求格式保持不变。已验收悬停/点击/键盘关闭、桌面/窄屏/深色；保存失败重试由自动化回归覆盖，真实保存回读因审批未授权账号偏好变更而未执行。
