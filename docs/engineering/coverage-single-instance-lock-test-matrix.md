# 覆盖率单实例锁测试用例矩阵

| #   | 层        | 场景              | 输入/前置                                   | 预期                                             | 优先级 |
| --- | --------- | ----------------- | ------------------------------------------- | ------------------------------------------------ | ------ |
| 1   | Node 单元 | 并发获取          | 第一个持有锁，第二个同时请求                | 第二个等待；第一个释放后第二个才能获取           | P0     |
| 2   | Node 单元 | 异常释放          | 持锁回调抛出异常                            | 保留原异常，同时释放锁；后续任务可立即获取       | P0     |
| 3   | Node 单元 | 陈旧锁保护        | owner 记录的 wrapper/child 进程均已不存在   | 立即失败并给出人工核对/清理提示，不自动删除锁    | P0     |
| 4   | Node 单元 | 正常锁交接        | `EEXIST` 后，首次读取 owner 前/后原任务释放 | 复核目录与 owner token；消失或换 owner 时重试    | P0     |
| 5   | Node 单元 | 等待超时          | 活跃 owner 持续占锁超过 timeout             | 明确失败并报告 owner，不删除仍在运行的任务锁     | P0     |
| 6   | 命令集成  | test:cov 串行入口 | 两个 `pnpm test:cov` 使用同一工作树         | 都经过同一个锁入口；不再并发写入 `coverage/.tmp` | P0     |

## 边界

- 锁按工作树根目录隔离；不同 worktree 的独立 `coverage/` 可以并行。
- `SIGINT`/`SIGTERM` 转发给 Vitest，并在子进程结束后释放锁。
- `SIGKILL` 无法运行清理逻辑；下一次任务会根据 owner 进程存活状态 fail-closed，需确认没有覆盖率进程后人工删除 `.coverage-lock/`。
