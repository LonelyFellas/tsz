# Node 运行时版本测试用例矩阵

| #   | 层        | 场景                | 输入/前置                    | 预期                                                   | 优先级 |
| --- | --------- | ------------------- | ---------------------------- | ------------------------------------------------------ | ------ |
| 1   | Node 单元 | 精确版本通过        | `24.19.0` / `v24.19.0`       | 版本检查通过                                           | P0     |
| 2   | Node 单元 | 其他版本拒绝        | Node 22、24 其他补丁、25     | 明确失败并提示 `nvm use`                               | P0     |
| 3   | 配置契约  | 本地工具版本一致    | `.nvmrc`、`.node-version`    | 均为 `24.19.0`                                         | P0     |
| 4   | 配置契约  | 包管理约束一致      | engines、Volta、preinstall   | Node 固定 `24.19.0`，pnpm 固定 `10.33.0`，安装前先检查 | P0     |
| 5   | 配置契约  | CI 与容器一致       | CI 三个 job、两个 Dockerfile | CI 读取 `.nvmrc`；容器使用 `node:24.19.0-alpine`       | P0     |
| 6   | 配置契约  | 原生部署运行时一致  | deploy-web、systemd、CLAUDE  | 构建前校验本地/服务器版本；服务使用已校验的 node       | P0     |
| 7   | 命令集成  | coverage 入口防漂移 | 使用非 24.19.0 运行          | 在启动 Vitest 前失败，不创建 coverage 锁或报告目录     | P0     |

## 升级规则

- Node 补丁升级必须一次性修改上述所有权威点，并让配置契约测试保持全绿。
- `packageManager` 与 Volta 的 pnpm 版本必须同步，避免本地与 CI 使用不同 lockfile 语义。
