## 已实现

- admin / web 产物先上传独立暂存目录，再进入服务器全局 `flock` 发布事务。当前制品和候选均验证摘要，成功后切换完整 release，验收失败恢复入口、Nginx 上游、配置和 accepted manifest。
- 当前路径为 `/opt/tsz-releases/{admin,web}/current`。首次迁移复制旧部署，保留旧物理目录；旧 manifest 路径仍可读，新 manifest 写新路径。复制保留符号链接原始内容。
- 静态资源独立存放在 `/opt/tsz-releases/{admin,web}/assets`。按 release 清单和最后退役时间保留 30 天，当前与上一个回滚版本始终保留。重名不同内容拒绝发布，不用新版文件顶替旧哈希 URL。
- HTTPS 与 8081 使用相同的静态资源规则。HTML 重新验证缓存，`version.json` 不缓存，缺失静态资源直接 404。版本标识为 SHA 加本次构建 UUID，避免同 SHA、不同构建开关被当成同一版本。
- web 使用 `tsz-web@3100` / `tsz-web@3101` 两个 systemd 实例，新实例先验活、Nginx 再切流，旧实例等待 30 秒后停用。已有裸 IP 禅道入口只迁移其 web 转发到共享上游，其他禅道配置不变。
- 入口前置恢复脚本独立于 React 和外部 CSS；支持 JS / CSS 加载失败、版本探测、网络失败提示及手动恢复。首页和登录页在无输入且确认新版本时最多自动恢复一次，存储不可用时禁用自动恢复。一次失败不会因马上启动新页面就清空恢复锁；稳定运行 60 秒才释放。
- 普通图片/媒体错误和业务 API 异常不进入全页刷新。信息性更新提示等应用挂载后再显示，避免在 Next 水合前改动页面结构；字符集声明保持在后台 HTML 最前面。
- 词条、句库使用账号与实体隔离的 sessionStorage 恢复快照；服务端 revision 不匹配只允许导出对照，不能自动覆盖。保存成功清理对应快照，注销/切换账号清理不属于当前账号的备份。
- 词条补齐外部导航确认；句库沿用其原有的保存后离开交互，避免同时注册多个 React Router blocker。刷新/关闭页面有未保存提示。
- web 配置 `deploymentId`，生产构建的 release 标识固定内联；定级测试进行中补齐离页提示。Next 两个真实构建间的旧页面导航已经验证。
- Nginx 资源恢复日志只记录版本和静态资源路径，不记录凭据、查询正文或 Referer；浏览器同一资源事件去重，每页最多记录 10 个不同路径。
- 发布事务与双端跨版本浏览器验证已接入既有 CI 门禁。

## 发布与运维边界

首次发布仍须经过 PR 合并及精确 main CI 成功，再运行现有部署入口。部署不会恢复已经被历史发布删除且没有可验证备份的资源；旧页面需要更新一次才能获得客户端恢复能力。

发生 SIGKILL 或断电时可能留下 `/opt/tsz-frontend-transaction`，后续发布会拒绝继续。记录包含暂存目录、组件和旧版本路径；该目录中的 `backup` 保存旧 Nginx 配置、上游、manifest、端口与 previous。先核对当前入口和运行服务，按旧状态恢复并复验，再解除事务记录；不要直接删记录或伪造 manifest。正常错误由脚本自动回滚，回滚失败会保留证据。

历史资源仅在成功发布后回收。磁盘不足会使新产物上传/校验失败，不能通过删除保留期内的资源强行继续。旧物理部署目录在首次迁移后留作人工核对，自动清理仅作用于新的 release 管理目录。

恢复快照保留的是可序列化编辑内容，不能恢复尚未上传的 File / Blob / 临时媒体 URL；发现这类内容或存储失败会提示并阻止无提示刷新，用户需先保存或单独保留媒体。旧代码发生错误时，也不能保证任意局部组件的未提交内部状态均可重建。

当前 C 端练习页还是占位，定级客户端使用内存 mock 会话；本次为定级流程提供离页保护，不伪造刷新后可继续服务端会话的能力。未来接真实学习会话时，需要由会话 API 提供恢复依据。其他未接入恢复快照的页面不允许错误处理自动刷新。

静态资源保留不能替代 API 兼容；破坏性后端变更仍需遵循先扩展、客户端迁移、再收缩。跨 30 天旧版本不承诺继续离线运行，但会进入受控更新/错误恢复。
