# 部署后资源连续性与安全恢复：系统评估

日期：2026-09-16。状态：评估方案已进入本地实施，实际行为与验证见 [实施记录](implementation.md)，尚未部署。

## 目标与边界

正常发布期间，已打开页面继续使用同一版本的 JS、CSS、字体、图片等构建资源；新访问获得完整的新版本。资源加载确实失败时有可理解、可恢复的界面，不无限刷新，不因恢复丢失未保存输入。

覆盖 admin 的直接故障，并评估 web 的同类发布风险。上传音频、业务图片、第三方资源和 API 错误单独分类，不承诺静态资源保留能解决这些问题。不能保证断网、浏览器故障或无限期旧版本永不出错；验收以正常部署不中断、异常可恢复、输入不被静默丢弃为准。

## 建议方案

### 1. 发布完整版本，再切换入口

admin 将新产物上传到独立的 release 目录，完成文件清单与 manifest 校验后，通过同一文件系统中的临时链接加 rename 切换 `current`。不要用逐文件覆盖模拟原子发布；`rsync --delay-updates` 也不是整个版本的原子切换。

静态资源采用按内容哈希寻址的独立资源目录，新资源完整上传并校验后才允许入口切换。相同路径出现不同内容时发布失败，避免覆盖污染。当前 release 的制品仍精确校验，历史资源另有发布清单和完整性校验，不通过放宽 manifest 校验解决目录混杂。

首次迁移先复制当前在线资源并启用双入口读取，再切换发布布局；既有物理目录改为链接需要专门迁移步骤与回退路径，不能直接覆盖。已删除的更旧资源不能凭空恢复；仅从可验证的旧制品恢复，不能把旧哈希请求重定向到任意新版文件。

服务器部署锁覆盖资源更新、入口切换、共享 Nginx 配置和 manifest 接受；admin/web 共享配置的写入必须串行，防止并发发布相互回滚。切换前保留旧版本引用，切换后 HTTPS smoke 失败恢复入口和匹配的 accepted manifest。进程中断时保留事务记录，后续可核对和恢复。

### 2. 旧资源有明确保留窗口

建议默认保留最近 30 天退役版本引用的静态资源，并始终保留当前版本和至少一个已验证回滚版本。这是建议的初始策略，不是现有能力或无限期兼容承诺。

清理依据发布清单与退役时间，不能按构建文件 mtime 删除。当前版本、候选版本、回滚版本引用的资源始终受保护。只回收所有受保护版本均不再引用的文件；清理在发布成功后、同一锁下进行。监测磁盘容量，空间不足时停止新发布并保持当前服务，不提前删除仍承诺保留的资源。

所有构建依赖应使用哈希 URL；不带哈希的 public 文件需逐项审计，变化内容改用版本化地址。业务上传文件遵守独立的数据生命周期。

HTML 保持重新验证缓存；版本探测文件使用 `no-store`。成功的哈希资源长期缓存，缺失资源返回真正的 404，禁止回退成 HTML，也不长期缓存失败响应。HTTPS、8081 和仍在使用的其他入口规则一致。

### 3. 恢复前判断故障与编辑状态

构建生成公开的最小 release 标识（区分同一 SHA 下不同构建配置），同时嵌入入口并作为版本探测文件发布。私有 CI 信息和完整 manifest 不作为前端探测接口公开。

页面启动、回到前台和发生资源错误时探测版本，合并重复请求并限频。探测超时不等于版本更新；版本不同也不证明所有异常均由发布导致。发布回滚时只比较标识是否相同，不按 SHA 排序。

| 情况                                             | 恢复行为                                                                     |
| ------------------------------------------------ | ---------------------------------------------------------------------------- |
| 检测到新版，旧页仍正常                           | 非阻塞更新提示，允许继续工作                                                 |
| 关键 JS/CSS 失败，确认新版可用，明确无未保存内容 | 每个标签页最多一次自动整页恢复；成功稳定后才解除失败锁，防止连续发版形成循环 |
| 有未保存内容、上传/保存进行中，或状态未知        | 不自动刷新；保留当前编辑视图，提供保存后更新、稍后处理或显式放弃             |
| 离线、同版失败、版本探测失败                     | 显示资源/网络加载失败，保留输入，提供人工重试；不误报“版本已更新”            |
| 普通图片、字体、音频失败                         | 组件级占位、系统字体或媒体重试，不触发全页刷新                               |
| 业务 API 错误或程序异常                          | 原业务错误路径处理，不当作资源更新，不自动重放写请求                         |

admin 使用 `vite:preloadError` 获取动态加载错误，并与路由边界协调。不能仅匹配一个英文报错字符串，也不能只 `preventDefault()` 吞错：必须验证 `route.lazy` 拒绝后路由状态、当前组件和恢复界面仍有效。

启动兜底应在入口模块之前生效，使用最小 HTML/内联样式提供错误与重试界面；否则入口 JS 或共享依赖加载失败会让所有 React 兜底失效。限制捕获范围，避免把普通图片失败或所有未处理异常都转换成刷新。

恢复锁使用 session 范围持久化；存储不可用时关闭自动恢复，保留手动操作。只重载当前同源 URL，保留路径、查询和 hash。

### 4. 编辑输入保护是完整方案的组成部分

整合词条和句库的未保存状态、保存中/上传中状态与路由离开保护。不能在根错误页卸载编辑器之后才询问是否保存：那时内存内容可能已经消失。

对关键编辑器在变更时保存恢复快照，按用户、实体、数据 schema 和服务端 revision 隔离；刷新后先确认恢复，不自动提交。服务端 revision 已变化时提示冲突，不静默覆盖。保存成功、退出登录或切换账号后按策略清理。

小型可序列化内容可用 sessionStorage；体积或文件对象要求超出时再使用 IndexedDB。文件/录音的恢复必须单独验证，不能声称 JSON 快照保护了 File、Blob 或临时 URL。存储额度/权限失败时明确提示保护不可用，阻止自动刷新，提供可恢复内容导出。

此处不做跨设备草稿同步或通用表单框架。先覆盖词条、句库及已确认的其他编辑页；自动恢复只允许在明确安全的页面，未接入页面默认人工处理。

### 5. web 按 Next 的运行方式补齐

web 复用静态资源保留原则，但 SSR/RSC 请求不能仅靠历史文件解决。新 standalone 在独立目录、备用本地端口启动并通过健康检查，Nginx 再切上游，旧进程等待已有请求结束后退出；失败切回旧上游。发布期间不得修改旧进程正在使用的目录。

为每次构建设置 `deploymentId`，核对构建环境白名单传递和产物值。框架检测版本不一致可能整页导航，因此学习进度、练习输入等状态保护必须先完成相应审计与回归；不能无条件启用后就宣称无损切换。该参数不会自动保留旧文件，也不会自动按版本把请求路由到旧进程。

不默认引入 CDN、Service Worker 或长期运行所有历史服务。先用现有 Nginx、systemd、构建脚本完成所需能力；持续保留旧服务来处理破坏性 API 变化属于另一个成本级别。

## 跨版本兼容与观测

保留旧 JS 代表旧客户端可能继续调用当前 API。发布需验证支持窗口内的关键契约兼容，破坏性变化按“先扩展、客户端迁移、再收缩”实施。不能承诺静态资源保留 30 天就自动保证 API 兼容 30 天；兼容策略与保留窗口应共同确定。

最低观测覆盖 Nginx 静态资源 404/5xx、发布版本及失败 URL 路径、浏览器恢复尝试/结果。过滤凭据、查询参数和编辑内容。实施时先盘点已有日志接收能力；若没有浏览器事件接收端，需要明确增加最小端点的范围，不能把 console 日志当成已实现线上观测。

## 验收与实施顺序

1. 基于最新主线实现 admin 完整发布、双入口规则、历史资源保留、版本标识、回滚。复用已有配置安装和来源校验。上一轮补丁只作为回归证据，不直接发布。
2. 接入关键编辑状态保护、启动兜底、错误分类和有上限的恢复。
3. 对 web 完成 Next 运行版本一致性、备用进程切换与状态保护。
4. 统一运行质量门和真实构建的跨版本验收，再按另行授权的交付范围发布。

必须覆盖的可观察场景：

- 浏览器打开 A 版后发布 B 版，不刷新访问此前未加载的路由；旧 JS、CSS 及其字体/图片依赖均可用。
- 发布途中不断请求入口与资源，不出现半版文件；上传中断、校验失败、配置失败不影响已接受版本。
- 删除已过期资源后，旧页进入受控恢复，最多一次自动重载；持续故障、禁用存储、连续发布不形成循环。
- 有未保存词条、句库内容或上传任务时发生错误，输入可保留/恢复，保存失败不触发刷新。
- 入口 JS、共享 JS、路由 JS、CSS 分别失败；断网、403、404、5xx、错误 MIME、普通程序异常分类正确。
- 图片/字体失败只局部降级；API 401、500 和提交失败不被资源恢复逻辑吞掉。
- 回滚到 A 后入口、版本标识、资源和 accepted manifest 一致；B 页面在保留窗口内仍能读取 B 资源。
- Nginx 配置使用与生产一致的实际配置，测试 HTTPS 域名和 8081；不能只用 Vite preview 代替。
- web 用生产构建与 standalone 验证，覆盖旧页面导航到新服务的行为与练习状态。

主要实施风险为发布目录首次迁移、共享 Nginx 配置竞争、错误边界卸载编辑状态、快照冲突及 Next 硬导航。工时应在关键编辑页和恢复存储范围确定后按以上关键路径估算，不将评估完成等同于实施完成。
