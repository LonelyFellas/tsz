# 部署资源连续性要求

目标：解决每次部署后旧页面加载 JS/CSS 等资源失败、必须手动刷新才能恢复的问题，覆盖后台与 C 端的发布路径和失败恢复。

## 用户可见行为

- 正常发布后，已打开的页面仍能读取原版本构建依赖；新访问获得完整的新版本。
- 关键资源加载失败时有可操作提示，入口 JS 本身失败也不白屏。
- 只有明确安全的入口且无输入时，允许确认新版后的单次自动恢复；编辑页面、未知状态、离线或同版本故障不自动刷新。
- 普通图片、字体、媒体及业务 API 错误不导致全页刷新或写请求重放。
- 词条、句库编辑内容可从本标签页备份恢复，版本冲突不自动覆盖服务器数据；存储或临时媒体无法备份时明确告知。
- 有未保存修改时，离页/刷新有保护；嵌入句库编辑仍保留原有保存确认。

## 发布要求

- 保留精确 main、成功 CI、干净构建和制品摘要校验。
- 在独立目录准备新版本，通过验证后再切流；失败可恢复旧入口、服务上游和来源记录。
- 使用全局发布锁协调两端共享 Nginx 配置；异常中断保留可恢复证据。
- 历史静态资源按版本引用保留 30 天，当前与回滚版本始终保留。
- HTTPS、裸 IP/8081 入口的相关规则一致；不存在的静态资源返回 404，不回退为 HTML。
- 记录有限的资源失败诊断信息，不收集输入、凭据或 URL 查询内容。

## 验收

- A 版标签页在 B 版发布后加载此前未访问的路由，旧 JS/CSS/图片仍可用。
- 发布中断、制品篡改、Nginx 配置失败、HTTP 验收失败不破坏已接受版本。
- 入口资源失败、离线、存储不可用和版本变化均不产生无限刷新。
- 恢复快照按账号和实体隔离，服务端 revision 改变时要求人工核对。
- 使用真实 Vite/Next 构建与 Nginx/浏览器验证，并纳入 CI。

范围边界：不增加跨设备草稿同步，不自动上传或重放编辑操作，不把旧静态资源保留当作后端接口兼容保证；上线需另行完成 PR 与部署流程。
