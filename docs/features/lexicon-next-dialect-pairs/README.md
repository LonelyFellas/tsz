# 新版词库：英美义项配对（禅道 #177）

范围：新版 Admin 第三步、草稿预览、单条发布及已发布版本。词形拼写照旧处理；没有修改学生词典、出题、AI 或旧词库。前端基线 `084af114`，Rust 基线 `c9279b3`，两仓任务分支 `codex/sense-pairs`。

- 通用是缺省；专用义项可待配对、人工确认无对应义（说明选填），或和同一媒介语词库内另一条英语词条、相反方言的具体义项一对一配对。配对表达等义，不是近义度分数。
- 在第三步选择目标只修改本地草稿；原保存接口一次提交 `expected_revision`、完整草稿和显式 `dialect_changes`。换配核实原目标和新目标的版本与编辑权限。保存争抢或失败不丢输入。解除后原对方回到待配对；要删已配义项应先解除并保存。
- Rust 复用词库写锁和同一事务；每次新建配对写一条不可变身份记录，两端草稿修订引用同一 ID。更新对方时推进版本，保留其内容和目录引用。旧客户端保存保留仍在草稿中的义项标注。永久删除不得留下活跃配对。
- 发布沿用本条词的冻结修订；对方未发布同一配对只给提醒。已发布视图依双方当前可见发布修订解析同一个配对 ID，从对方的发布内容取原形和释义。先发一端无链接，后发另一端即时双向生效；新草稿不影响已发布内容，任一端发布解配或归档后不再出链。历史发布记录不回写。
- Admin 与 API 协商头 `x-tsz-next-dialect-pairs: v1`。旧后端不返回能力或配对字段，新客户端不发送配对写入；新后端对未协商客户端隐藏字段、保留数据。配套上线先迁移及 API，再 Admin。迁移为空时可下行；一旦写入配对或专用义项历史，下行拒绝丢弃数据，也不能回退到不保存义项标注的旧服务端。前端可独立回退。前端 CI 在 deploy/api-target.json 固定配套 Rust 提交的 OpenAPI，部署仍核对线上实际契约。

本地验收（2026-11-16）：使用任务专属 PostgreSQL 18、Redis 7、真实 Rust Router 和 Admin 同源代理。短信使用本地模拟通道，词库请求未使用 mock。用 API 准备两个完整草稿和目标方言；在浏览器将 flat 的住宅义标英式、选择 apartment 的美式义项、保存并从两端重开。预检先发现 fixture 缺少语法字段；用真实 PUT 补齐后重新预检与发布，没有绕过校验。仅发 flat 时已发布视图无跳转；随后发布 apartment，双方可跳到对方的已发布义项，切至美式时高亮 apartment。独立核对两条词各仅一条发布记录（草稿版本分别为 4 和 5）。最终候选重新打开同一发布版本，1440px / 390px 页面无整页横向溢出。

真实 PostgreSQL 的新版词库套件验证迁移上下行、双端重开、换配、并发占用、越权、过期对方版本、草稿与发布隔离、归档/恢复、旧客户端保存与禁止丢失历史。前端覆盖保存失败保留待解除操作及原目标版本重试、旧服务能力协商和严格解码。本地实施与验证完成；配套交付顺序为 API → Admin，PR、CI、测试服版本及验收见两仓 PR。

验证结果：Rust 新版词库 50 项、Admin 定向 102 项、api-client 全包 755 项通过；全仓类型检查 7 项、Admin 生产构建、UI 规范、受影响包 ESLint、Rust fmt/Clippy 通过。候选 OpenAPI SHA-256 为 `c9cb58bd08c3baca0ce84f47c3e22aad53253ce5d4defb04c91800952a11b3ea`，与前端生成输入一致。两套临时容器及两个匿名卷已移除，四个专用端口已释放；专属浏览器站点的认证 cookie、两类 Storage、IndexedDB、Cache Storage 和 Service Worker 均复查为零。未使用 OSS。
