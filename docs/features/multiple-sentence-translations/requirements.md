# 例句多条分档译文

> 注：2026-09-10 起档位改为语义化命名 `word_for_word`（初阶）/ `balanced_fluency`（中阶）/ `adapted_creation`（高阶），初/中/高指译文风格而非 CEFR 难度，服务端也不再按例句等级推导档位。本文记录的是当时口径，其中的 `a1_a2` 一组命名与「低阶」叫法均已废弃。

2026-09-07，用户要求在当前前后端 dev 工作区直接扩展例句汉语译文。

- 每个英文例句可添加多条汉语译文，高、中、低每档均可有多条。
- 用户明确映射：高阶 a1_a2，中阶 b1_b2，低阶 c1_c2。将原“初阶”显示改为“低阶”。
- 添加时选择档位；已有译文也可独立修改档位、正文和删除。档位不再跟随英文例句等级自动改变。
- 至少保留一条输入行。草稿允许正文暂空，完成/发布继续要求填写。
- 现有译文正文、稳定 ID、英文例句、人工关联均保留。修改一条不影响其他条或其他例句。
- 同档按原添加顺序保留，沿用已有跨档整理顺序；不增加拖拽排序功能。
- 页面按每条例句独立区块排版：等级、英文及整句操作在首行；译文放在下方，按高/中/低分组自适应分列，长中文自动换行。译文删除和整句删除分开，不再将多条译文堆在右侧窄列。
- 保存、刷新、预览、发布和历史快照完整展示所有译文。旧数据仍可读写。

验收重点：一条例句至少两条高、两条中、两条低；分别编辑/改档/删除；独立保存后刷新、发布读取仍完整；重复 ID 继续拒绝。条数受现有词条总节点与请求大小保护，不再按每档一条或每句三条限制。

不包含提交、推送、部署；本地验收沿用任务隔离环境。无待确认的产品选择。
