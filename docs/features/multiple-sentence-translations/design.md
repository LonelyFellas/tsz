# 设计与依赖

基线：tsz/dev c6d839e、tsz-rust/dev 66e6920，包含本会话正文关联功能的未提交改动。共享文件集中修改，保留已有功能。

关键路径：解除译文存储的档位唯一限制 → 放宽 V3 校验与生成契约 → 前端编辑列表 → 数据库/浏览器保存发布验证。剩余预估 25–35 分钟。

| 分类       | 能力与处理                                                                                    |
| ---------- | --------------------------------------------------------------------------------------------- |
| 已有、复用 | zh_translations 数组、稳定 ID、旧 zh_text 兼容别名、发布快照恢复、预览逐条展示                |
| 小改动     | 中文译文行添加选档、增删操作；删除别名后选剩余条作为兼容值；取消单条译文档位跟随例句等级      |
| 小改动     | DTO maxItems 从 3 调整至现有 2000 节点量级，取消同档重复拒绝；保留节点、正文、ID 及总请求限制 |
| 新工作     | 数据库仅对非分档译文保留原 slot 唯一索引；译文节点使用不随档位变化的角色及非 stable_slot 身份 |
| 无需新增   | 端点、表、鉴权机制或新的译文枚举                                                              |

数据库 migration 保留现有行、正文和 ID。译文节点用统一角色，使修改 band 不会被节点身份校验拒绝；原 slot 约束替换为仅约束非分档译文的 partial unique index，其他文本字段约束不变。兼容 zh_text 投影写入前暂时恢复别名节点旧身份，完成投影后恢复译文身份。存储 sort_order 使用规范化列表下标，同档顺序不依赖 UUID。

前端新增独立译文列表组件，沿用 antd Input、Dropdown、Button；每行档位按钮可切换高/中/低，添加菜单可重复选择相同档位。已有文字编辑继续使用 replaceRichText，增删改以 ID 为准。旧 zh_text 指向列表中有效的一条，删除别名时选择剩余第一条，服务端沿用其按例句等级选择兼容别名的规则。

后续排版调整将每条例句分为上下两行，首行是等级、英文及整句操作；下方是译文标签、档位分组和添加入口。分组仅改变展示顺序，不改写保存数组；组内保持原顺序、编辑和删除仍绑定原 ID。只展示实际存在的档位，避免单条译文也出现空分组。使用普通 TextArea 自动换行，译文删除按钮默认弱化、悬停强调。分组网格自适应列数，窄容器将标签/添加与译文组换行；原稳定 ID、增删改档、兼容别名及保存契约不变。

发布顺序：先发布兼容新旧响应的配套前端，再部署 migration 与新后端；两端完成前不进行新功能写入验收。旧前端 runtime schema 的 maxItems=3 会拒绝含更多译文的新响应，不能把新数据交给旧前端验收。配套部署按交付记录执行。回退前必须移出同档多条的情况；down migration 遇到无法恢复的多条/已退休节点身份时明确拒绝，不删译文。

验证：组件验证同档增删改、档位独立、稳定 ID 与其他例句隔离；Rust 验证同档多条保存、变档、删除别名、旧客户端省略字段、发布快照及重复 ID 拒绝；同步 OpenAPI 与 runtime bundle 后做契约测试；隔离环境浏览器实际保存六条以上并刷新、预览。
