## WL-UX-01：手机选择文件夹后，目录抽屉继续遮挡内容

- **状态**：已修复。
- **复现步骤**：在手机窄屏打开「我的词表」→ 打开「目录」→ 点击文件夹名称。
- **问题与影响**：路由已切换到目标文件夹，但目录抽屉没有收起，用户看不到已切换的内容，还需要手动关闭抽屉。原路径只执行 `go(id)`，没有调用 `closeDrawer()`。
- **修复**：选择文件夹后调用已有的 `closeDrawer()`，与选择词表的行为一致；桌面目录保持原有行为，单独点击展开箭头仍可浏览目录树。
- **验证**：内置浏览器在 390px 视口、触控模式下，打开目录抽屉并选择文件夹；确认路由与面包屑切换、抽屉收起，焦点返回目录按钮。目录抽屉原有回归测试通过。
- **相关文件**：`apps/web/src/features/wordlist/components/WordlistLibrary.tsx`。
- **回收站入口补充回归（2026-10-18）**：同样遗漏了关闭目录抽屉。新增手机回归测试在旧实现失败：点击回收站后路由已改变，目录抽屉仍在；现将进入/返回回收站接入相同的 `closeDrawer()`，并验证返回后仍是原词表分类。

## WL-UX-02：重命名弹窗没有稳定聚焦名称输入框

- **状态**：已修复；自动化与隔离数据下的内置浏览器复核通过。
- **复现步骤**：打开词表行的「更多操作」→ 选择「重命名」。
- **问题与影响**：浏览器中焦点落在「关闭」按钮；菜单关闭时的焦点恢复还会与弹窗聚焦竞争，导致用户不能直接输入名称。新增回归断言在修复前失败，出现焦点回到菜单触发按钮或页面主体的情况。
- **修复**：原生弹窗打开后聚焦可用输入框；列表和目录树菜单关闭时，如已有原生弹窗打开，将焦点交给弹窗，避免恢复到被遮挡的菜单触发器。
- **验证**：`WordlistLibrary.test.tsx` 的重命名用例验证输入框最终获得焦点、旧名称保留、保存沿用原项目 ID 和版本，成功反馈正常。C 端 69 个测试文件、691 项测试全部通过；最终生产构建、修改文件 ESLint 与格式检查通过。

## WL-UX-03：保存中草稿仍可编辑，失败反馈重复且焦点丢失

- **状态**：已修复。
- **复现步骤**：重命名词表 → 修改名称并保存 → 请求未结束时继续输入；或模拟名称冲突后重试。
- **问题与影响**：请求中名称输入框仍可编辑，界面草稿可能与正在提交的内容不同；失败提示同时出现在弹窗和背景中；浏览器中禁用保存按钮后焦点落到页面主体，重新编辑需要再次点击。后端错误已有句号时还会重复拼接句号，并要求用户刷新，容易丢失待修改的输入。
- **修复**：请求中锁定草稿与取消；失败只在弹窗显示一次，保留名称并重新聚焦输入框；去掉重复标点和统一强制刷新的提示。未修改名称时禁止重复保存。
- **验证**：新增回归测试在修复前因输入框未禁用而失败；修复后验证请求中锁定、失败保留、单一错误提示及焦点恢复。浏览器已复现名称冲突与草稿保留，最终修复后沿相同路径确认错误文案、输入焦点与重新保存正常。

## WL-UX-04：移动或恢复请求期间仍可切换目标页

- **状态**：已修复。
- **复现步骤**：打开包含多页目录的目标选择器 → 发起移动或恢复 → 请求中点击「下一页」。
- **问题与影响**：分页没有继承请求中的禁用状态，显示的目标可以在提交过程中变化，用户难以判断实际提交位置。
- **修复**：请求中锁定目录、面包屑、分页和确认操作；目录读取完成前不允许提交；明确显示目标位置与动作名称。
- **验证**：`LibraryFolderPicker.test.tsx` 在修复前确认「下一页」仍可点击；修复后通过。另验证进入文件夹后提交的是当前显示的目标 ID。

## WL-UX-05：所选文件夹子目录检查（已排除）

- **结论**：不属于已确认 Bug，已移除针对该情形的冗余分支。
- **核对结果**：当前目标选择器的接口只返回当前目录的直接子节点；已选文件夹的入口本来就会被禁用，因此不能经正常路径进入其子目录。最初人工 fixture 将父目录和其子目录并列返回，不能证明真实链路存在问题。
- **处理**：测试改为验证原有的「所选文件夹不可作为目标」行为，保留服务端的循环引用约束，不用不符合目录语义的样本宣称修复。

## WL-UX-06：固定批量操作栏被站点顶栏遮挡
