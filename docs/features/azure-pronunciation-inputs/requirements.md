# 任务 54：独立的 Azure 发音输入

状态：已按批准方案实施手工输入、持久化、来源选择与合成接线；自动转换为有明确边界的部分实现。日期：2026-09-15。
验收证据与未完成项见 [verification.md](verification.md)，业界调研见 [industry-practice.md](industry-practice.md)。
来源：用户提供的禅道任务 54 截图；不包含父任务 52 的其他优化。
基线：前端本地 main `0d35927401b79aab379ec61f9479642c8e810f50`；后端本地 main `4ad21fadc3f66dabdfa0e23d0009df7fedbb730e`。

## 目标

在后台 V3「词形与发音」中，将教学展示、实际发音标注与 Azure 合成输入分开。
每条发音独立保存 Azure IPA、Azure UPS 及选中来源，适用于英美共用、英式、美式和各类词形。

## 推荐交互

| 项目      | 推荐行为                                                                 |
| --------- | ------------------------------------------------------------------------ |
| 字典音标  | 继续录入和展示；作为主动转换的输入，不直接发起合成                       |
| 实际发音  | 保持当前文本及连读编辑                                                   |
| Azure IPA | 普通文本框，可直接输入、粘贴、修改；左侧「转换为 IPA」，右侧发音设置入口 |
| Azure UPS | 普通文本框，可直接输入、粘贴、修改；左侧「转换为 UPS」，右侧发音设置入口 |
| 合成来源  | 单选 IPA/UPS，默认 IPA；两个框均可编辑和保存，只有选中的来源用于合成     |
| 发音设置  | 复用音色、语速、逐音色试听能力；两种格式共用当前发音的 voice_profile     |
| 真人录音  | 仍归属当前发音，复用现有上传与播放能力；切换格式不删除录音               |

左侧使用转换图标和明确提示，不继续使用扬声器图标。选中来源的右侧入口打开同一个发音设置面板；未选中来源先选择再试听。最终播放使用当前选中内容。
面板明确显示「当前使用 Azure IPA/UPS」。本方案不新增麦克风采集或语音识别。

## 转换规则

1. IPA 按钮执行「字典音标 → Azure IPA」，只写 IPA 框。
2. UPS 按钮执行「字典音标 → 内部 IPA 中间结果 → Azure UPS」，只写 UPS 框，不覆盖页面 IPA。
3. 两个按钮始终使用字典音标。页面上人工修正的 IPA 不会隐式成为 UPS 转换源；按钮提示明确来源。
4. 转换不改选中来源。手工输入、切换来源、修改字典音标均不自动启动转换或合成。
5. 目标为空且转换完整成功时直接填入；目标非空且结果不同时，先展示将替换的结果，用户选择应用或取消。输入框支持撤销。
6. 未知符号、歧义或不支持的组合须定位并说明；转换失败不部分写入，不猜读音，不静默删除符号。
7. 转换表更新不重写已保存结果；用户需要时主动再转换。

按任务正文采用以上来源规则。若以后需要「手工修正 IPA → UPS」，应另设有明确名称的动作，不让同一个按钮随内容变化改变来源。

## 编辑、保存与历史数据

- 新输入保存在发音记录中，刷新、保存其他步骤、发布、历史读取及复制词形均不得丢失。
- 草稿允许未填完。两框都空等同未配置合成；已有内容但选中框为空时，草稿可以保存，试听及完成/发布定位提示。
- 推荐不新增「必须有音频才可发布」门槛：完全未配置合成的记录继续遵循原有发布规则。
- 未选中的候选内容可保留草稿状态，不要求两套都有效；切到它进行合成时才执行目标格式校验。
- 旧记录不自动批量回填音标，不重合成历史音频，不改写已发布快照。
- 旧字典富文本继续保留，编辑普通正文时沿用现有标注调整机制保持正文一致；新合成入口不读取旧字典富文本。
- 真人录音继续保留。旧记录没有 Azure 输入时，新合成入口提示先转换或录入，不退回字典音标直接合成。
- 共用/英美分栏转换沿用现有显式映射流程：复制时复制两套候选和选中来源；合并差异内容时不能静默选边或丢弃。

## 推荐边界

本任务保留发音人、语速、试听和真人音频功能。IPA/UPS 框是音素输入，重音和音节边界用各自符号表达，不把完整富文本标注工具搬到两个框中。
旧字典音标中的任意停顿等标注不自动迁入音素字符串。若要求在新输入上继续逐段插入任意停顿，应补充音素分段需求，不能直接把 SSML break 插入一个 phoneme 内。
不改变词形识别、发音去重和例句关联的业务规则；不将本任务扩大到整站语音编辑器改版或历史数据批处理。

## 验收标准

1. 每条发音的两套内容及选择互相独立；同页多发音、多词形、共用/英美切换后仍准确。
2. 两个转换按钮各自只写目标框；未知符号失败、已有手工内容的取消与撤销均不丢数据。
3. 保存、刷新、保存词义、发布、重新打开和历史读取能还原完整配置。
4. 实际请求以拼写为正文，以选中音标为 phoneme 参数，alphabet 准确为 ipa/ups。
5. 更改选中音标、来源、拼写、音色或语速后不播放旧请求回包；仅改未选中内容或字典展示音标不改变当前合成结果。
6. 真人录音引用在修改和发布后仍有效；切换来源不触发删除或回收。
7. 已配置目标无效时能定位错误；完全未配置合成的旧记录仍能正常保存和按原规则发布。
8. 用正式配置的英式、美式 Azure 发音人分别验证 IPA/UPS 请求和听感；mock 或仅 HTTP 200 不替代音标准确性验收。
