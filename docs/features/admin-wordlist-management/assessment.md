## 推荐的首期闭环

### 管理列表

- 关键词覆盖词表名称、创建人；公开状态、推荐状态、创建时间范围支持组合查询、搜索、重置和服务端分页。
- 自定义词筛选不伪造：首期仅有智能词汇，明确提示该能力尚未开放；后续接真实来源字段。
- 展示 ID、名称、词汇数、是否含自定义词、公开状态、审核状态、推荐、作者、创建时间和操作。题量/点赞/收藏显示「—」。
- 投币统计建议按累计投币枚数，使用整数安全传输；若产品要统计投币人次，应改列名为「投币次数」，不混用。
- 查看读取当前内容；审核查看绑定提交时快照，两者不能共用一个模糊的「查看审核」入口。
- 创建、编辑、删除、切换公开、推荐分别有服务端权限和操作审计，不能只在 UI 隐藏按钮。
- 推荐只允许公开词表。转私密或删除时原子取消推荐，C 端推荐查询仍强制检查可见性。
- 删除采用逻辑删除，业务读取立即不可见，保留审计与历史投币流水；不增加原型未要求的回收站页面。

### 创建与编辑

- 独立 Admin 页面，固定标题/操作区与词汇搜索区；采用 antd，不照搬截图布局或 Web 的 Tailwind 组件。
- 名称 1–100 字；逐行选取已发布平台单词/短语，候选最多 3 条；选中后释义只读。
- 候选释义调整为前两个可展示词义各取第一条中文释义；缺失时如实留空，不由备注补齐。
- 首期未匹配词不能保存为自定义词，保留输入并提示重新选择；搜索失败与无匹配必须区分。
- 行支持新增、删除确认、排序和备注；保存前定位错误行，不能只弹统一失败提示。
- 新建默认私密。保存创建请求幂等；编辑校验版本，冲突不覆盖；不确定的网络结果保留输入并允许核对/重试。
- 返回、内部导航及关闭/刷新页面均保护未保存内容。
- 建议公开词表修改名称/成员时，明确提示「保存后转为私密并取消推荐」；管理员可再次直接公开。这比增加公开版/草稿版双版本机制简单。
- 管理员编辑用户词表时保持作者身份，不读取或修改用户的私密备注；后台自建词表的备注建议仅后台有权限者可见。

### 公开、审核、推荐规则

公开状态与审核状态独立存储；审核结果绑定内容版本，保留历史记录。

| 动作                              | 公开状态    | 审核状态              | 推荐       |
| --------------------------------- | ----------- | --------------------- | ---------- |
| 新建词表                          | 私密        | 未申请（界面「—」）   | 否         |
| 师生申请公开纯智能词表            | 公开        | 自动通过              | 默认否     |
| 师生申请公开含自定义词表（后续）  | 私密        | 待审核                | 否         |
| 审核通过 / 拒绝（后续或历史申请） | 公开 / 私密 | 通过 / 未通过         | 不自动推荐 |
| 管理员创建的词表设为公开          | 公开        | 无需审核（界面「—」） | 可设置     |
| 管理员强制切换用户词表可见性      | 按操作设置  | 不改变已有审核状态    | 私密时取消 |
| 删除                              | 不可见      | 保留历史              | 取消       |

管理员强制公开待审词表后，可以出现「公开 + 待审核」，这是原型允许的组合；不能靠旧的单一 state 推算两列。
审核动作始终验证快照对应的内容版本；推荐和可见性操作不得把旧内容误标为当前版本已审核。
对历史待审/拒绝词表不在迁移时批量自动公开。自动通过适用于用户新发起的纯智能词表公开操作。

## 新增原型的后续阶段

### 自定义词汇

- 词表项增加稳定 item_id 和来源类型；智能项引用 entry_id，自定义项保存词面、释义和语音设置。
- 自定义项以词表为边界保存，不直接写进智能词库，不把相同词面自动当成同一条词。
- 搜索无匹配且请求已成功完成，失焦后出现必填释义；返回编辑时保持原来源，不自动改绑新出现的平台词条。
- 含自定义词的用户公开申请走快照审核；后台作者无需审核。审核中修改内容使原申请失效。
- 阅读、编辑、审核、导入和将来的学习任务必须一起识别两类项；自定义内容不能直接套用智能词汇的多层词义/出题结构。
- 教师任务仍另期。自定义词加入现有个人学习任务前也需明确题型支持，不能把「能阅读」当成「能出题」。

### Excel 与识别导入

- 原型支持 `.xls`、`.xlsx`，最大 10 MB；模板固定「词汇 / 释义 / 注释」。解析方案在实施时验证两种格式，不静默缩成仅 xlsx。
- 流程：解析 → 字段/行数/长度校验 → 批量匹配 → 预览修正 → 确认追加到编辑器 → 保存。
- 导入只填编辑状态，不立即写数据库；任一错误显示文件名、行号和字段，修正完毕才确认，不静默丢弃错误行。
- 只对唯一精确匹配自动绑定；近似匹配必须人工选定，不能默认取第一个候选。重复平台词条建议阻止并标明位置。
- 识别导入复用完全相同的 Excel 入口，仅增加模板、可复制/展开提示词和操作说明；不建设 OCR、模型调用或外部 AI 自动上传。
- 无真实操作指南链接、客服联系方式和二维码时不使用原型示例；这些是上线内容依赖，不是数据模型依赖。

### 自定义语音

- 复用现有 TTS provider、内容指纹去重和对象存储，补充词表音频资源关联、权限、生成状态及清理生命周期。
- 推荐保存文本事务成功后异步生成；生成失败可重试，不能把文本保存也报失败。明确区分「保存成功」和「音频就绪」。
- 全局开关决定新行的默认选择，单行可覆盖；更改全局默认不悄悄覆盖已编辑行。
- 后台不校验/扣用户天生币，但仍检查生成权限并限制重复任务。
- 生成对象、默认口音/声音、是否需要朗读释义尚待产品确认；建议首版只朗读自定义词面。

## 数据与接口影响

- `wordlists`：管理员/用户作者二选一约束、独立可见性和推荐、逻辑删除；审核关联内容版本。
- `wordlist_items`：首期保留平台引用；自定义阶段再引入 item_id 与来源结构，避免首期预写尚未使用的模型。
- Admin：扩展分页筛选，新增当前详情、编辑快照、候选目录、创建/更新/删除、可见性和推荐端点；保留审核快照端点。
- Web：接系统推荐查询，调整纯智能词表公开流程与文案，并支持平台作者展示。
- 平台词表没有现成用户收款方。建议首期不提供投币入口，并由后端拒绝；不得伪造用户身份或默认把款转给管理员。
- `@tsz/types` 与 api-client 保持 snake_case，使用后端 OpenAPI 原生生成链同步严格 runtime schema。
- 作者类型会影响公开阅读、投币、账户注销和已有个人学习任务，不能只修改管理页。

兼容与迁移：先发布能读取旧数据及新作者表示的消费者，再启用产生管理员词表的新功能。
新增管理字段优先放独立管理 DTO，避免无条件扩展旧公共响应；实际新旧组合仍须以生成 schema 验证。
旧单一 state 保留过渡映射，明确历史审核记录和新独立字段的归属，不能双写后无一致性规则。
迁移须有 up/down；存在新管理员词表或自定义项时，回退旧模型不得静默删除数据，应拒绝破坏性 down 或先做明确的数据处置。

## 剩余关键路径、估算与验收

关键路径：作者/状态与权限 → 管理 API 与迁移 → 契约同步 → Admin 列表/编辑器 + Web 推荐 → 隔离环境真实验收。

- A：已确认的管理闭环与纯智能编辑器。粗估 4–8 小时有效工作，包含定向验证，不含未就绪环境等待。
- B：自定义项及条件审核。额外约 1–2 个工作日，需明确学习能力边界。
- C：Excel 与外部 AI 辅助导入。额外约 0.5–1 个工作日；可独立做纯智能导入，但与 B 一起落地可减少未匹配行处理的返工。
- D：自定义语音持久化与状态反馈。额外约 1–2 个工作日，取决于存储和真实 TTS 验收条件。

此前 90–120 分钟是未完成依赖调查的初估；管理员作者涉及学习/投币/注销消费者，加上新增编辑原型后不再适用。

验收重点：

1. 管理员创建私密词表 → 保存 → 重新打开，名称、顺序和后台备注一致；用户无法越权读取。

5. 每个筛选及组合筛选查询真实全量分页数据，搜索和重置回到第一页。

## 选词搜索优化与规模验证（2026-10-12）

### 实现

新增 `GET /api/v1/admin/wordlists/suggestions?q=...` 与用户端 `GET /api/v1/wordlists/suggestions?q=...`。Admin / Web 创建编辑器均已改用此接口，返回只有 `items`，最多 3 个不同 `entry_id`，没有总数、分页或全量内容。
旧 `catalog` 分页接口保留兼容，已不在新选词交互中调用；以下性能结论只针对新的 suggestions 接口。

- 统一使用现有 `surface_sources` 当前发布投影、词面归一化和词条身份，不新建搜索服务或重复维护一份词库。
- 精确匹配复用 `lexicon_surface_sources_v3_lookup_idx`；1–2 字符仅做精确匹配。
- 3 字符起补前缀结果。增加 C collation 的有序前缀索引，以明确的上下界读取，按词条去重后最多再查两次；避免宽前缀聚合所有命中项。查询同时检查当前发布指针与归档状态。
- 普通单词纠错复用已有 `lexicon_surface_sources_published_surface_trgm_idx`（GIN）。包含空格且长度至少 8 的长短语走新 GiST 最近邻索引，先取最近的最多 32 条词面，再校验可用性、长度并按词条去重；按已选词条排除后最多 3 轮。
- 纠错是有界联想，不保证枚举全部近似结果；极端重复/失效数据可能使候选不足 3 条。精确与前缀查询不采用这个截断窗口。
- 新 GiST 的部分索引条件 `char_length(surface)>=6` 与长短语纠错的长度窗口一致，也让普通单词查询继续选择更快的现有 GIN。没有全局禁用顺序扫描或强制优化器开关。
- 只对最终选中的最多 3 个当前发布记录读取名称与两条释义摘要，每条摘要最多 200 字。SQL 不将完整发布 JSON 传回应用；完整词汇内容仍在详情读取时加载。
- 两端均使用 250 ms 防抖和请求取消；回归测试验证旧请求完成后不能显示过期候选。

新增索引迁移 `20261012140000`、`20261012150000`，均有 down，仅删除对应新索引；已有索引保持不变。本次测试集上新增索引约 40 MB + 52 MB。正式应用迁移时需考虑普通 CREATE INDEX 对词面写入的锁定时间，当前未执行部署。
