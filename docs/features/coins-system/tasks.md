### B1a 的完成边界

- 交付可被业务安全调用的核心和本人查询，不增加业务奖励算法、不做收款页面。
- 可以在隔离测试库直接调用服务验收，不提供临时生产发币接口，也不靠手改余额测试。
- B1b 未完成前不对真实账号开放记账，避免现有立即注销流程与新账本混用。

### B1b 的完成边界

- 延迟注销归属账号模块，钱包只提供事务能力。
- 必须同时覆盖登录、refresh、旧 access token 与敏感写入的锁后到期检查；不能只测试 worker 删除成功。
- 申请/撤销/worker 锁序统一；时间检查用锁后的数据库实际时间，不能被锁等待跨越截止时间绕过。
- 存在申请后不能回退到忽略等待期的旧后端；不因 worker 暂停重新开放账户或延长撤销期限。

### B2 的完成边界

- 首个运营可验收版本：人工发放 → 两端钱包到账 → 查询流水 → 必要时按原单纠错。
- 客服真实联系方式属于上线配置，开发可测试缺省/未配置状态；不编造联系方式，不因此阻塞核心。
- 购买核验只是人工记账依据；不在本批引入支付网关、汇率、退款、图片凭据上传或商城。
- 对外售币建议等首个真实消费路径可用后开放；本批交付不代表词表投币已经能用。

5. 用户已要求在新聊天继续。交接携带两仓 SHA、未提交差异、当前失败/成功证据与下一项。
6. 实施安排不包含新的 commit/push/PR/合并/部署；它们继续按当时用户指令执行。B4 的“可以提交”只覆盖已提交的 B4，不自动覆盖后续词表改动。
