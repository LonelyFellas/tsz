# COIN-12 学习奖励需求

日期：2026-10-07。状态：用户已授权开工，按会话明示的推荐口径实现；每日金额 A、最低题量 N 及实际启用日期仍待确认，交付默认关闭。测试数值只用于独立 fixture，不是生产配置。本轮授权覆盖实现与隔离验收，不包含提交推送、合并、部署或启用真实发币。配套 [技术设计与验收](learning-rewards-design.md)，总任务见 [tasks.md](tasks.md)。

## 1. 目标与不可改变的基础

为真实学习完成接入天生币，服务端计算奖励，学生在学习结果和钱包看到可核对的结算状态。复用 LT-01～LT-04、coins 核心与账号生命周期，不重建学习系统。

- LT 已于 2026-10-07 合并并部署到 tshb-test：后端 PR210、前端 PR371。本次 fetch 的最新 main 与该次部署 SHA 一致；这是代码和历史部署证据，不代表本轮重新验收线上。详情见学习设计的发布记录。
- 学生自建每日/长期任务，看中文释义拼写英文；规定题量全部有效首答即完成，合法错误计进度，正确率独立统计。
- 不增加正确率、时长或全部答对门槛。下文 N 是奖励门槛，绝不改变一个 1 题任务可完成的事实。
- 北京时间 04:00 换日。每日 ends_at 是整个任务结束时刻；长期可以跨日，完成后显式新开后继。
- 完成依据为服务端 `learning_completions` 与题目/首答链，不接受客户端 completed、停留时间、旧 PracticeRecord 或奖励金额。
- 待注销的 72 小时内学习资格沿用现状，但钱包暂停全部收支；到期禁止学习写入。物理删号删除学习明细，独立账本和签署保留。
- 主线当前完成不会发币；本次实现默认仍不发币。旧 `DAILY_CHECKIN_COINS = 10` 不是本次金额来源。

## 3. 推荐候选的完整产品行为

用户于本会话要求“可以开始实现开工了吧”，已按以下明示口径推进代码和验收；A/N 和真实启用仍未确定，不因开工自动发币。若选择其他计奖口径，需同步调整实现和验收。

1. 参与者是具有真实学生资格的 C 端账户；同账号教师/学生共用钱包，每个 user UUID 每日最多 A 币。Admin、邀请、词表投币互不占用本项日额度。
2. 只统计本业务日**已完成的每日轮次**里的有效首答。未完成、失效、过期轮次不累计；错误首答也累计。先前已完成的事实不会因后来来源撤回而倒扣奖励资格，内容仍按当前权限隐藏。
3. 去重单位为现有 `(entry_id, pos_id, sense_id)`。同一单元换词表、新建任务、换 publication、改名或重新开始都不会在同一天多计。次日可重新计奖；不同义项是不同单元。平台重新建立全新语义 ID 不在学习者自助能力内，不增加语义相似度引擎。
4. 多个短任务可以累计不同单元；不能靠一个单元创建 N 个任务凑 N。累计达到 N 时一次发 A；不足 N 不发，超出不增发。显示“奖励进度 min(去重数量,N)/N”，不要把截断计数说成全部学习统计。
5. 奖励业务日为每日 completion.business_day，须与该完成时刻的既有 04:00 窗口一致。已成功请求跨日重放只返回原学习事实/原奖励查询结果，不结算新一天。
6. 推荐所有常规规则（含关闭、金额、N）从未来业务日 04:00 生效，当天不修改、不追溯；首次开放也选择未来业务日，开放前的 completion 不补发。未配置时关闭，不能隐式套用测试金额。此生效政策属于实施口径（尚未启用）。
7. 规则关闭时，第一个参与范围内的 completion 记录当日 `reward_disabled`，学习照常完成。规则开启但未达 N 时仍可累积；首次达 N 时钱包为 `deletion_pending/closed`，记当日 `wallet_unavailable`，零入账。撤销注销后当日不再补发，次日重新判断。未达 N 前撤销注销，之后达标时钱包开放则可正常奖励。
8. 账号已停用/已到注销时刻不接受新的学习完成，不制造奖励记录；已合法完成并入账的奖励不因后来停用而追扣。注销执行时按原签署及作废流程处理余额。
9. 配置关闭、钱包暂停是业务不发奖；数据库、余额溢出、账本约束或审计写入故障是技术失败，整笔末题事务回滚，可原键重试，不显示“已完成/已到账”。这沿用末题持久化的原子性，但增加账本故障对末题可用性的影响。
10. 无领取按钮、自动补发任务、运营批量补发入口或通用规则引擎。若要求学习完成不受账本故障影响，需改为持久后续结算，不能把失败吞掉或提交后裸发币。

## 4. 用户可见流程与异常

- 学习页沿用“本轮已完成”和正确率；另列“今日奖励进度/已到账 A 币/奖励未开启/钱包暂停未发放”。某个新任务完成时，当天已到账不再弹一次到账提示。
- 钱包获取入口展示服务端规则及学习链接；流水以学习奖励来源展示，只以真实操作 UUID 和金额判定到账。
- 奖励 GET 超时或解析失败显示“奖励状态暂时无法读取”，不改写已保存学习事实、不伪造零金额。旧 API 不支持新奖励端点时显示“奖励功能尚未就绪”，原学习与钱包继续可用。
- 刷新、换设备、响应丢失按服务端恢复；跨号请求取消、缓存按用户隔离。领取成功状态不能由浏览器缓存推断。
- 来源失权后的奖励只展示本人日汇总和金额，不复制被隐藏题面、答案、来源名称或作者信息。

## 5. 验收标准与范围外

必须证明：不同任务并发/不同请求键也只发一次；重复单元不凑门槛；全错可完成并按相同规则计奖；04:00 和用户/钱包锁等待不越界；规则版本不改变历史；关闭/暂停/注销不绕过；技术失败无半账；删号后学习明细清除而最小奖励审计和流水保留；新旧客户端/API/schema 组合明确。

可执行命令、具体断言和混合版本步骤见 [设计末节](learning-rewards-design.md#验收)。本轮实现与隔离测试结果见技术设计验收记录；没有生产迁移或发币。

范围外：真人/机器人识别、正确率奖励、长期按首答日期追溯、教师任务、连续打卡、排行榜、在线规则后台、补发/追扣/兑奖、奖励额度跨业务共用。每日限额能约束单账号发行量，不能证明用户真正掌握知识或消除多账号行为。
