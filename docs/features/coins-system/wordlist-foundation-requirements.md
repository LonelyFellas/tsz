# COIN-11 前置：词表基础业务需求

日期：2026-10-06。状态：最小词表闭环及 COIN-11 已实施并验收，见 [验收记录](wordlists-tips-acceptance.md)；未提交、推送或部署。

本目录为唯一维护位置。后端方案见 [词表基础设计](wordlist-foundation-design.md)；本前置不计入原 COIN-11 的投币接入工作量，也不表示投币或学习任务已可用。

## 1. 确认规则与范围

用户于本轮明确确认：

1. 首批只从平台**已发布词库**选词，暂不实现自定义词汇。
2. **全部公开词表经管理员人工审核**；私密保存无需审核，公开内容修改须重新审核。
3. 平台词库发布更新后，词表自动读取该词条**最新发布内容**，不固定旧 publication。
4. 词条下的“注：用户自己的想法”**仅作者本人可见**，不随词表公开，也不进入管理员审核快照。
5. 游客或尚未设置等级时按 **C2 预览**，不写入/修改学习等级；某个词义不存在当前或更低等级释义时，明确显示**暂无适合当前等级的释义**，不自动向上取。

沿用可查的产品范围：师生均可自建词表，有公开/私密之分。教师、学生属于同一 C 端账号，作者取登录 user UUID，切换身份不转移所有权。现有公共词表浏览允许游客；匿名 mock 创建不作为真实匿名创作授权。

首批建议闭环：登录师生搜索已发布平台词条 → 选择/排序 → 保存私密词表 → 提交公开审核 → 管理员通过/驳回 → 游客或其他账号浏览已公开内容 → 作者撤回后编辑、重新审核 → 管理员必要时下架。

本轮没有引入平台/Admin 作者、作者转让、合作编辑、评论、收藏、班级推荐、学习集、学习进度、每日任务、自定义词汇/词库、自动内容审核、音频和动态例句播放。总产品文档包含的收藏/推荐等要求保留为后续范围，不当成已经删除的需求。COIN-11 转账和投币页面另批实现。

### 完整模式与展示规则补充

新增参考：[完整模式](references/wordlist-detail-full.png)、[详情规则便签](references/wordlist-detail-rules.png)。以下记录原型目标；首批与后续的功能边界仍按上文，不把截图中语音/自定义词/社交按钮当作额外实施授权。

- 详情默认标准模式，可切换完整/简洁。标准图与完整图已提供；简洁模式的具体列及折叠规则尚未提供，不能仅凭名字自行定义。模式改变是阅读呈现，不改变词表内容、作者或审核状态。
- 完整模式的列为英文词汇、基本词性、词形变化、细分词性、多维释义、语法结构，按基本词性及其词义层次组织。不同来源的单词/短语混合排列；自定义词未来只有词面和释义，缺少的字段留空，不借平台数据假装匹配。
- 标准详情也不是展示同一词义的全部分级释义：**每个 sense 选择一条适合当前读者等级的释义**。先取同级，没有则取最近的较低等级；同级候选优先中文，确无中文再英文。多条词义各自选择，因此画面仍可能同时出现 A1/A2/B1 标签。若同级同语言仍有多条，建议按发布稿顺序取首条，保留确定性，不随机选择。
- 教师按当前“教师角色查看”的 C2 展示；学生按其已保存学习等级。不能仅因账号拥有 teacher 角色就忽略其当前学生视角，也不能为展示改写已经锁定的学习等级。游客/未设置等级按已确认的 C2 预览；全部释义高于读者等级时显示“暂无适合当前等级的释义”，不能把更高等级偷偷当作匹配。
- 语法结构只显示所选 definition 实际关联的内容，不把其他等级释义的语法混入本行。强调样式来自安全的发布内容标记，不能用原始 HTML 执行；音频播放仍是后续独立能力。
- 完整模式的词形行展示平台配置的词形标签、词面、音标；顶部词面音标按原型取第一个基本词性下原形对应信息。音标斜杠属于展示格式，避免给本来已有分隔符的内容重复包裹。短语词形栏在原型中留空，这是展示约定，不等于平台存储必然没有短语词形数据。
- 详情支持关键词查询，词类筛选默认全部；具体词类菜单仍未展开。排序按钮打开独立浮层，阅读排序不应改写作者保存的词条编排。
- 原型明确“总题量”为每个词能生成的所有题量之和；但题型、生成条件、去重和是否受读者等级影响尚无定义。首批仍不展示假统计，不将词义数直接当题量。
- 点词可进入平台词条详情；自定义词不能跳平台词条详情。当前没有真实 C 端词条详情路由，不能拼管理员链接；此跳转需随 C 端详情能力准备后启用。
- 有自定义词才显示相关标签。未来自定义词若已存在对应平台词条但尚未升级引用，应显示红点提示，不能在读取时静默改绑/替换原自定义内容。自定义语音仅在真实存在时提供播放按钮。
- 自己创建的词表不能点赞、不能投币，相关按钮禁用；投币的服务端拒绝自投已是 coins 确认规则。点赞/收藏/评论尚未实现时不显示可成功操作的按钮，不能因为原型有按钮而生成伪成功或样例计数。

## 2. 必须满足的行为

- 公共发现与“我的词表”分开。公共只读接口不接受 owner/review 等可伪造身份参数；个人查询、创建、编辑和提交均需认证。创建/管理不要求先完成学习偏好引导。
- 公共列表与详情仅显示已通过审核、未撤回/下架且作者当前存在、未停用、未逻辑注销的词表。未公开对象对非作者返回 404，不泄露名称、条目或审核意见。
- 名称、顺序和选词由服务端校验；客户端不能传作者、审核状态或任意词库草稿。输入行的自由文本只是搜索条件；改写已匹配词面立即清除旧 entry ID 与预览，避免保存错误的旧引用。按真实词条 UUID 引用，不迁移 mock 的 `w_*` / `wl_*` / `owner_id=demo`。
- 首批编辑采用完整替换名称及有序条目，避免新增复杂协作补丁协议。编辑初始化返回同一 revision 下的完整轻量有序 ID，不以当前词义分页的数据覆盖整表。重复词条拒绝，不能以同一词条重复占位。搜索和详情条目均分页，加载失败不回落 mock。
- 提交审核后固定本次待审名称与条目集合。待审不能直接编辑；可显式撤回，再修改重提。已公开不能原地改内容：先明确撤为私密，编辑后重新审核。这样首批无需并行维护“线上版＋编辑草稿”两套词表。
- 审核是对词表名称和选词编排的审核，不包含作者私密备注；平台已发布词条的后续修正自动生效，不触发词表作者重审。审核页展示的是当前词库已发布内容，不承诺冻结当年释义。
- 管理员审核、驳回和下架使用独立权限，服务端事务中重读权限；驳回/平台下架必填原因，且与状态变更同事务审计。用户端只能看到本人词表所需的结果/原因，不能看内部管理信息。作者停用/到期阻止审核通过，但不得阻止管理员驳回或下架，以免恢复账号后重新露出原公开内容。
- 平台词条归档后允许原词表保留其位置，但该项只返回“内容不可用”，不提供旧快照绕过归档。已公开词表仍能展示其余可用项，作者可撤回后替换；公开审核通过时要求所有引用项仍可用。
- 作者待注销期间沿用现有账号使用资格，不额外把 72 小时改成立即注销；到期后拒绝创建/编辑/审核发布，公开查询不依赖 worker 清理速度。钱包暂停、未来投币拒绝收支仍由 coins 规则决定。
- 建议作者最终注销时由同事务级联删除其词表内容、条目与审核快照；独立管理审计保留必要 ID/动作，不能把整份内容永久复制进审计。未来投币事实和账本使用独立稳定 UUID，不级联删除。此生命周期选择属于本方案建议，实施前随整体方案确认。
- 创建/提交结果不确定时可用同一请求键安全重试；写入必须有并发版本检查，旧页面不能覆盖更新或批准已经撤回的提交。

技术默认建议：名称 1–100 个 Unicode 字符；每表 1–10,000 个去重词条；条目每页默认 50、上限 100；搜索每页默认 20、上限 100。实现前核对数据库/响应大小，不能一次响应返回万条完整词义。以上为可调整的工程上限，不是新奖励参数。

## 3. 与投币的依赖边界

基础业务必须交付稳定 `wordlist_id`、不可改作者 user UUID、真实公开/下架状态、引用项可用性，以及可与下架互斥的行锁。它本身不写任何 coins 流水。

COIN-11 再接“一次真实投币事件 + 一次 transfer_in”：付款方不得是作者、目标必须公开可访问且可投、双方账户/钱包可用、不能重复或透支。已确认有不可用词条时不允许投币，修复并重审后恢复；数量由用户输入正整数并确认，不设预置档位。平台作者和管理员投币暂不开放。

## 4. 可观察验收

| 风险       | 成功判据                                                                                                              |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| 作者/身份  | 伪造 owner 被拒；教师/学生切换仍只管理本人词表；其他用户或游客不能读取私密、待审、驳回内容                            |
| 词库来源   | 只搜索/引用 active + current publication；草稿、归档或其他词条的 publication 不能被客户端伪造引用                     |
| 发布与审核 | 未审不可公开；仅有查询权不能审核/下架；撤权及待审撤回后旧审核请求零副作用；状态/审计整体回滚                          |
| 版本与重试 | 同键创建/提交只一份；同键异载荷冲突；并发编辑不丢更新；公开编辑不能绕过重审                                           |
| 动态词条   | 管理员发布新词义后词表显示最新；归档后不能从详情/搜索/历史 publication 读出该项内容；恢复后显示当前发布稿             |
| 注销与数据 | 到期立即隐藏公开内容且拒绝写；worker 最终清理词表不阻断既有账本关闭/签署保留；未来财务记录不被级联清理                |
| 页面真链   | 游客可浏览公开页；创建跳登录但不强制学习引导；失败保留输入；切号不泄露私密缓存；生产构建连接真实隔离 API 完成公开闭环 |

原型增量验收还须证明：输入改写不沿用旧词条、乱序搜索响应不串行、删除/排序不丢备注、非作者及审核接口不含备注、备注变更不干扰公开/待审状态、标准详情按每个词义选择等级/语言并展示对应语法，角色/等级切换不复用错误投影；未知题量不伪造。
