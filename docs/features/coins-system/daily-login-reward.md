# 每日登录 1 币与学习达标 5 币

用户于 2026-10-17 确认每日登录奖励 1 币、每日学习达标奖励 5 币，并要求补齐登录奖励。本任务先完成实施和验收；用户随后授权两仓本地提交，不包含推送、PR、合并或部署。学习门槛沿用本次推荐的 10 个去重学习单元。

## 规则与边界

- 登录奖励面向绑定手机号的 C 端账号，学生与教师共用每天 1 币；平台管理员不参与。首次打开并确认登录态、返回页面或真实页面交互时自动尝试结算；静置跨日不发币，无需退出重登或手动签到。奖励失败不阻断登录和学习。
- 两种奖励均按 Asia/Shanghai 04:00 换日。登录按账号/业务日唯一；学习按已有每日任务的完成事实累计 10 个去重单元，一次奖励 5 币，二者独立。全错但有效完成仍按原学习规则累计。
- 未绑定手机不发登录奖励；绑定后可获得当日奖励。钱包待注销/关闭时不新增登录奖励，恢复后当日再次访问可领取；不补过去日期。已获当日奖励后暂停，仍只返回原流水。学习达标时钱包暂停保留未发记录；恢复后当天再完成一次每日任务可重新结算，仍使用当天累计已完成的去重单元，不需要额外积累 10 个新单元。刷新或重放旧完成请求不会补发。
- 金额与日期不能由客户端输入。登录奖励请求可安全重试、刷新和多设备并发。邀请奖励、管理员奖励、连续签到、兑换、风控扩展不在本次范围。

## 实现与依赖

已在主线：coins 事务账本、账号/钱包生命周期、每日学习奖励政策与结算、持久会话恢复。直接复用业务来源唯一约束和学习业务日函数；不新增奖励表或通用规则引擎；新增 `20261017080000_learning_reward_recovery` 迁移，将“用户/日唯一”调整为最多一条暂停记录和一条最终结算，保留历史记录不可变。

- 后端 `POST /api/v1/me/coins/login-reward` 接受空 JSON 对象，不接受额外查询参数。锁定账号并重查手机号/security_version/状态后，以 `daily_login_reward` 和 `user_id:business_day` 调用现有 `credit_in`；源唯一性和请求幂等共同保证一天一笔。锁等待后重查业务日及注销截止，跨日回滚并返回 409，客户端可重试。
- 返回独立 `LoginRewardDay`：业务日、服务器时间、次日边界、状态、实际已发金额、操作 ID。不修改登录、会话恢复、钱包和学习的既有响应。余额溢出或数据库失败整笔回滚，不返回假到账。
- 前端独立业务组件观察已确认的登录态，不修改鉴权内核。Query 按账号隔离；根据服务端时间判断交互是否已跨日，不使用定时器自动结算，切号取消旧请求；钱包展示真实结算状态并更新余额/流水，Admin 仅增加流水来源标签。
- 学习金额使用现有政策表。后端 `ops/enable-learning-rewards.sql` 提供已确认的 5 币/10 单元配置，从执行后的下一业务日 04:00 生效；遇已有政策显式拒绝，不覆盖、不追溯。登录也读取这份政策的生效日和 enabled；另受默认 false 的 `LOGIN_REWARD_ENABLED` 控制。开关变更须重启全部 API 实例，关闭只阻止新增登录奖励，已到账记录照常返回。脚本须在对应发布授权下执行，本次只在独立测试数据库验证。
