# 用户注册地区

## 目标与范围

用户管理右侧详情在注册时间附近展示注册 IP 对应的城市，例如北京、上海、杭州。仅展示城市，不返回原始 IP，不表示用户住址。不改注册、登录或历史 IP 数据。

- 新增独立权限 `users.read_registration_region`，名称「查看用户注册地区」，只依赖 `users.access`。
- 普通管理员需单独授予；超级管理员沿用权限目录全集规则。
- 无权限时隐藏整行且不请求；撤权时沿用取消请求、清缓存、隐藏的机制。
- 有权限时打开抽屉自动查询。未记录 IP 显示「未记录」；非法、非公网地址或无城市结果显示「未知」。请求错误可重试。

## 已有能力与剩余实现

后端 `users.registration_ip` 已在注册事务中写入，历史行可空，不被登录更新。现有用户列表及详情不返回该字段，也没有地区解析。管理员权限目录及前端敏感资源清理机制可复用。

- 前端基线：`63a3b34e`；后端基线：`1e1fbd7`。
- 两仓任务分支：`codex/user-registration-region`，各自独立 worktree。
- 主记录位于此前端文件，后端实现引用此记录。

## 契约与解析

`GET /api/v1/admin/users/{id}/registration-region`

成功响应（schema `UserRegistrationRegion`）：

```json
{ "city": "杭州", "status": "resolved" }
```

`status` 为 `resolved | not_recorded | unknown`，`city` 为必有字段、可空字符串：后两种状态为 `null`。无权限返回 403，用户不存在返回 404；授权在数据读取前及响应前分别核实。列表和基本资料响应不增加地区或 IP 字段。

采用固定版本的开源离线 IPv4/IPv6 数据，在后端解析，随二进制内嵌，查询不向外部发送用户 IP。不从普通省份推测城市；直辖市按城市名称展示。数据来源、许可与校验和随后端数据文件记录。解析数据更新独立于用户记录，不承诺历史时点的精确地理位置。

## 可观察验收

1. 只有 `users.access` 或已有联系方式/基本资料权限，直接请求地区接口仍为 403，抽屉没有地区行或查询。
2. 仅增加地区权限后，可在抽屉看到城市；响应不包含 IP；其他敏感信息不因此获得授权。
3. 历史空 IP 显示「未记录」，无法解析的地址显示「未知」，已知公开 IPv4 与 IPv6 按固定数据集正确解析。
4. 切换用户、关闭抽屉和撤销权限后，旧数据不残留；失败可重试。
5. 后端定向 handler/解析测试与 fmt/clippy，前端契约/组件/共享鉴权测试、全仓 typecheck 和普通测试通过；隔离本地后端实际请求与浏览器打开详情验证。

## 兼容与交付边界

新增独立端点，不改旧响应，无数据库迁移。后端先可提供新接口；旧前端继续使用原接口。新前端配旧后端时，超管可看到地区查询失败，因此发布应先后端再前端。回退前端保留后端接口安全；回退后端前需先回退前端或撤销新权限。
