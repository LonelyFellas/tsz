# 单词行英美多条拼写

## 目标与验收

用户已确认：同一词形内容下，英式、美式各有独立的有序拼写列表，数量可不同；每条拼写拥有自己的发音和拼写试听设置；移动表示同侧排序，不建立英美逐条配对关系。

- 内容抽屉中在词形拼写旁新增、删除、拖动排序；每侧至少保留一条。
- 保存、重新请求和重新打开后，所有拼写、顺序、发音和语音配置保持一致。
- 排序保留内容 slot 和绑定 reference ID；删除受已有引用保护。
- 原有单条、英美通用和共享标签内容行为保持。

## 依赖与方案

已有：共享词形内容及标签绑定、每条拼写的多发音、语音编辑器、引用检查。
新增：`regional_variants` / `regional_bindings` 的 `uk_us_many` 分支，`uk`、`us` 为非空数组。旧 `common`、`uk_us` 分支继续接受；新增多条时升级该份内容，不静默裁剪。多条拼写仅用于英美拼写区别开启的内容；合并模式前须先整理到每侧一条，避免有损合并。

前后端各消费者须遍历全部变体；摘要可以使用首条，搜索、引用解析、发布、语音和持久化不得遗漏其他变体。内容 slot 与绑定节点通过 slot ID 对应，不能通过数组下标重建已有身份。

数据库移除每词形/方言、每内容/方言的单条唯一限制；排序以草稿/发布快照的数组顺序保存。down 迁移须在多条数据存在时拒绝，不能删数据以恢复旧约束。

主记录在本文件。前端基线已同步至 `7c9d20c4`，后端基线已同步至 `425e307`，均使用 `codex/task-167-multiple-dialect-spellings` 独立工作树。用户随后授权部署到测试环境，按两仓原生交付与发布门禁推进。

## 验证与兼容

验证独立 2:3 列表、编辑各自发音、排序身份、共享标签、删除引用保护、保存重载、搜索与发布投影。按风险运行 TS/Rust 定向测试、类型检查和原生质量门。真实联调须绑定本任务构建和隔离数据；环境缺失时明确未验证。

旧前端无法解析 `uk_us_many`，新 API 必须使用请求能力协商阻止向旧客户端下发该格式及旧客户端写入造成丢失。新前端对旧 API 不开放多条编辑。已有多条数据时，回退旧 API 不安全；发布前需配套兼容验证。
