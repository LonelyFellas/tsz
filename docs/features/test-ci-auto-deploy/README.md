# 测试精简与 tshb-test 自动部署

目标：保留鉴权、数据、契约、关键用户路径及部署安全保障，减少低价值断言；PR 与 main 使用一致的核心验证；main 精确 CI 成功后自动发布前端制品。

当前阶段：实现及验证中。自动部署暂时失败关闭，需要先合入并验证后端控制器的共享锁协议、配置专用 SSH 身份和可信主机指纹；上线前仍须完成独立审查、CI 与真实自动部署验证。

现有前端部署复用精确 CI 制品、来源检查、远端锁和事务；不构建服务器源码。`deploy/check-api-contract.mjs` 根据服务器 API manifest 对照该版本 OpenAPI，校验前端快照及运行时 schema。拟定协议让前端在事务期间持有 `/opt/tsz-cross-deploy.lock` 并检查后端的 `/opt/tsz-rust/deploy.lock`；后端在创建自己的事务锁时也须持有共享锁。两仓协议就绪前不得启用自动部署。2026-10-29 检查到 tshb-test API manifest 为 `edba6bef11c8c2610da2d5dc2a5cd87c44a36912`，两份契约通过。该契约检查本身不验证数据库迁移，仍依赖后端发布事务的验收及现有配套发布要求。

已精简：移除两条只固定词形拼写字重和一条固定连续边框的 E2E；UPS 展开用例保留交互状态，去除图标样式断言。取消 CI 测试中固定五个分片名称的重复断言，分片完整性仍由模块清单测试和实际执行清单校验。其余测试尚未完成逐项梳理，不应宣称全面审查完成。

验收：成功 main push CI 对应的精确版本在兼容性与凭据检查通过后自动发布；旧候选不能覆盖新版本；失败及部分发布可观察且可恢复；PR/main 的关键测试模式一致；部署安全、关键业务和权限回归保留；移除 Gitee 镜像及其运行依赖。
