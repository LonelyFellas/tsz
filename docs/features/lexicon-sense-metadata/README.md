# 新智能词库词义总体数据对齐 V1

## 范围与结果

本轮沿用当前 V1 的义项头部、等级、语义区间、细分词性、词频和语境依赖控件，不实现 AI 生成或审核，也不搬入整套 V1 释义、例句和发布模型。两版共用提取后的 `V3SenseEditorShell`、`V3SenseMetadataFields`；V1 修改等级时，仅重铺未改动的默认释义行，行为保持不变。

新增义项默认 A1、词频 `"0"`、不依赖语境；词频允许 0–100，最多两位小数，可清空。存量缺字段不自动填值。义项排序保持稳定 ID，沿用 V1 的折叠、标题摘要及至少保留一个义项规则；存量未指定基本词性的义项保留补录入口。只读禁用编辑、排序、删除和保存。

## 契约与兼容

- `NextSense` / `NextSenseView` 增加可选、非 null 的 `level`、`frequency`、`depends_on_context`。词频沿用 V1 的十进制字符串及后端校验函数。
- 新前端发送 `x-tsz-next-sense-metadata: v1`，能力目录才返回 `sense_metadata: true`。旧 API 不开放控件；未协商客户端读取时省略扩展，保存时按稳定义项 ID 保留已有总体数据。新客户端可显式清空词频。
- 复用整份 JSONB 草稿快照、权限、`expected_revision` 冲突保护，不新增迁移或 SQLx 编译期查询。保存预览和本地预览均携带总体数据；列表、统计的等级筛选只匹配当前已保存快照，不匹配历史版本，也不推断空白等级。
- 配套更新时先发后端，再发前端。出现带新字段的草稿后，不可直接回退到拒绝这些字段的旧后端二进制。
- 前端基线 `731436c6`，后端基线 `eb29c559`；两仓分支均为 `codex/lexicon-sense-metadata`。本次制品来自基线加任务未提交差异。OpenAPI 来源与二进制指纹见 [验收证据](acceptance/checks.json)。
