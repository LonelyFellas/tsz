# 词条内容自动生成与安全回填需求评估

## 背景与目标

当前智能词库创建流程能够检测词头、创建词性骨架，并实时展示“完成情况”及定位未完成字段；它不会生成语法结构、词义或例句。目标是在管理员编辑词条时，调用真实且可追溯的数据源生成候选内容，安全回填到现有多词性、多方言、多词义和多例句结构中，再由管理员审阅并保存。完成情况继续复用现有实时计算，不把“请求已返回”误当成“内容已完成”。

## 现状证据与功能边界

- `tsz-rust/docs/openapi.json` 当前只有词典检测、方言建议、词形/词义保存、校验和发布接口，没有生成或补全接口。
- 当前 Kaikki 导入数据集 `kaikki-en-2026-07-06-rules-v1` 只落库词头、词性、sense 数量、地区标签/拼写/别名证据。数据库没有释义正文、例句、语法结构、CEFR 或中文内容。
- 检测契约虽然含 `suggested_meanings`，后端当前只生成 A1 空占位；前端也明确提示释义、例句和词频需要人工补充。该字段不能作为“已有生成能力”。
- 已部署的 readiness 只负责实时判断与定位，不负责内容生成；本功能只消费其结果，不改写其判定含义。
- 本次目标端为 `apps/admin`。学员端、批量离线生成、自动发布、自动生成关联词、测试服数据回填不在本次范围。

## 用户故事 / 使用场景

1. 管理员创建或编辑草稿，进入“多维词义与例句”，看到可生成内容的入口和将处理的范围。
2. 管理员发起生成后，可以看到正在处理、部分成功、失败和可重试状态，不会因一个分区失败而丢失其他可用分区。
3. 管理员先预览候选内容和来源，再将选定结果回填到当前表单；回填不会直接发布，也不会绕过现有保存与校验。
4. 同一词条包含多个词性时，结果严格绑定 `pos_id`；同一词性下的语法结构、词义、定义和例句使用稳定 ID 关联，例句的 focus link 指向正确的 `word_id + sense_id`，定义可引用本次生成的 `grammar_structure_id`。
5. 英美内容确有差异且有来源依据时生成区分内容；没有证据时保持统一内容或明确缺失，不制造“英式/美式差异”。
6. 管理员修改了表单或另一会话保存了新 revision 后，旧生成结果不能静默覆盖新内容；系统提示过期并允许基于最新 revision 重新生成。
7. 管理员可对失败或缺失的分区重试。相同幂等请求返回同一任务/结果，不重复计费或产生不一致副本。

## 功能范围

### 本次范围内

- 为单个已有词条草稿生成/补全：
  - 每个词性的语法结构，包含适用方言的文本变体；
  - 多个词义及其 sense group、子词性、CEFR、上下文依赖属性；
  - 中文释义与英文释义（英文内容按统一/英美区分结构表达）；
  - 每个词义的多条中英例句、CEFR 和 focus link；
  - 定义到语法结构的可选引用。
- 返回字段级来源：Kaikki 数据版本/原始记录引用、模型提供方与模型标识、生成规则/提示版本、生成时间；UI 能区分“来源提取”和“模型整理/翻译”。
- 支持整体任务和分区状态：`pending`、`running`、`completed`、`partial`、`failed`；部分结果可以预览、回填和按失败分区重试。
- 回填后仍为未保存的本地草稿；管理员明确点击现有保存/完成按钮后才写入 canonical 词条并触发 revision、验证和 readiness 联动。
- 后端接口受 OpenAPI 约束；前端类型和快照只能由权威 OpenAPI 同步生成。

### 明确不做

- 不把 mock、固定模板、空占位或纯规则词形变化宣称为真实生成。
- 不在生成成功后自动保存、完成、发布或部署。
- 不自动创建/绑定同义词、反义词、派生词；这需要对现有发布词义做独立消歧。
- 不补发音、词形和词频；它们保留在现有流程，除非后续单独立项。
- 不修改测试服数据库或运行数据，不导入新数据集，不合并或部署。

## 数据与内容规则

- Kaikki/Wiktionary 是事实依据而不是完整答案。必须扩展独立、版本化的内容数据集，保存可定位到来源记录的 key；不能仅凭当前 `dictionary.terms` 反推释义和例句。
- 模型只允许在来源事实范围内做结构化整理、中文翻译、CEFR 建议和满足教学要求的例句生成。来源缺失或模型无法可靠完成的字段标记缺失/失败，不能伪造 provenance。生成 provider 支持已完成的 OpenAI 与本次新增的阿里云百炼千问，部署时显式选择一个，不做跨 provider 自动降级。
- CEFR 是生成建议，不是 Kaikki 原生事实；必须标记为模型推断，并限制为 `A1`–`C2`。词义、定义和例句分别给出等级且通过现有后端验证。
- 方言差异只有在来源数据或已验证的地区规则支持时才展开；无依据时使用 `common` / `unified`。
- 每个返回节点都带服务端生成 UUID；引用必须只指向同一结果或当前词条中的有效节点。
- “空缺”按字段语义判断：初始化产生的空文本/A1 占位可以被补全；任何非空人工文本、人工新增节点或已修改字段均视为已有人工内容。

## 失败、重试与并发

- 上游超时、限流、无凭据、内容安全拒绝、结构校验失败和来源缺失必须有可区分错误码；不得退回假数据。
- 重试默认只处理 `failed` / `missing` 分区，并沿用相同任务上下文；管理员也可发起全新生成任务。
- 创建任务使用 `Idempotency-Key`。相同管理员、词条、`base_revision`、生成范围和配置摘要的重复请求复用同一任务。
- 结果绑定 `base_revision`。若词条 revision 已变化，后端查询结果仍可用于审计，但前端禁止一键回填并要求重新生成或人工逐项处理。
- 上游调用不得持有词条数据库事务；生成结果与业务词条分开持久化，失败不改变 canonical 词条。

## 人工覆盖与保存语义

推荐默认策略为“仅补空缺”：新增缺失节点、替换初始化空占位、跳过所有非空人工内容，并逐项报告 `applied` / `skipped_existing` / `failed`。这样可复用现有保存接口、revision 乐观锁和 readiness。

若用户明确选择允许覆盖，必须在预览中逐项展示将被替换的旧值与新值并二次确认；不能用一个全局开关静默覆盖整个词条。无论何种策略，生成接口本身不保存 canonical 词条。

## 权限、安全与运营约束

- 复用现有 admin 鉴权和词条编辑权限；归档词条及只读发布视图不能生成或回填。
- 上游密钥只存在后端配置，不进入 OpenAPI 响应、日志、前端包或仓库。
- 发送给模型的内容限制为目标词条、必要来源片段和结构约束，不发送管理员身份信息或其他业务数据。
- 记录请求者、任务、词条 revision、来源版本、模型/规则版本、耗时与状态；日志不记录密钥，不把完整提示或用户数据无界持久化。
- 设置每任务超时、词义/例句上限和管理员级并发限制，避免失控成本。

## 验收标准

- [ ] 权威 OpenAPI 存在真实生成任务创建、查询和失败分区重试契约，认证、幂等、状态码和 RFC 9457 错误有定义。
- [ ] 对至少一个真实 Kaikki 有内容来源的词条，后端返回非空语法结构、多个词义及其多条中英例句；每项带可追溯来源/推断标记。
- [ ] 多词性、英美统一和英美区分三类结构均保持 ID 与引用正确，CEFR 值合法。
- [ ] 上游部分失败时返回 `partial`，成功分区仍可预览/回填，失败分区可重试；无真实来源/凭据时明确失败而非返回 mock。
- [ ] 重复幂等请求不重复创建任务；revision 变化后旧结果不会覆盖新内容。
- [ ] 前端可从编辑页按钮发起、查看状态、预览并按策略回填，生成期间和失败时不丢失当前未保存编辑。
- [ ] 默认回填不覆盖任何非空人工内容；若最终允许覆盖，只有逐项预览并确认后才发生在本地表单中。
- [ ] 回填后现有“完成情况”立即根据新草稿重算；保存后 canonical revision 更新，现有后端校验仍是发布权威。
- [ ] 测试证据分别报告：单元/mock、真实 HTTP、真实 Kaikki/真实模型提供方、Codex 内置浏览器；任何缺层均标为 BLOCKED，不能以 mock 代替。

## 一次性评审需确认

1. **触发方式（推荐：两者结合）**：首次进入空白“多维词义与例句”页时只展示明显提示，不自动产生计费请求；由管理员点击“自动生成”。生成成功但尚未保存时再次进入仍显示结果。备选是进入页面立即生成，或仅保留按钮且不主动提示。
2. **覆盖策略（推荐：仅补空缺）**：默认新增缺失内容并替换初始化空占位，跳过非空人工内容。是否需要在首版加入“逐项选择后覆盖已有内容”？
3. **真实生成提供方（已确认）**：以版本化 Kaikki 原始内容作 grounding，保留已完成的 OpenAI structured output 实现，并接入阿里云百炼千问严格结构化输出模型；本次真实验收优先千问。凭据、模型和 provider 由后端配置显式选择。
4. **首版范围**：是否接受不自动生成词义关联（同义/反义/派生）、词形、发音和词频，仅覆盖本目标明确的语法结构、多维词义、多维例句？
