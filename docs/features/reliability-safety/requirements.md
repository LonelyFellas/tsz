# 异常、日志与恢复保障：需求评估

状态：已按确认方案实施并完成本地验证。日期：2026-10-09。实际证据见 [verification.md](verification.md)。

## 目标与边界

- 用户要求补齐异常可控、日志敏感信息保护、关键操作恢复保障；已确认按本方案实施和验证。
- 不改权限规则、验证码通道，不上线或部署。按当前非生产阶段设计。
- 用户确认最终删除保持不可逆，只补恢复验证和提示；保留主线已有的 72 小时注销等待期及期间撤销，不新增删除恢复期。
- 不新增通用撤销平台，不把业务撤销等同于数据库整库恢复，不通过备份给已生效注销增加产品恢复入口。

## 可观察验收目标

1. 无响应、响应头已到但响应体停滞、依赖阻塞时，界面最终退出 loading，允许安全恢复；用户主动取消与系统超时可区分。
2. 同一业务调用最多一次 401 刷新重发，不能靠重新计时无限延长；一个请求取消不取消其他请求共用的 refresh。
3. refresh 超时不立即当作 401 清会话；释放共享锁，旧响应不能覆盖新登录。轮换已提交但响应丢失时，不盲目自动重放旧 refresh token。
4. 写入超时/断网显示结果待确认；已有幂等接口复用同一键和原 payload，其他接口回读事实。禁止以超时为依据断言“未写入”或自动重复扣币。
5. 响应、应用日志、服务入口 stderr 不出现测试注入的密码、OTP、Cookie、token、联系方式、连接串、签名 URL 和供应商响应正文；仍保留安全事件类别、请求 ID 和必要诊断字段。
6. SQL/审计失败时，业务数据、账本、版本和审计整体回滚；响应丢失后重试不重复发布、入账或投币。既有成功撤销只作用于允许的业务状态。
7. 永久删除、生效注销没有恢复入口，提示准确；等待期撤销继续按现有规则工作。不能把整库备份恢复包装成单个误删撤销。
8. 能将含代表性测试数据的备份恢复到独立目标，核对 schema、行数、校验值及账本不变量；损坏备份、非隔离目标、异常中断时明确失败且不覆盖源库。

## 范围外

生产备份排期、保留期、异地容灾和 SLA；真实服务器恢复或故障注入；新资金退款/任意流水撤销；修改既有注销数据保留规则；替换权限系统；自动提交、推送、合并或部署。

详细技术方案、兼容性与可执行验收见 [design.md](design.md)。
