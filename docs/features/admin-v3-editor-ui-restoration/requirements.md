# Smart Lexicon V3 管理端编辑器 UI 恢复与统一创建入口需求评估

## 背景与目标

Smart Lexicon V3 已具备独立的创建、词形与发音、词义与例句、校验、发布、发布历史和历史版本激活流程，但当前管理端把底层技术分流直接暴露给了管理员：词条列表同时显示“创建单词”和“创建短语”，V3 页面还显示 `Smart Lexicon V3`、`revision`、`concrete form`、`membership`、原始 UUID、状态代码和完整 JSON 等工程信息。现有 V3 布局与表单样式只有约 77 行 CSS，尚未达到 V2 管理端编辑器已经形成的产品化层级、操作反馈和响应式体验。

这不是合并冲突造成的偶发现象。历史提交 `d707328` 曾把词条列表收敛为唯一入口“创建词条”，后续提交 `49e3bdc` 又主动将入口拆为“创建单词”和“创建短语”，并同步修改测试。问题的本质是：单词走 V3、短语走 V2 的技术路由差异，被错误地呈现成了产品入口差异。

本功能的目标是：

1. 恢复唯一的“创建词条”产品入口，由前端根据一次输入自动判断单词或短语；
2. 自动检测不仅用于重复校验，还要清楚呈现并应用内置词典提供的英美主词或地区建议拼写、基本词性、词形和音标建议，不能退化为只显示“已匹配 / 未匹配”；
3. 单词进入原生 V3 流程，短语继续使用现有 V2 phrase 流程，管理员不需要理解版本或路由；
4. 将 V3 全流程恢复为与现有 V2 Admin 一致的产品语言和编辑体验，同时完整保留 V3 数据语义、稳定身份、冲突保护、校验定位和原生发布能力；
5. 在桌面、平板和 390px 移动宽度下都保持可编辑、可定位、可确认，不出现必须横向滚动才能完成的核心操作。

成功不是“把 V3 涂成 V2 的样子”，更不是把 V3 数据转成 V2 组件，而是让管理员只看到词形、变化组、发音、释义、例句、发布版本等业务概念，底层 V3 模型继续由 V3 组件原生承载。

本次确认的能力回归发生在前端呈现层，而不是后端契约：`BuiltinDictionaryEvidenceV3` 在 `matched` 时仍返回 `suggested_pos`、`suggested_forms`、`coverage` 和 `provenance`，既有 V3 需求文档“新建与检测”也明确要求返回词典证据、已有 surface 候选和建议词性/词形。当前 `V3CreateEntryStep.tsx` 从零实现了最小 detect/create 状态机，却只显示 `内置词典：${status}`，没有迁移 V2 `CreateEntryStep` 已有的建议主词、词性、词形和音标呈现。现有 V3 测试主要覆盖检测、创建、幂等和 surface 确认，没有建立建议 UI parity 回归门，因此未能发现该退化。

## 目标端

- 仅 `apps/admin` 管理后台。
- 使用 antd v6 和管理端现有品牌主题。
- `apps/web`、学习端展示与 SEO 不在本次范围内。

## 目标用户与权限

- 目标用户为已有智能词库访问与编辑权限的词库管理员。
- 沿用当前 Admin 登录、路由门禁、请求鉴权和 401/403 处理，不新增角色或权限模型。
- 无权限、登录过期、服务不可用或契约异常时必须明确失败，不得显示创建、保存、发布或激活成功。

## 产品原则

### 一个入口，一次输入

- 词条列表只保留一个主按钮“创建词条”。
- 创建页只提供一个词条文本输入，不显示“单词 / 短语”选择器。
- 不显示独立的“检测”步骤、检测按钮或需要管理员理解的检测 ID。
- 用户提交后，系统自动完成归一化、分类、词典检测、重复项检查和 surface 冲突检查。

### 词典建议是创建产出，不是技术状态

- 内置词典命中后，界面以业务语言展示将采用的英美主词或地区建议拼写、基本词性、词形和音标/实际发音建议，并把同一份检测结果用于草稿预填。V2 可展示正式 `headwords`；V3 只能把 base form 地区变体展示为“建议拼写”，不能把它们提升成领域唯一主词或写入 legacy compatibility。
- 建议摘要不是新的“检测步骤”，不要求无冲突用户再次点击；系统在一次提交中自动展示、应用并继续创建。
- 为避免快速创建导致建议只短暂闪现，进入编辑器后继续显示“已根据内置词典预填，请核对”的产品提示，实际预填字段就是最终核对入口。
- 内置词典未命中时明确说明将创建空白草稿；内置词典不可用或建议无法按现有词性目录安全解释时停止创建，不静默退化为空白草稿。
- 智能词库重复项、surface 匹配和策略确认是独立边界：只有这些冲突或后端明确要求确认时才暂停自动创建，不能把普通词典建议误呈现为冲突。

### 业务语言优先

- 默认界面使用清晰中文业务名称。
- 不显示 `concrete form`、`membership`、`word_id`、`sense_id`、`role`、原始 UUID、`revision`、schema 版本、内部状态码或原始 JSON。
- 稳定 ID 必须在内部保留并参与保存、排序、冲突比较、问题定位和 React key，但管理员不能查看或编辑这些 ID。
- 无法识别的新状态或错误代码使用安全的中文兜底，不直接把代码串抛给管理员。

### V3 语义不降级

- V3 单词始终使用 V3 原生数据和组件，不转换成 V2 `base_form` / slot 结构。
- 产品化改造只能改变呈现、交互编排和本地视图模型，不能缩减、合并或重写 V3 wire 语义。

## 用户故事与使用场景

### 1. 从词条列表开始创建

作为词库管理员，我在智能词库列表只看到一个醒目的“创建词条”按钮。点击后进入统一创建页，不需要先决定正在创建单词还是短语。

批量归档、恢复、搜索、筛选和统计仍保持原有能力；统一入口不改变现有列表数据或生命周期操作。

### 2. 一次输入并自动分类

作为词库管理员，我输入英文词条并提交，前端按以下固定规则处理：

1. 去除首尾空白；
2. 将连续的内部空白折叠成一个半角空格；
3. 归一化结果仍含内部空格时判定为短语；
4. 归一化结果只有一个 token 时判定为单词。

连字符和撇号不是分词符，因此 `state-of-the-art`、`mother-in-law`、`can't`、`rock’n’roll` 都按单词处理；`give up`、`day in, day out` 按短语处理。复制输入产生的 Tab、换行或连续空格在分类前统一折叠，不产生肉眼相同、实际不同的入口行为。

空输入、纯空白、缺少英文字母、包含不支持字符或归一化后超过现有限制的输入，在发送检测请求前给出字段级提示。

### 3. 提交后自动检测与创建

作为词库管理员，我点击“继续创建”或在输入框按 Enter 后，只看到一次连贯的处理过程：系统正在检查并创建词条。

- 单词调用现有 V3 检测、重复项和 surface 冲突检查；
- 短语调用现有 V2 phrase 检测、重复项和 surface 冲突检查；
- 内置词典命中时，在创建页立即展示建议摘要，并使用该 detection 创建已预填的草稿；摘要至少覆盖 V2 英美主词或 V3 地区建议拼写、基本词性、词形以及词典音标/实际发音中实际存在的内容；
- 内置词典未命中时，展示“未找到词典建议，将创建空白草稿”，仍按现有允许条件继续；不可用或建议含无法识别的必需词性时阻断并允许重试；
- 无智能词库冲突、无需 surface 确认且满足现有创建条件时，系统不等待第二次点击，自动创建草稿并直接进入对应编辑器；编辑器顶部保留已应用/未命中提示，预填字段可直接核对；
- 不把“检测完成”作为需要管理员再次点击的中间步骤；
- 后端返回的分类或请求回显与本次输入不一致时安全停止，不得静默切换流程或创建错误类型。

输入在请求进行中不可被重复提交。同一输入的未知结果重试继续遵守现有幂等规则；用户修改输入后，旧检测结果、确认上下文和幂等上下文全部失效。

### 4. 产品化确认重复项与 surface 冲突

当后端要求管理员确认时，统一创建页保留当前输入并展示产品化确认信息：

- 命中的词条名称、词条类型、当前状态和命中原因；
- 每个重复候选可查看产品化详情，包括已有主词/词面、词性或释义摘要（响应实际提供时）、生命周期状态和关联来源；同一候选命中多类原因时按现有优先级归并，不按底层 match 行重复堆叠；
- 当前已加载数量与总数，以及尚在加载、已过期或策略阻断状态；
- 清晰说明“继续创建会新增草稿，不会修改现有词条”；
- 主操作使用“确认并继续创建”，次操作使用“返回修改”。

确认区与词典建议区职责分离：词典建议回答“草稿将预填什么”，智能词库确认回答“是否仍要在已有相似词条的情况下创建”。发生冲突时仍保留并展示本次建议摘要，但建议本身不产生确认门。

确认界面不显示 snapshot ID、token、policy code、schema 版本、节点 ID 或底层 match 结构。只有完整且仍有效的确认快照可以继续；确认上下文变化后必须更新内容并要求重新确认，不能沿用旧 token。

### 5. 单词进入 V3 编辑流程

单词草稿创建成功后直接进入 V3“词形与发音”，不再展示“创建 V3 草稿”或版本选择。V3 编辑流程包含：

1. 创建信息摘要；
2. 词形与发音；
3. 词义与例句；
4. 核对与发布；
5. 发布历史与历史版本激活。

如果检测命中内置词典，进入页面时可见“已根据内置词典预填，请核对”，地区建议拼写、词性、词形和发音以创建响应中的 V3 canonical 数据呈现；前端不得自行生成领域主词，也不得把建议转换成 V2 结构。管理员可以返回列表，也可以在允许到达的步骤之间切换。已发布词条、编辑已发布内容、已归档只读态继续遵守当前 V3 路由和生命周期规则。

### 6. 短语继续使用 V2 phrase 流程

短语草稿创建成功后进入现有 V2 phrase 向导。统一入口只替代创建前的产品分流，不重写 V2 phrase 的编辑、保存、校验、预览和发布语义。

管理员不需要再次输入短语，也不会在统一入口之后再次遇到单词/短语选择器或独立检测按钮。内置词典命中时沿用现有 V2 headwords 与 suggested forms 预填，进入编辑器后可见对应来源提示并直接核对字段。

### 7. 编辑 V3 词形与发音

作为词库管理员，我可以按词性维护变化组、词形、地区拼写和多条发音，并在视觉上理解它们的层级：

- 词性是最高层级，以中文名称作为 Tab 或分区标题；
- 每个词性可以有多个“词形变化组”，变化组可新增、删除和排序；
- 每个变化组可以添加新词形，也可以复用该词性下已有词形；
- 同一个词形可以出现在多个变化组中，界面使用“已在多个变化组中使用”等业务提示，不显示 `membership`；
- 同一 `form_type` 可以存在多条，包括多个“原形”，界面不得因为类型相同而合并、覆盖或拒绝；
- 词形可使用“通用拼写”或成对的“英式 / 美式拼写”，并允许在两种结构间按现有影响确认规则转换；
- 每个地区拼写可以维护多条发音，支持字典音标、实际发音和发音方式；
- 删除最后一处复用关系、删除变化组、改变地区结构等有数据影响的操作继续要求显式确认。

词形类型、方言和发音方式使用中文标签；原始枚举值只保留在内部。排序按钮、删除按钮和类型切换都具备不含 UUID 的可访问名称。

### 8. 编辑 V3 词义与例句

作为词库管理员，我按“词性 → 释义 → 定义 / 例句 / 关联”的业务层级编辑内容：

- 释义组、语法结构、词义、定义、例句和关联使用有序卡片或可折叠分区；
- 卡片标题使用“释义 1”“例句 2”等当前可见顺序，不显示节点 ID；
- 子词性、等级、频率、定义方式、方言和关联类型显示中文标签；
- 主关联和上下文关联以业务文案区分，不显示原始 `role`；
- 多维例句、来源区间、稳定 sense/form 引用和可写关联语义全部保留；
- 添加、删除、排序、折叠和错误定位不会改变任何稳定 UUID；
- 草稿允许不完整，完成步骤和发布仍以后端校验为最终权威。

### 9. 侧栏摘要、完成进度与问题定位

在 1024px 及以上宽度，编辑器提供侧栏摘要与主编辑区：

- 展示词条名称、中文状态、是否有未发布修改和各步骤完成情况；
- 当前步骤、已完成步骤和待处理数量清晰可区分；
- 点击待完成项后切换到对应步骤、词性和卡片，展开祖先区域并聚焦具体字段；
- 同一问题不会在全局与步骤内重复造成噪声；
- 未知位置的问题仍可见，但不会错误聚焦其他字段。

在较窄宽度，侧栏摘要移动到主内容上方或收敛为可展开区域，不能遮挡编辑内容或操作按钮。

### 10. 保存、dirty 与冲突状态

- “保存草稿”和“完成并继续”保持语义分离；草稿保存可以不完整，完成操作会执行现有影响预览和校验。
- 当前步骤存在未保存修改时显示清晰提示；切换步骤、离开页面和激活历史版本继续受到 dirty 保护。
- 保存成功后清除对应 dirty 状态并以服务端返回数据为准。
- revision 冲突保留本地输入，使用“内容已被其他操作更新”等产品文案展示服务端最新状态和可选动作，不向管理员暴露原始 revision 数字。
- 网络失败、服务不可用、登录失效和契约异常分别给出可恢复或不可恢复的明确反馈；未知写入结果不能宣称失败后可无条件新建。

### 11. 核对、发布与发布历史

- 核对页以产品卡片展示词性、变化组、词形、英美拼写、发音、释义、例句和关联，不展示原始结构或 ID。
- 发布前继续调用 V3 原生 validate、impact、surface 确认和 publish；有问题时按步骤定位，有影响时展示产品化确认摘要。
- 发布能力被策略阻断时显示可理解的中文原因，不显示 `phase2_consumers_not_ready` 等原始代码。
- 发布历史使用“第 N 次发布”、发布时间、发布人、当前版本等产品信息，不显示 schema 版本、publication ID、entry ID、revision 或完整 JSON。
- 历史 V2/V3 快照都保持不可变；查看详情不改变当前词条。
- 在现有能力允许时，可显式确认并激活历史 V3 发布版本；dirty 状态、surface 确认、幂等和冲突恢复保持不变。
- 归档、恢复和归档词条只读行为继续沿用现有生命周期能力。

## 功能范围

### 本次范围内

- 智能词库列表的唯一创建入口；
- 创建输入的归一化、自动分类和单次提交编排；
- V3 word 与 V2 phrase 的内部路由分流；
- V2/V3 现有检测、重复项、surface 确认和创建能力的统一产品交互；
- V2/V3 内置词典建议摘要、自动预填和进入编辑器后的来源提示；
- V3 编辑器外壳、侧栏、步骤进度、操作栏和响应式布局；
- V3 forms、meanings/examples、preview/publish、publication history 的中文产品化呈现；
- V3 dirty、冲突、影响确认、校验问题定位、发布、历史激活和生命周期状态的产品化反馈；
- 对现有相关单元、集成、路由和 e2e 测试的更新；
- 390 / 768 / 1024 / 1440 宽度、键盘操作和基础无障碍验收。

### 明确不做

- 不修改 `apps/web` 或学习端消费者；
- 不修改后端、数据库、OpenAPI 或任何 wire contract；
- 不把 V3 数据转换成 V2 DTO、V2 表单或 V2 发布快照；
- 不改变 V3 数据规则、校验规则、surface 策略、发布能力门禁或生命周期策略；
- 不新增语言、词条类型、权限、自动生成内容或新的词典数据源；
- 不重新设计 V2 phrase 编辑器；
- 不在本功能中 ship、合并或部署。

## 约束与边界

### V3 语义保护清单

以下能力必须在 UI 改造前后逐项保持：

- 同一 `form_type` 多条；
- 多个 `base` 词形；
- 同一词形通过稳定关系在同一词性内被多个变化组共享；
- common 与成对 uk/us 地区结构；
- 每个地区词形多条发音；
- POS、group、membership、form、variant、pronunciation、sense 等节点的稳定 UUID；
- 数组顺序作为权威顺序；
- retired node、orphan 保护和引用冲突；
- forms / meanings 独立 dirty 状态和保存；
- revision / lifecycle revision 乐观锁；
- 聚合校验问题和稳定节点定位；
- forms impact 与 surface 影响确认；
- 原生 V3 发布、不可变发布历史、历史版本激活、归档和恢复。

### 展示与身份边界

- 中文序号只用于当前视图展示，不得写回或替代稳定 ID。
- 重新排序后序号可以变化，稳定 ID 必须不变。
- 内部 ID 可以保留在组件状态、请求、React key 和用于问题定位的非展示属性中，但不能进入可见文本、输入值、tooltip 或面向用户的可访问名称。
- 不依赖当前数组下标保存引用；下标只用于生成“词形 1”“例句 2”等临时展示名称。

### 兼容与失败边界

- `/words/new` 是唯一产品入口；已有深链可保留为兼容路由，但列表和页面不再提供分流按钮。
- 后端检测和归一化仍是数据权威；前端分类只决定使用现有 V3 word 还是 V2 phrase 创建链路。
- 请求回显、schema 或身份不匹配时继续 fail closed。
- 现有 V3 runtime guard、API identity guard、幂等保护和异步过期响应丢弃逻辑不得弱化。

## 验收标准

### 统一创建入口

- [ ] 词条列表只显示一个主按钮“创建词条”，不显示“创建单词”或“创建短语”按钮。
- [ ] 点击后进入统一创建页，只出现一个词条输入和一个主提交操作。
- [ ] 页面没有单词/短语选择器、独立检测步骤或“检测”按钮。
- [ ] 首尾空白被去除，连续内部空白被折叠为一个半角空格后再分类和请求。
- [ ] `give up`、含 Tab/换行的双 token 输入进入 V2 phrase；`can't`、`rock’n’roll`、`state-of-the-art` 进入 V3 word。
- [ ] 无警告时一次提交后自动创建草稿并进入对应编辑器，不要求第二次点击。
- [ ] 内置词典 `matched` 时，不显示原始状态码，而是清楚展示实际返回的 V2 英美主词或 V3 地区建议拼写、基本词性、词形和发音建议；同一 detection 被用于创建，编辑器中的 canonical 草稿已按后端规则预填。
- [ ] 建议摘要不会变成新的确认按钮；快速创建后，目标编辑器仍显示“已根据内置词典预填，请核对”，并能看到实际预填字段。
- [ ] 内置词典 `not_found` 时明确提示将创建空白草稿；`unavailable` 或建议无法安全解释时阻断并允许重试，不能把不可用伪装成未命中，也不能静默丢弃建议后继续。
- [ ] 智能词库 clear 时自动继续；重复项、surface warning 或策略要求确认时才停留并展示详情，且建议摘要与冲突说明不会混为同一状态。
- [ ] 重复候选详情展示词条名称/词面、词条类型、生命周期状态、命中原因，以及响应可提供的词性/释义或来源摘要；不显示 `word_id`、match ID、内部状态码，并且可用键盘打开和关闭。
- [ ] 有确认要求时保留输入，完整加载现有匹配并展示中文确认卡；确认后进入正确编辑器。
- [ ] 修改输入、确认过期、策略变化、并发响应和重复点击不会创建错误类型或重复草稿。
- [ ] 已有创建深链不会把用户带到双入口选择页；兼容行为有路由测试覆盖。

### V3 编辑器产品化

- [ ] 顶部、侧栏和状态不再显示 `Smart Lexicon V3`、schema、原始 status、revision 或 UUID。
- [ ] forms 页面不显示 `concrete form`、`membership` 或原始枚举；对应操作使用“词形”“复用已有词形”“通用/英式/美式”等中文文案。
- [ ] 同类型多词形、多个原形、一形多组、多发音和地区结构转换均可完成，保存 payload 中稳定 ID 与语义不变。
- [ ] meanings/examples 的卡片标题、字段标签、按钮和可访问名称不包含 UUID、`role` 或原始代码。
- [ ] 侧栏完成度与步骤实际 readiness 一致；点击问题可定位到正确步骤、词性、卡片和字段。
- [ ] 保存草稿、完成并继续、影响确认、dirty、冲突和错误状态均使用一致操作栏与产品文案。
- [ ] 核对页完整展示 V3 业务内容，不显示节点 ID、内部 node type 或原始 JSON。
- [ ] 发布历史与详情不显示 schema、publication/entry ID、revision 或 JSON；仍可查看不可变快照并按现有规则激活历史 V3 版本。
- [ ] published、published edit、archived、restore 等现有 V3 状态路径没有能力回归。

### 响应式与无障碍

- [ ] 在 1440px 与 1024px 宽度展示稳定的摘要侧栏 + 主编辑区，操作栏和长内容不互相遮挡。
- [ ] 在 768px 宽度收敛为单列或顶部摘要，英美双栏、发音矩阵和操作区不产生页面级横向滚动。
- [ ] 在 390px 宽度所有核心字段、确认信息和主操作均可访问；长词、长错误文案和按钮可换行。
- [ ] 仅使用键盘可完成创建提交、步骤切换、Tab/折叠切换、新增/删除/排序、确认、保存与发布前检查。
- [ ] 所有输入有可感知标签；纯图标按钮有不含内部 ID 的中文可访问名称。
- [ ] 校验失败或问题导航后焦点移动到正确字段；异步状态和错误对辅助技术可感知。
- [ ] 颜色不是区分当前、完成、警告和错误状态的唯一手段。

### 质量门

- [ ] 在写测试代码前由 `test` skill 产出并评审测试矩阵。
- [ ] 相关单元、组件、路由与 e2e 测试覆盖统一入口和 V3 语义保护路径。

## 开放问题

当前没有阻塞评审的开放产品问题。本文采用以下明确口径：

- “内部空白”包含粘贴产生的连续空格、Tab、换行及其他可识别空白，统一折叠为半角空格；
- 前端分类只负责选择既有创建链路，不取代后端对词面、重复项或 surface 的权威判断；
- “自动检测”负责获取后端权威建议和冲突证据；“建议预填”使用同一 detection，由后端创建结果承载；“冲突确认”只处理智能词库/surface 决策，三者不可合并为一个模糊状态；
- V3 的建议 base form 可以产品化显示为英式/美式“建议拼写”，但不据此生成 V3 领域唯一主词，也不填写 legacy compatibility；
- 建议卡自动出现并自动继续，不引入第二次确认；进入编辑器后的来源提示与真实预填字段保证快速响应下仍可清楚核对；
- 现有深链可以作为兼容路由保留，但不能重新出现在产品入口中；
- 原始 ID、代码和 JSON 不设置面向管理员的“高级模式”，本次默认与常规操作中均不展示。
