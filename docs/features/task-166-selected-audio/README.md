# #166：选用音色即生成正式音频

## 目标与范围

用户勾选音色后，只要正文、读法和配音配置有效，就应自动请求正式生成接口；默认勾选和载入时已有的勾选同样适用，不以点击试听为前提。结果作为 `audio_asset_id` 回写当前草稿，沿用现有保存流程持久化；不自动发布或提交其他未保存内容。

已核实的旧行为：手动勾选局部池音色已能串行生成；默认推荐和载入勾选未加入该队列，折叠字段未挂载编辑器，因此默认配置可能一直只有音色设置而没有正式资产。测试服 `dc8bd171` 上原词条 centre / center 的发布音频面板仍有缺失项。

## 依赖与实施

| 能力                                   | 状态     | 处理                                                                         |
| -------------------------------------- | -------- | ---------------------------------------------------------------------------- |
| Azure 正式生成、资产登记、请求幂等     | 主线已有 | 复用 `speech.generateAudio`，不增加接口                                      |
| 继承推荐解析、语法关联、IPA / UPS 来源 | 主线已有 | 复用现有适配器及 `speech.resolve`                                            |
| 手动勾选生成队列                       | 小改动   | 从当前有效勾选派生待生成项，不仅追踪点击事件                                 |
| 折叠正文及音标配音                     | 新接线   | 输入结束或载入有效配置后自动生成；输入中暂缓，保存可主动等待                 |
| 词形汇总表、词典带入和复制配置         | 新接线   | 不打开弹窗也处理已选来源；弹窗打开时暂停，关闭后恢复；旧配置先读取缺少的地区 |
| 业务保存                               | 小改动   | 等待本页登记的音频任务回写后，再读取当前草稿并保存                           |
| 发布检查、批次确认                     | 原样复用 | 继续校验正式资产；不在检查和读取端偷偷生成                                   |

关键路径：失败基线 → 生成触发及草稿回写 → 保存等待 → 定向回归 → 真实后端页面验收。

## 行为边界

- 只生成有效且已选用的声音；已有匹配资产复用，未选用项不生成，不自动播放。
- 正文、读法或参数变化后，旧结果失效；取消勾选、切换目标、失去编辑权限或关闭编辑器后，迟到结果不能覆盖新草稿。
- 失败保留选择和输入，提供显式重试；同一输入重试复用请求身份，避免无限自动重试。
- 多个折叠字段的正式生成串行执行，避免同页默认配置同时请求供应商。
- 后台资产回写不能关闭正在编辑的音色详情，保存参数时保留仍匹配的正式资产。
- 音色解析只提供有效参数，不得恢复已被当前草稿清除的旧资产；资产回写本身不重复触发音色解析。
- 缺少 `speech.generate` 或内容编辑权限的读取流程不启动生成。
- 不批量改写既有词条；只有进入授权编辑流程、其当前已选用配置确实需要音频时触发。

## 验收

- 默认勾选、载入勾选和手动勾选均无需试听即可生成，并将正确资产绑定到对应版本。
- 折叠正文、语法关联、当前启用的 IPA / UPS 配音使用正确来源；已有音频及未勾选声音不重复生成。
- 生成中保存等待回写，保存后重新 GET / 打开仍有同一资产引用。
- 改字、改参数、取消勾选、切换目标、只读及失败重试均保留正确状态，不绑定过期结果。
- 所有真实 OSS 测试限定独占批次；创建前通过清理权限预检，结束后彻底清理对象版本、删除标记及专属登记。
