# 统一音标自动转换

范围：管理端现有「字典音标 → 实际发音 → Azure IPA / UPS」按钮内置规则，无规则配置界面、无 API 或存储结构变更，不批量改写历史数据。

依据：用户提供的[天生之统一音标规范](https://www.yuque.com/tianshengzhi/cowork/ymutpyfg2e1ykvt4)，于 2026-10-11 读取。目标音素依据 [Azure 英美音素表](https://learn.microsoft.com/azure/ai-services/speech-service/speech-ssml-phonetic-sets)、[Azure UPS 表](https://learn.microsoft.com/azure/ai-services/speech-service/customize-pronunciation)及 [SSML 文档](https://learn.microsoft.com/azure/ai-services/speech-service/speech-synthesis-markup-pronunciation)链接的微软 UPS 参考（长音 `lng`、复合音 `+`、重音 `S1/S2`）。这些资料说明格式，不代替音色的真实合成试听。

## 转换顺序与边界

1. 字典音标按钮读取当前词形拼写、口音、常规／强读／弱读，生成统一音标。原字段不变，结果只进入实际发音字段。
2. IPA / UPS 按钮读取实际发音，根据按钮的英美口音适配目标音素。UPS 共用 IPA 适配结果，再生成 UPS 音素、重音、音节边界与逐词元数据。
3. 有旧内容时预览确认，支持撤销。确认期间来源、词形、口音、读法或目标变化时旧结果失效。转换失败不写入部分结果，转换不改变语音来源选择。

### 字典音标到统一音标

| 文档规则        | 自动处理                                                                                       | 边界                                                                                            |
| --------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 1、3、4 元音    | `e→ɛ`、短 `ɑ→ɒ`、`oʊ→əʊ`；保留 `ɑː`、`ɑr`、`eɪ` 等完整组合                                     | 长组合优先，不重复替换生成结果                                                                  |
| 2 happy 元音    | 已有前置元音、非显式重读音节的裸 `i→ɪ`                                                         | 保留唯一或显式重读的 `i` 与 `iː`，不推断未标出的重音                                            |
| 3、5 卷舌及滑音 | `ɝ/ɚ→ər`；`ɪr→ɪʲər`、`ʊr→ʊʷər`、`ɛr→ɛər`；`ɪə→ɪʲə`、`ʊə→ʊʷə`                                   | 复合元音中的对应序列沿用规则；r 后接元音时不视为卷舌韵尾（如 very、literature）；不凭词形增删 r |
| 6 ju            | 短 `ju→jʊ`，保留 `juː` 与 `uː`                                                                 | 不凭目标口音增删 j                                                                              |
| 7 清浊          | 显式音节起始的 `sk/st/sp→sg/sd/sb`；文档中的 Hudson、英式 bib、of course 按原音标匹配处理      | 不把词尾 ask/last 或所有 b/d/v 全局替换；其他清化需要额外语音依据                               |
| 8 闪音          | 已标出的 `ɾ→d`，以及文档明确的美式 butter、city                                                | 不把任意 t 都变成 d，不反推统一记法 d 的来源                                                    |
| 9 成音节辅音    | `l̩/n̩/m̩` 与文档给定前置辅音后的音节末 l/n/m 补 ə                                                | 不在任意辅音丛里补 ə                                                                            |
| 10、11 读法     | 使用已有读法选择，按文档中的 family、definite、useful、careful、different、literature 示例映射 | 同时匹配词形、原读音、必要的口音；未知强弱读只规范符号并提示核对，不生成新发音条目              |
| 12 喉塞音       | 文档明确的美式 button、Italy 弱读生成 ʔ，已有 ʔ 保留                                           | 其他词不猜测喉塞音位置                                                                          |

文档个别示例仍保留 `e`（如 seven），与“舍弃 e、保留 ɛ”正文不一致；统一执行正文符号规则。英美通用字段遇到明确口音差异示例时提示在对应口音下转换，不读取全局偏好替用户选择。

### 统一音标到 Azure

- `r→ɹ`；英式滑音组合还原成 Azure 元音组合 `ɪə/ʊə`。美式 `ɪʲər/ʊʷər/ɛər/aɪʲər/aʊʷər` 映射为官方列出的 `ɪɹ/ʊɹ/ɛɹ/aɪɹ/aʊɹ`，不将上标滑音读成额外辅音。
- 美式 `əʊ→oʊ`、`ɒ→ɑ`、`iː/uː/ɑː/ɔː→i/u/ɑ/ɔ`；英式保留其长音及元音。已录入的 `ər` 输出 `əɹ`，不凭丢失的重音信息猜 `ɚ/ɝ`。
- UPS 英式长元音带 `lng`，双元音按 UPS 组合表示，英美口音不混用。例：英式 `wɜːld→W ER lng L D`，美式 `wərld→W AX R L D`。
- IPA 在词中重音前补明确的音节边界（`həˈloʊ→hə.ˈloʊ`），避免 Azure 将重音前移。UPS `ˈ/ˌ→S1/S2`；两者保留显式边界，但不会推断所有未标出的音节。短语按空格逐词处理，不猜连读词界。
- Azure 英语音素表未列出 `ʔ`，IPA 与 UPS 自动转换均给出具体错误，保留原值，建议其他已录入读法或真人录音。美式目标遇到英式 `ɜː` 也不擅自添加卷舌音。
- 这不是字典查询或语音识别系统；有信息损失的教学记法不能无条件逆推出原始实际声音。已有手工 IPA/UPS 不批量规范化。

## 验收

2026-10-11 的验证：

- 整仓普通测试：249 个文件，3624 项通过、2 项原有跳过。后续卷舌边界及 Azure 重音修正后，6 个受影响测试文件的 117 项定向回归通过；整仓类型检查及改动文件 ESLint 通过，最终共享包类型与 lint 复核通过。
- 真实 Azure：en-GB-SoniaNeural / en-US-AriaNeural，57 次合成请求，55 份有效 WAV；2 个故意无效音素请求正确返回 400。13 组词／口音分别合成默认拼写、IPA、UPS，另加重音、错误音素、正文与音素不一致的控制组。
- 将正文 cat 指定为 dog 的音素后，机器回听为 Dog，证明音素覆盖生效，而非一直回退到拼写。
- hello 补重音边界后重新合成，IPA 与 UPS 的音频波形差异大幅缩小。tomato 的完整分音节与仅补已知边界仍不同，未宣称可从任意字典音标自动恢复所有音节。
- **未通过发音准确性验收的样本：** of course 清化为 əf 后，IPA／UPS 回听为 FC；保留 əv 及默认拼写均回听为 Of course。加重音可改善识别，但不足以证明教学读音正确。遵守用户规范保留清化规则，需人工对照试听决定是否调整。
- butter 的机器识别置信度偏低，但默认拼写基线也偏低，不能据此认定转换错误或把识别置信度当作发音准确率。
- 原始请求结果、无凭据脚本、源文件摘要及内嵌音频报告保留在本地 `test-results/unified-pronunciation/`（Git 忽略目录）。未进行人工专家听辨；波形接近和语音识别成功不等于音素准确。

本次直连真实 Azure，复用本地配置中的凭据；未启动后端或连接数据库，没有验证浏览器登录、应用后端、对象存储和持久化链路。样式修复已在浏览器验证：空值、单行、多行、撤销按钮和窄容器的按钮／输入框上下边界一致。PR 交付另由原生 hooks 和独立提交审查把关；合并与部署不在本次授权范围。
