# 词形变化配置：重新评估

状态：用户已确认并完成实施；验证见 verification.md。日期：2026-09-09。

## 目标与结论

用户希望把词条编辑器的词形类型列表，像基本词性一样放在「系统设置 → 词性配置」维护。
截图只作为入口与选项的参考，不构成其他实施指令。
建议增加「词形变化」Tab，支持搜索、新增、修改、删除未引用项，按完整配置管理实施。
基本词性已有稳定编码与目录校验模式可复用；固定枚举是实现中需要改造的部分，不是削减新增、删除能力的理由。
上一版另加手动排序、删减名称字段未充分遵循既有交互，本版纠正。用户已通过“开始实施”批准该范围。

## 页面与操作

- 超级管理员可管理；普通有效管理员可读取创编需要的目录。
- 复用基本词性的搜索、分页和操作布局：序号、正式中文、简洁显示、正式英文、英文缩写、英文全称、引用词条数、创建人和创建时间。
- 新增/修改沿用五个名称字段及派生默认值：简洁显示跟随正式中文，英文全称默认取正式英文小写；手动修改后不再覆盖。
- code 在创建时由英文全称按现有规则派生，用户不填、不看，创建后不可改；修改英文全称不重新生成 code。
- 排序沿用基本词性：新增自动追加末尾，修改保留顺序；不增加手动排序。
- 业务页面沿用现有词性展示约定，优先显示正式中文。

## 规则与范围

1. 初始化现有 8 项，保留原有 code 和中文名，不改历史词条内部引用。
2. 所有基本词性继续共用同一全局目录，不增加所属基本词性筛选或词性与词形关联配置。
3. 原形 `base` 的名称可编辑，编码不能改，不能删除，下拉中仍居首位。每个完整变化组至少有一个原形；继续允许多原形、同类型多条词形和跨组复用。
4. 其他类型，包括非原形内置项，未被应保留的草稿、历史发布或关联引用时可删除；被引用项只能修改展示信息。
5. 内置词典标签映射仍使用原 code，建议输出按当前目录过滤，避免自动生成已删除类型。
6. 自定义类型可在下拉选择、人工录入拼写与发音、保存、发布及用于关联；本次不增加语法规则、拼写推导或词典映射配置。
7. allowed_form_types/default_form_types 继续同源、按序排除 base；不新增默认生成配置，不追补已有词条。
8. 改名不改变词条 revision；管理成功后刷新当前客户端相关缓存，其他客户端重新获取目录后生效，不增加实时推送。

## 验收标准

| 风险                   | 可观察验收                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------- |
| 配置能保存但业务不可用 | 新增原 8 项以外的测试类型 → V3 下拉选择 → 保存刷新 → 发布 → 匹配及关联读回均成功   |
| V2/V3 不一致           | V2 恢复入口继续读取、保存合法类型；V3 复用 V2 类型的匹配接口不会拒绝自定义编码     |
| 名称只改了下拉         | 下拉、预览、发布历史、目标选择、匹配及问题定位名称一致，词条 code 和 revision 不变 |
| 删除破坏历史           | 当前草稿或仅历史 publication 引用均禁止删除；未引用非 base 类型可删，base 始终拒删 |
| 并发产生悬空引用       | 删除和保存并发时，不留下目录不存在的词形编码                                       |
| 删除后仍自动生成       | 删除未引用内置类型后，检测/补全不再输出它，其他建议正常                            |
| 加载失败或目录过期     | 可重试，保留编辑内容，不猜测候选；展示可兜底为内置名称或编码，提交仍由后端校验     |
| 权限及修改冲突         | 非超管不能管理；名称/编码冲突定位字段；旧 base_revision 不覆盖新版本               |
| 历史语义退化           | 原形必需、多原形、重复类型、跨组复用和英美结构维持原规则                           |
