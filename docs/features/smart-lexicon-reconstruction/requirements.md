# 平台级 Agent 与全新智能词库需求方案

日期：2026-11-04。状态：可评审草案；本方案范围止于需求与架构评估，不实施业务代码、不训练、不发起付费调用、不迁移数据或部署；文档提交与 PR 按后续交付授权办理。

目标是建设天生会背自己的 Agent 平台，以全新的智能词库作为第一个业务接入。平台负责可控执行与持续改进，业务负责事实、权限和最终决定。未来可容纳十几个业务 Agent，但不预设数量、角色名单或每个 Agent 独立部署。

配套：[架构、数据与实施估算](design.md)、[代码与原型证据](evidence.md)、[甲方业务图](business-diagrams.md)。本目录是三仓唯一主方案。旧版关于旧词库迁移、强制保留旧命题功能和“不建设平台级 Agent”的范围及估算均被本版替代。

## 2. 范围与非目标

### 2.1 首期完整目标

1. 最小公共平台：能力注册、模型接入、受限工具、任务持久化、取消与恢复、预算账本、反馈与评测、运维可见性。
2. 全新词库：创建、检索、内容编辑、AI 候选、审核、发布、历史、用户阅读；内容身份与数据结构全新设计。
3. 英语＋中文完整内容：词形发音、义项、语义区间、语法、分级释义、译词、关系、共享例句与译文、来源。
4. 对接边界：新用户词典优先，词表与学习按明确的新接口接入；旧内容和已有学习事实由旧路径继续服务。
5. 用一个差异较大的第二场景检验公共平台。评论审核是候选，尚未授权实施；业务本身不存在时不能把创建评论模块藏在“接入一个 Agent”中。

### 2.2 不在当前实施范围内

- 旧词库数据迁移、历史字段转换、旧新词义自动映射、全库内容生产。
- 默认移植全部旧 Agent、默认关闭旧服务、重建账户和通用权限体系。
- 自动审核发布词库；Agent 自行写正式业务数据；任意 SQL、Shell、网络地址或第三方插件执行。
- 可视化工作流设计器、任意动态代码、Agent 自主招募 Agent、平台通用审批系统。
- 首期全部语言、全界面国际化、评论业务完整重建、学习算法重写。
- 自动训练、在线更新参数、未批准的模型供应商切换。

不迁移旧词库，并不等于可以不处理下游接入。新旧数据使用不同身份与明确入口；旧资源不能因拼写相同被替换。是否最终关闭旧模块属于另一次范围决定。

下表后四类是需求方向，尚未构成立即交付承诺。延时是待实测的产品目标，吞吐是假设量级，不是已有容量。每类都先明确业务行为，再决定是否需要模型或多个 Agent。

| ----------------------------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 词库内容生产：编辑手动选择板块/组合 | 指定义项、语言、内容版本、资料、预算 → 候选、缺口、来源、用量             | 可自动检索、生成与结构校验；编辑选择保存，审核者确认，发布者发布 | 提交目标 ≤2 秒；单板块数十秒，组合分钟级；低频大任务 | 义项不漂移、不编造引用；只能看编辑有权访问的范围；超时保留可核查结果，未知调用不盲重试   |

| 词表辅助审核：审核员/提交事件       | 词表提交版本、内容及规则 → 问题分类、证据、审核建议                       | 规则可检查缺项；Agent 建议；最终批准、退回由业务审核流程决定     | 秒到分钟；提交时突发，通常可排队                     | 不替换已有审核事实；不因词表标题变化误用旧建议；已有人工审核模块可复用                   |
| 评论辅助审核：发布事件/审核员       | 文本、必要对话上下文、政策版本 → 风险标签、证据片段、建议动作、可拒判状态 | 首轮影子运行，不拦截、不删除；以后自动限流/隐藏须另定政策        | 线上若接入则目标 1–3 秒；突发、高吞吐、小输入        | 误杀与漏检分开，申诉闭环；最少个人信息；超时进入业务规定的人工队列，不能自动解释为“安全” |
| C 端出题：学习请求/预生成任务       | 有效已发布且已审核题源、学习范围 → 候选题或不足原因                       | 确定性算法优先；模型只选合法引用；题目审核仍是独立事实           | 用户请求通常秒级；高峰集中，宜预生成合格缓存         | 不允许每次点击等待大型研究；无合格题源则回退既有合法题型/提示不足，不降为未审来源        |
| 学情分析：教师/学生/定期任务        | 经授权统计、时间窗、样本量 → 证据化总结与建议                             | 统计由业务计算；模型解释；不自动改成绩、学习计划或给学生永久标签 | 分钟级异步；周期批量，较大上下文                     | 学生/班级隔离；显示数据期与缺失，不能从相关性声称因果；隐私风险高于词库                  |

建议压测输入：首轮以 10 位同时在线编辑、2–4 个活跃生成任务、单实例有限模型并发建基线；评论候选用 20 条/秒短时突发验证排队与隔离。它们只是工程实验点，必须在 P0 用实际预期量修订。持续吞吐取决于供应商限额、平均调用次数与耗时，不能由 Agent 数量推导。

不为已知的几个场景增加十几个虚构角色。同一个词库 Agent 可以有多个明确能力；一个确定性校验步骤无需包装成独立 Agent。

## 4. 用户、权限与操作语义

| 职责        | 可以做什么                                       | 边界                                             |
| ----------- | ------------------------------------------------ | ------------------------------------------------ |
| 编辑        | 新建、修改、请求生成、查看并采纳候选、保存草稿   | 查看权不等于修改权；采纳到本地不等于保存         |
| 审核者      | 确认指定版本、标记争议、撤销确认、附依据         | 是否允许自审见 D02；审核不自动发布               |
| 发布者      | 核对缺项、预览、发布、撤回、历史回退             | 必须检查当前权限、内容与依赖版本                 |
| 平台运维    | 看任务、失败、成本、队列、停用能力、管理模型策略 | 不因运维权限获得词库内容批准权或学生数据查看权   |
| 学习者/教师 | 使用授权的公开词库、个人或班级学习结果           | 不获得内部审核附件、原始提示、凭据或其他用户数据 |

每项任务显示：申请范围、正在做什么、已完成什么、需要什么人工动作、预算/已知用量/未知用量、失败或取消后可做什么。提供查询、取消和明确重试入口，不要求用户理解服务进程。

业务后端是权限与保存权威；Agent 根据委托调用工具，每次调用仍由业务校验。模型提出工具请求不代表授权。首期工具以只读为主，候选提交是执行产物，不是业务批准。

## 5. 新词库核心模型与编辑流程

### 5.1 核心概念

- **词条**：稳定身份的词或短语，相同拼写不自动合并。新 ID 与旧库互不替代。
- **目标语/媒介语/地区变体/界面语言**：分别是学习对象、解释语言、表达差异和界面文案。首发英语＋中文；建议英美、简体中文、中文界面，具体变体见 D04。
- **义项**：具有稳定身份的意义；自己的难度、词性、区间、内容。排序和中文标题不是身份。
- **语义区间**：组织义项的分类，名称可按语言维护；不等于一个义项。
- **释义、译词、例句译文**：解释意义、给对应词、翻译一句话，分别建模，不能合为同一个翻译字段。
- **共享例句**：独立生命周期的原文及译文资源，多义项引用；引用适配与句子本体审核分开。
- **审核单元**：具体版本的内容板块；**发布版本**：不可变的公开内容快照。

义项难度、释义阅读难度、例句原文难度互不代替。译文自由度不属于 CEFR，也不是翻译正确率。

### 5.2 工作区与闭环

列表可按词面、目标语、归属、草稿/发布、缺项、待审/争议筛选。四步工作区为“词条身份 → 词性词形发音 → 词义与例句 → 预览发布”，步骤可跳转，不强迫一次填完。概览定位到实际字段并保留上下文。允许保存不完整草稿，非法引用、越权和版本冲突仍拒绝。

代表性验收：从空库创建 job → 人工建立词性及“职业/任务”义项 → 生成某义项的英文释义与中文译词 → 预览并选择保存 → 重新打开仍在 → 待审版本发布可供词典阅读但不可测评 → 审核对应版本 → 发布新快照进入测评资格 → 修改释义使新草稿确认失效，已发布快照不被静默重写。

当前发布内容的确认被撤销时，未来测评立即停用对应来源，不需要等下一次发布；已经形成的学习答案快照不重算。详情见设计中的资格与发布分离。

### 5.3 内容要求

| 内容         | 必需行为与边界                                                                                                         |
| ------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 词性词形发音 | 人工配置基本词性；允许通用/专用词形、共享内容、多读法、英美差异、短语成分；候选单独确认，不由生成义项偷偷新增词性      |
| 义项目录     | 新增、排序、归组、细分词性；AI 提示与现有义项的边界，不能自动合并或删除；中文标题可来自前两个常见译词，身份始终独立    |
| 语义区间     | 多语言名称及完整归组建议；每个参与义项恰好归组一次；已确认内容的改动须显式重新待审；词元可待关联，不造目标 ID          |
| 释义         | 同语言可有多条、同等级可多条；定义/整句方式独立，语法绑定可明确为空；修订追加新记录并关联原释义，不覆盖已确认原文      |
| 语法         | 三类有序分段：词性提示、目标词汇、待填成分；逐字拼接等于原文且包含目标词汇；结构改变使相关释义适配需重新核查           |
| 常见译词     | 按义项、媒介语记录；去重、语体、行业和评分领域分开；常见度 0.1–99.9、精度 0.1，只是估计；明确“无”不同于未填            |
| 义项关系     | 派生/近义/反义绑定具体新库目标义项；分数 0–99.9；目标不存在可留待补草稿，公开有效关联必须可解析且获授权                |
| 共享例句     | 原文等级、语体、领域、句内词元、译文及音频；更改显示影响范围，保存草稿不自动更新各处已发布内容                         |
| 译文         | 每个媒介语可多条；自由度 0–100、精度 0.1，按三等分派生直译/意译/创译；不同自由度都必须忠实原义；人工未评估可为空并提示 |
| 来源         | 区分真实引用、改写、AI 原创、人工原创；引用要有可核查定位；来源不可访问时如实显示，不改标原创掩盖不明来源              |

自由度类别边界为 `[0,100/3]`、`(100/3,200/3]`、`(200/3,100]`。新模型只存规范 freedom，无旧 restoration 或旧 band 迁移字段；原型内部历史转换代码不进入新库需求。

### 5.4 组合生成与预算

支持义项目录、语义区间方案、单条语法、单条/批次释义、译词、三类关系组合、六级例句和 `sense_bundle`（释义＋译词）。它们是一个词库 Agent 的能力，不必各自成为服务。

第二版的六级例句覆盖 A1–C2；条数以义项等级为中心建议分布，约每级 5–20 条。短句译文建议直译/意译/创译约 1/2/5 条，长句建议 1–3/至少3/至少8 条，长句默认参考 20 个英语词。这些是原型内容目标，不是首个闭环的固定产量，也不是必须凑数的质量标准。原型每语种至少两条组合释义同样需要纳入预算拆分。

生产必须先展示批次范围和上限，按“来源准备 → 语义计划 → 分级生成 → 校验”分步，报告覆盖和缺口。预算不足时不伪装完整成功；可以保存已验证的部分候选，由用户明确选择采纳。继续生成是新批次，沿用来源和覆盖信息且去重，不无限追加调用。具体条数与预算由 D06 决定。

### 5.5 来源研究

首期建议只用明确获授权的资料源及人工资料；“有内置词典”不等于拥有再分发或训练许可。受控在线来源按 D05 开放。每次访问由工具生成回执，模型只引用已有 source_id；模型自称访问成功不算证据。

“研究 20–30 部词典”不能变成默认抓取目标。展示已访问/无结果/不可访问/未访问，区分访问成功与内容支持结论。内审原文、附件和公开来源摘要分开；“天生®自创”可以是公开标识，但内部仍区分 AI 与人工，不作为版权许可证明。

## 6. 审核、发布与读取

### 6.1 审核范围与失效

审核单元包括：词形发音、义项目录、某语言语义区间、语法结构、义项总体数据、单条释义、某媒介语译词组、例句及译文整体、义项例句引用、某类义项关系。建议首期例句与全部译文整组审核；新增译文会使该组重审，见 D07。

状态为待审、已确认、有争议。确认记录审核者、时间、内容及依赖指纹；改变被确认内容或关键依赖即失效；重新确认不能抹去旧意见。审核旧页面必须冲突，不能确认更新后的陌生内容。审核进度以实际启用板块为分母，不把未开放语言算缺项。

| 状态                 | 保存草稿       | 词典公开阅读                                                      | 新测评使用                                       |
| -------------------- | -------------- | ----------------------------------------------------------------- | ------------------------------------------------ |
| 待审                 | 可以           | 用户已确认：满足结构、来源和发布约束后可以                        | 不可以                                           |
| 已确认               | 可以           | 满足发布约束后可以                                                | 相关内容与依赖均确认、题型适合、无答案泄露后可以 |
| 有争议               | 可以并保留意见 | 建议阻止争议版本新发布；已公开内容提示并进入处置清单，待 D01 确认 | 不可以                                           |
| 已撤回/归档/无权公开 | 按生命周期权限 | 不可以                                                            | 不可以                                           |

“所有结果 requires_human_review=true”表示 Agent 产物未获人工确认，与待审内容允许词典阅读并不矛盾。读者应能看见待审标识；模型自评不替代审核。

### 6.2 保存与发布

发布区分硬约束、必填和质量提醒。硬约束包括权限、合法结构、有效依赖、媒体归属；必填包括词条目标语、基本词性原形、义项等级/细分词性/区间、目标语释义以及已填写行的完整字段；普通待审和非必需内容缺口为提醒。音频哪些场景必须有，见 D03，不能以新审核规则擅自取消旧模块门禁。

预览绑定本次内容和依赖版本；实际发布再次校验并原子写入。发布失败不产生半个版本。草稿编辑不改当前快照；历史回退产生新发布记录、重新检查当前依赖，不删除当前草稿。支持单条及有界批量发布、撤回、归档/恢复和历史查看。

共享句子的公开内容来自独立发布版本。词条发布固定句子版本；句子撤回后当前读取和未来测评必须复核可见性，不能无限信任旧缓存。

### 6.3 阅读选择规则

建议采用第二版最终逻辑，作为待评审规则 D04：

- 地区精确匹配 → 明确语言通用内容 → 显示缺失；不把缺失美式静默冒充已有美式。
- 释义优先不高于阅读水平的记录，默认其中最高可读等级；没有时取最近较高等级，再没有时显示未知等级。多条同级可切换，滑块只落在真实内容上。
- 例句先筛语体/领域，再从可读档中选最接近义项等级的一档；没有可读档才回退最接近用户等级，距离相同取较低档。档内按英语词数、字母序、稳定身份排序。
- 译文首次从意译随机选；没有意译显示缺口并用其他已有译文。首次主动切换低等级优先直译，B1 及以上优先创译；随后循环未展示记录。自由度滑块只选现有译文，不改评分或文本。
- 随机与已读状态在阅读会话内保持；版本、语言或候选集合变化重新核实。预览与用户端使用相同规则和选择状态。
- 词汇/句子连读开关只改显示，不能据演示标记认定音频已验证。
- 新录入建议首期 A1–C2；原型 Pre-A1 与六级控件冲突须定稿，不存在“保留新库历史 Pre-A1”的迁移工作。
- 用户响应仅含公开内容、公开来源摘要及获准音频，不包含审核人、内部意见、提示词和附件。

## 7. 平台体验与非功能要求

| 能力       | 必须满足的行为                                                                                           |
| ---------- | -------------------------------------------------------------------------------------------------------- |
| 能力目录   | 按场景显示可用操作、版本、语言、模型能力、预算和维护状态；未知能力拒绝，不执行任意提示命令               |
| 可靠任务   | 重开可查；重复提交返回原任务；只有已持久化才显示提交成功；断开观察不取消长任务                           |
| 恢复与重试 | 区分未发送、已完成、调用结果未知；有安全检查点才自动恢复，预算不重置；不承诺模型严格只调用一次           |
| 取消       | 禁止新的调用与后续采纳；已发生费用保留；保存先成功的内容不因取消消失                                     |
| 人工等待   | 用业务审核单记录决定；等待不占 worker；恢复必须核对权限、版本和有效期；第一闭环用“执行结束→人工采纳”即可 |
| 模型策略   | 先按能力筛选，固定一次执行的策略；fallback 仅在预先允许的范围发生并记账；不因失败偷偷切付费账户          |
| 故障隔离   | 长词库研究不能耗尽短问答或审核的资源；有界并发、排队、限流、停用能力和全局熔断                           |
| 可观测性   | 业务请求、执行、步骤、调用、候选、采纳和反馈可串联；敏感内容默认不入日志；费用未知显示未知               |
| 降级       | AI 不可用时手工编辑/审核/发布/读取仍可运行；质量不足返回不足，不自动放宽内容资格                         |

吞吐、可用率、恢复时间、每批预算的数值在 P0 压测与需求量核实后冻结；第一闭环必须先证明无越权、无重复采纳、无错误终态和可恢复性。

## 8. 经验积累与训练需求

积累四类相互独立的资产：业务事实和来源、人工版本化决定、可撤销的案例/规则、隔离的评测和训练数据。采纳是行为信号，审核是质量判断；没有采纳不等于负例，改了两个字也不等于模型原答案错误。

路线为“规则/工具与检索 → 固定评测 → 小范围参数训练实验 → 合格后灰度”。SFT 学示范，偏好训练学同输入下的优劣，蒸馏让更小模型学习教师输出；都要真实更新参数才可称训练。模型总结只能作为待审建议，不能自动变成平台规则。

优先收集原因码、人工修改前后差异、证据、适用范围、撤销关系；不要收集隐式思维链。学生数据、私有评论、资料全文不能因为产生了日志就默认可训练。样本许可、删除传播、版本回退和评测隔离须先设计。具体门槛与费用模型见技术文档。

## 9. 分阶段路径与验收

| 阶段                  | 输入依赖                                   | 交付与退出条件                                                                                        | 风险/终点                                                        |
| --------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| P0 范围与契约         | 本文确认项、人工内容负责人、语言及来源政策 | 冻结新库概念、任务/保存契约、原型差异样例、评测判据和吞吐预算假设                                     | 不读取生产数据来估迁移；旧服务实际使用盘点另需授权环境           |
| P1 最小平台＋词库闭环 | P0；已有运行基础改造                       | 从全新空库创建一条内容，生成→选择保存→审核→发布→读取；重启、取消、重复请求、权限撤销均有确定结果      | 成果只是纵向样板，不宣称全部英语模块完成                         |
| P2 第二场景验证       | P1稳定；第二场景政策与脱敏/合成样本        | 候选评论审核影子接入；同一 runtime 接受非词库输入，不修改词库代码即可注册；共享模型、账本、取消和限流 | 未授权自动处置；业务入口不存在则先做离线适配验证，并列出业务缺口 |
| P3 全部英语词库       | P1/P2边界稳定；来源与语音规则              | 完整内容板块、组合生成、六级例句、来源、阅读控件、批量发布/历史、选定新消费者接入                     | 不带旧数据迁移；按新数据覆盖逐个开放消费者                       |
| P4 规模化/语言/训练   | 可量化使用数据、冻结评测与许可             | 分别立项新语言、额外 Agent、持久化引擎升级或训练实验                                                  | 每项单独说明收益和退出条件，不自动全做                           |

关键路径：产品政策/新领域模型 → 任务与工具契约 → 新库保存/审核/发布 → Agent 候选闭环 → 第二场景验证 → 完整模块及消费者。平台基础与编辑界面可在契约稳定后并行，不能跳过保存和授权直接证明“生成成功”。

| A06      | 取消与保存竞争给出实际先后结果，已发生用量不消失，未知费用不写零                      |

## 10. 待定决策与建议基线

仅 D01、D02、D03、D05、D06、D08 涉及明显业务风险或工作量，应由相应产品/内容负责人在相关阶段定稿；不要求一次回答全部问题才能评审架构。

| 编号 | 尚需决定                                 | 建议基线与影响                                                                                          |
| ---- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| D01  | 有争议内容的新发布、已发布处置与待审标识 | 普通待审可公开这一点已确认；建议争议阻止新发布、测评立即停用，公开旧版进入人工处置；撤回直接停止公开    |
| D02  | 自审及审核授权                           | 独立审核权限，首期允许有权限者自审且留痕；高风险内容再要求不同审核者                                    |
| D03  | 新库音频发布资格                         | 推荐按用途：词典文本可无音频并显示缺口，听辨/跟读必须有有效且经确认音频；旧模块门禁不改                 |
| D04  | 首发变体、等级与阅读规则                 | 英美＋简体中文、中文界面、A1–C2及第二版规则；中文等级标“面向该英语学习等级的解释”，不冒称中文 CEFR 标准 |
| D05  | 资料访问、公开引用、训练许可             | 逐来源登记使用范围，首期不默认联网抓全站；内容许可与训练许可分开                                        |
| D06  | 生成数量、时间及预算                     | 首个闭环小批次；完整六级/多译文分步有界，允许明确采纳部分候选；不上线“无限预算”                         |
| D07  | 例句整组审核粒度                         | 首期整组；后续若多语言审核负担过高，再引入按语种子单元                                                  |
| D08  | 第二场景与旧模块退场                     | 推荐评论审核影子模式作为复用检验；旧模块默认隔离共存，停用和旧消费者切换另按实际使用决定                |
| D09  | 运行与内容数据保留期限                   | 建议敏感输入短期、脱敏运行指标长期、业务发布历史按业务留存；具体天数、访问者和删除职责在上线前固定      |

本轮已完成评估的终点是这份需求及配套架构方案。尚未决定的政策均显式标注，不代表架构无法评审，也不构成实施授权。
