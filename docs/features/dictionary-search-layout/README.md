# 智能词库搜索栏重排（任务 145）

## 目标与范围

词条、词义和搜索操作常驻首行；附加条件按词条类型、基本词性、词义难度、词条状态、创建人、创建时间排序，桌面展开后两行三列，窄窗口依次降为两列和单列。初始收起；URL 带附加筛选时展开。收起保留值，搜索统一提交，重置清空全部条件并回第一页。垃圾桶复用布局，仍固定归档、不提供状态选择。

创建人为可搜索下拉，按管理员 ID 精确匹配；同名选项附 ID 尾段区分。选项包含有词条的创建人（包括已停用账号、归档词条的创建人），仅返回 ID 和姓名，不读取管理员管理接口。

## 契约与兼容

配套后端为 `tsz-rust` 仓库的 `codex/dictionary-search-layout` 分支；契约从该任务版本导出的 `docs/openapi.json` 同步。两仓 PR 在交付时相互引用。

- `GET /api/v1/admin/lexicon/entries` 新增可选 `headword: string`、`created_by: UUID`。词面为子串匹配，创建人为精确匹配，与其余条件取交集。分页主查询及空页总数使用相同条件。
- 旧 `q` 继续匹配词面或创建人，旧 `keyword` URL 可恢复；新版表单提交改用 `headword`。已有释义、类型、词性、难度、状态、日期、分页行为保留。
- `GET /api/v1/admin/lexicon/entries/creators` 返回 `Array<{ id: UUID, display_name: string }>`；权限为 `words.access`，不要求管理员管理权限。
- 现有响应结构不变，无迁移。发布须后端先行，再前端；新前端遇旧后端会缺创建人端点，且旧后端可能忽略新参数，不能作为支持组合筛选的版本使用。旧前端可继续访问新后端；回退后端前先回退前端。
