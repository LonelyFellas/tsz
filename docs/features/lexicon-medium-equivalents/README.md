# 媒介语言常见译词：需求评估

评估日期：2026-11-15。当前阶段：首批前后端实现与本地真实联调已完成，已获授权进入两仓 PR、CI、合并与测试服配套发布。主记录集中在前端仓库；后续后端任务和 PR 引用本文，不重复建立需求。

## 目标与已确认范围

将新版智能词库「词义与译词」中的纯文本译词，扩展为按义项、媒介语言维护的常见译词组。截图是功能参照，界面沿用 [Admin 规范](../../../apps/admin/style.md) 和现有义项编辑布局。

用户本轮确认：

- 首批完成手工录入、语体与行业属性、常见度、保存和预览；AI 生成与人工审核后续接入。
- 常见度评分领域与行业标签复用现有「行业领域」目录，不新建评分领域配置菜单。
- 行业未独立评分时沿用通用评分，按后续反馈仅在悬停或聚焦评分时说明来源，不在每行常驻提示，也不复制成行业独立评分。

首批不增加发布、测评资格或 C 端消费能力，不搬入 V1 的完整释义/例句模型。AI、审核按钮只有对应能力实际接通后才开放，不提供无持久化支撑的状态或操作。

## 首批行为

### 录入与身份

- 当前义项、当前媒介语内录入词或短语，保留简繁体数据隔离；不增加新语言，也不改变词条媒介语归属规则。
- 回车确认单条，粘贴可按中英文逗号、顿号、分号、换行分隔；空白片段忽略，短语中的普通空格保留。中文输入法组词期间的回车不提交。
- 同一义项、同一媒介语内去重，建议以去首尾空白、NFKC、统一 Unicode 小写后的文本为比较键，保留用户录入的显示文本；不同义项或媒介语允许同文译词。不做简繁互转、同义词合并或语义去重。
- 标签和表格共享同一份译词数据，删除任一处的译词会同步移除本条标签、属性和评分。编辑文本或评分不更换 ID；重复文本的编辑被拒绝，不能静默合并已有评分。
- 沿用单条译词最多 200 个 Unicode 码点、拒绝控制字符及当前整稿节点数量上限。批量输入超过限制时说明原因并保留未提交输入，不能静默截断。
- 空组可显式勾选「本义项无合适常见译词」，与尚未填写分开持久化；新增译词自动清除此声明，删除最后一条不自动宣称“无”。

### 语体与行业

- 每条译词分别选择多个语体、多个适用行业；选择器读取真实目录，用稳定 ID 引用，不存中文显示名或把「通用」当目录记录。
- 多选中的「通用」是全选控制：全部选中、部分选中、未选择三种状态可区分，并提供真实半选语义。
- 建议按原型采用已选具体 ID 的快照：全选表示选择当时全部目录项；以后新增配置不自动扩大存量译词的适用范围。此为评估假设，实施时保持显式行为。
- 新增译词建议语体默认全选、行业默认未选择，常见度未评估。存量纯文本译词不自动补标签或分数，缺属性可保存为草稿。
- 目录为空、加载失败和无读取权限分别处理；失败保留已有选项与草稿，不能误当空目录清除原引用。

### 常见度

- 每条译词可有一个通用分、各行业分别一个独立分；切换上方评分领域只切换当前编辑维度，不改下方行业适用标签。
- 评分领域下拉为「通用」加现有行业目录。这里的「通用」是通用评分维度，与标签多选中的全选控制语义不同。
- 行业有独立分则使用独立分；没有则显示通用分；悬停或聚焦评分时说明「当前行业未单独评分，显示通用领域的分数。」；两者都无则为空。继承仅为读取计算，不批量落盘。
- 在行业内填写分数创建或更新行业独立分；清空独立分后恢复沿用通用值。通用分变化只影响继承显示，不覆盖已有行业独立分。只查看或切换领域不将继承值写成独立分。
- 取值 **0.1–99.9，最多一位小数**；空白为未评估，拒绝 0、100、负数、多余精度及非数字。修正原型表头「0–100」与实际范围冲突。
- 分数是常见度估计，不是百分比或概率，各译词无需合计 100；与义项已有的 `frequency`（0–100，最多两位小数）分别保存、分别校验。
- 原型按当前领域有效分降序显示，建议沿用；同分或未评分保持稳定顺序，未评分置后。输入期间不移动当前行，确认输入后更新顺序；视图排序不重建节点身份。
- 首批写入均为人工评估，由整稿操作者留痕；服务端维护独立分的评估时间，不接受伪造时间，不伪造 AI 或资料来源。后续 AI 来源附在实际候选及采纳回执上。

## 契约与持久化建议

继续使用 `/api/v1/admin/lexicon-next/entries/{id}` 的完整草稿 GET/PUT 和语言 view，不为每个输入新增保存端点。在既有译词身份上增加可选元数据，按义项及媒介语保存“明确无译词”状态；具体字段名由后端实现后原生导出 OpenAPI，前端保持 snake_case wire 镜像。

建议 wire 分数使用规范十进制字符串（如 `"95.0"`），后端精确转换为十分之一单位整数，避免二进制浮点舍入；缺省表示未评分，清空由具备新能力的完整稿明确表达。保留原始独立分与读取时的继承值区别，不把评分来源交给客户端任意伪造。

需要一并补齐以下依赖：

1. **引用完整性**：标签 ID 校验所属类别，评分行业必须来自行业目录。建立真实引用登记和删除保护，保存与目录删除须在事务中协调，不能仅靠前端禁用或扫描字符串。引用覆盖当前与保留的历史 revision；永久删除词条时随 revision 级联释放，避免删配置后历史草稿无法解析。
2. **读取权限**：当前目录 API 需要 `lexicon_settings.access`，词条编辑权限不保证含此权限。建议给词库查看者提供受 `words.access` 保护的只读选项目录，配置增删改权限保持原样；分页必须完整读取或支持服务端搜索，不能只拿首屏 20/100 条当全集。
3. **旧客户端保护**：沿用已有能力协商模式。新能力未开放时继续原纯文本行为；旧客户端编辑已有译词时，按稳定 ID 保留其看不见的属性与评分，不因字段省略而清空。新客户端明确清空和旧客户端缺字段必须可区分；显式删除节点仍按整稿规则生效。
4. **双重存储一致性**：扩展现有草稿 JSONB 快照及必要的关系投影/引用表；不能只让 JSON 快照保存成功，目录删除检查或语言 view 却读到旧数据。迁移需求由最终表结构决定，本次不承诺无需迁移。
5. **全稿安全**：完整保存保留其他义项、语言、词形、语法、语音、总体数据和区间；保留 `expected_revision`、归档限制及 `words.edit` / `words.edit_others` 的后端校验。

## 后续 AI 与人工审核

完整需求保留以下边界，首批不实施：

- 生成范围是当前义项和媒介语；新译词生成与已有译词评分区分，先预览候选再显式采纳，去重且不覆盖既有人工内容。真实任务须有预算、版本、幂等和可查询终态，不将原型无限生成或演示值直接上线。
- 审核单元为「义项 × 媒介语译词组」，不是给每个输入任意增加本地已审核开关；保存审核人、时间、意见及内容/依赖指纹。
- 新增、删除、修改译词，或修改相关属性、评分，使对应组重新待审；不使其他无关义项/媒介语整库失效。旧版本审核不能确认新内容。
- 审核授权与自审政策沿用总体需求待定项 D02，在接入审核时定稿。发布和测评资格另按新库实际能力接入，不因首批属性保存成功而宣称可发布或可用于测评。

## 剩余关键路径与验收

关键路径：**译词契约、领域与标签语义 → 目录读取授权及真实引用保护 → 后端保存/读取与旧客户端兼容 → 前端编辑/预览 → 真实回读验收**。已有目录管理、草稿版本和语言上下文直接复用，不重复实现。AI 与审核不阻塞首批。
