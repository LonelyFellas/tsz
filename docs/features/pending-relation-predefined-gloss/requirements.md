# 未入库关联词预定义词义：需求

## 背景与目标

管理员录入近义词、反义词或派生词时，目标词可能尚未入库。现有合同只允许通过
`pending_target_headword` 保存目标词面，发布源词条时后端再创建一个带空 A1 词义的
占位草稿。管理员已经知道目标词的基本含义时，不能提前写入，后续还要进入目标草稿
重复补录。

目标：未入库关联词除词面外，可选录入一条预定义中文词义；真正物化新目标草稿时，
该文本进入目标草稿默认 A1 中文释义。关联词搜索、绑定已有具体词义、分数和三类关系
行为保持不变。

## 目标端

- Admin Step 3“词义与例句”中的近义词、反义词、派生词编辑器。
- 前端 `tsz` 与后端 `tsz-rust` 合同、持久化、校验和发布物化链。

## 用户故事

1. 管理员输入词库外关联词 `reliability`，可继续填写预定义中文词义“可靠性”。
2. 保存草稿后刷新，词面与预定义词义均保留。
3. 发布源词条时，若目标仍不存在，后端创建目标草稿，并把“可靠性”写入默认 A1
   中文释义；relation 绑定到该稳定 sense UUID。
4. 不填写预定义词义时，保持现有兼容行为：目标草稿的默认中文释义为空。
5. 搜索命中已有词条时，管理员选择具体词义；pending 词面和预定义词义被清除，不改写
   目标词条。
6. 发布锁内才发现同名词条已存在且 pending 携带预定义词义时，不静默丢弃文本，也不
   覆盖已有词义；返回定位到预定义词义字段的可操作错误。

## 规则与边界

- 新字段为可选纯文本 `pending_target_gloss`，空白归一为缺失。
- 最多 5000 个 Unicode 码点，与单段 RichText 正文上限一致；拒绝 NUL。
- 只允许两种合法目标形态：
  - bound：`target_word_id + target_sense_id`，所有 `pending_target_*` 缺失；
  - pending：`pending_target_headword` 必填，`pending_target_gloss` 可选，两个 target ID
    缺失。
- `pending_target_headword` 继续复用 Step 1 的归一化、word/phrase 分类、英文字符集、
  至少一个拉丁字母和 200 字符规则。
- 预定义词义是目标草稿默认的中文释义正文，不是语义区间名、语法结构、例句或英文
  释义。
- 占位目标继续使用后端当前默认词性 `noun`；本功能不增加 POS 选择。
- 不允许用预定义词义覆盖已有词条或已有词义。
- 不新增立即建条动作；仍只在源词条发布物化，避免试填污染词库。

## 兼容性

- 历史 bound relation 不变。
- 历史仅有 `pending_target_headword` 的 relation 合法，物化后仍得到空默认释义。
- 新客户端对旧服务端必须由合同版本/部署顺序保护：后端与 OpenAPI 先落地，前端后启用
  字段，避免 `deny_unknown_fields` 拒绝。
- 发布快照和历史详情保留已绑定结果，不保留已消费的 pending 字段。

## 验收标准

- [ ] 未绑定且词面合法时显示“预定义词义（可选）”输入；bound 行不显示该输入。
- [ ] 输入、清空、刷新保持 relation UUID 和其余字段不变。
- [ ] 保存/GET round-trip 保留非空预定义词义。
- [ ] 新目标物化后默认 A1 中文释义正文等于预定义词义。
- [ ] 未填写时仍生成空默认中文释义。
- [ ] 绑定已有词义会清除两个 pending 字段，不覆盖目标内容。
- [ ] 同名竞态不会丢弃预定义词义或覆盖已有词义，返回稳定 field issue。
- [ ] bound 与 pending 混合形态、孤立 gloss、超长、NUL 均 fail closed。
- [ ] 前端/后端/OpenAPI/运行时 schema/数据库投影一致。

## 不在本轮范围

- 多条预定义词义、英文释义、CEFR/POS/语义区间选择。
- 自动词典释义生成或 AI 生成。
- 修改目标词条已有内容。
- 提交、推送、PR、部署或生产数据迁移执行。
