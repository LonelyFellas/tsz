# #264 短语词形变化

词性配置的短语页复用单词的词形类型管理。管理员可为短语词性创建复数、过去式等类型，并配置是否在新增词性时放入默认模板。编辑器从目录读取可选类型，同一短语词性可按现有规则新增和编辑多组。每组至少有一个词形才能发布，第一组仍需有原形。

`GET /api/v1/admin/settings/form-types` 增加可选 `kind` 查询参数，放在分页前筛选，通用原形在两侧可见。省略参数沿用旧后台的单词侧范围。创建和更新使用原有权限、请求与响应。草稿及发布沿用已有 `form_groups` 结构。短语类型由管理员按词性配置，迁移不会为存量词条补写词形。

Rust 迁移将词形类型归属的外键改为按词性 ID 引用，保留父级删除保护。先升级后端再启用新版后台。旧后台可继续管理单词。已有短语词形类型时，数据库回退会拒绝并保留数据，应采用前向修复。

验收使用隔离数据库和 Redis，创建短语词形类型并确认其仅出现在短语侧。在同一个短语词性下分别给第 1 组和第 2 组录入词形，保存后重新打开核对两组内容，发布后核对发布快照。

本地隔离验收已在后台创建短语复数和过去式，并确认单词列表的旧请求仍返回单词侧。测试短语以两组分别录入原形和复数，保存后在新标签回读拼写和实际发音，再从后台发布并独立回读快照。发布所需的释义和语法结构经真实 API 填充验收数据，按文本发布。
