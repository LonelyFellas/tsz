# 语体色彩与行业领域配置

## 目标与范围

词库管理下增加两个独立菜单：「语体色彩」与「行业领域」。两个菜单复用管理页，数据按类别隔离，支持分页搜索、新增、修改及确认删除。

配置字段为中文名、英文名、编码、序号；编码创建后固定。列表显示更新时间。名称前后空白去除，同类编码唯一、中英文名各自忽略大小写唯一；不同类别允许同名同编码。按序号、创建时间、ID 排序。

本次只实现独立配置目录，不修改词条、译词、例句编辑和发布结构，不把原型的「通用」全选控件存成业务标签，也不预填业务分类。当前后端不存在这两类词条引用；将来接入选择器时须另建真实引用及删除保护，不能按字符串猜测使用情况。

## 实现与契约

- 前端：`codex/lexicon-taxonomies`，基线 `dbe3a5fd6f90261f1c117fde1ca748657fb4b3af`；管理路由 `/words/registers`、`/words/domains`。
- 后端：`/Users/darwish/.codex/worktrees/lexicon-taxonomies-api/tsz-rust`，同名任务分支，基线 `8537ef74568a8f9b0e5c03ff25b0408020f352ac`。
- 共用 API：`/api/v1/admin/lexicon/taxonomies/{kind}`，`kind` 为 `registers` / `domains`。

| 操作 | Method / path                        | 权限与结果                                          |
| ---- | ------------------------------------ | --------------------------------------------------- |
| 列表 | GET `/{kind}?q=&page=&page_size=`    | `lexicon_settings.access`；200 分页信封             |
| 新增 | POST `/{kind}`                       | 新权限 `lexicon_settings.edit_taxonomies`；201 配置 |
| 修改 | PATCH `/{kind}/{id}`                 | 同新增权限；请求带 `base_revision`；200 配置        |
| 删除 | DELETE `/{kind}/{id}?base_revision=` | `lexicon_settings.delete`；204                      |

上述权限均依赖配置查看权限，普通管理员不会自动获得新增编辑权限。路由策略、handler、写事务均校验权限；写事务共享锁定管理员授权状态，修改/删除锁定配置行并比较版本。不存在或类别不符返回 404；重名返回 409 `taxonomy_conflict` 和冲突字段，版本过期返回 409 `revision_conflict`。失败保留表单输入；版本冲突后提示关闭并重新打开。

OpenAPI 由选定后端原生导出，前端显式指定该路径同步；响应通过生成的 runtime schema 校验，无 PENDING 扩张。数据库使用 `catalog.lexicon_taxonomies`，新增迁移 `20261113150000_lexicon_taxonomies`，up/down 成对。down 会丢失目录配置，需先导出要保留的数据；不改变词性/词形表。

旧前端配新后端：原接口、原响应结构不变，新目录独立。新前端配旧后端：新菜单不能使用（404 会显示加载失败与重试），所以需要先发布后端迁移及接口，再发布前端。回退前端不会删除配置；回退后端前须先撤回新前端入口并保留目录备份。本次未执行发布。

## 可观察验收

- 两菜单位于词库管理下；只读账号可查看，无查看权限时不发目录请求。
- 新增/修改后独立 GET 或刷新页面仍显示保存结果；类别间数据不串用。
- 同类重名、非法输入被拒绝；并发修改只允许一个版本成功，旧版本不能删除新数据。
- 保存期间不能重复提交或关闭弹窗；失败保留输入；读取失败不伪装为空列表。
- 删除需确认；删除当前页最后一条时返回前页。删除后重新读取为空。
- 按后台规范核对 1440px 桌面和 1000px 窗口，表单及主要操作可达。
