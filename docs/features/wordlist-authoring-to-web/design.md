# 词表创编迁入 C 端

## 范围与实现

普通用户和老师复用账号名下的词表编辑器及现有登录/手机号门禁。身份切换不改变作者归属。新建私密，作者主动公开；公开/待审内容先撤回再编辑，“注”是作者给读者的补充说明，跟随词表可见性并纳入内容版本及审核快照；已有个人私密备注维持独立版本且仅作者可见。

复用用户创建幂等键、编辑快照、分页 items、最多三项的已发布词条候选和 publish/review API。C 端提供名称、逐行选词、只读释义、作者注释及已有私密备注、增删、拖动和按钮排序、全表搜索、分页、错误行定位及离开保护。自动读取全部 items 后开放全表搜索与保存；所有批次须与冻结快照的 revision、总数和顺序一致。编辑会话隔离缓存，加载失败可重试，版本变化须重新打开，保存保留所有不可见行。搜索中禁止排序，避免误解筛选后的相邻位置。

后台移除创编 UI、路由、客户端方法、服务端创建/更新/编辑读取/创编候选路由及 create/edit 权限。用户词表 `visibility public=true` 一律拒绝，合法审核仍可通过。历史平台词表保持原作者、后台备注及既有查看/公开状态管理；不迁移数据，不新增平台词表。

不包括导入、识别、自定义词/语音和教师任务。

## 验收与兼容

- 普通用户和老师可创建、编辑、全表搜索/排序、保存并重新打开；身份切换归属不变。
- 他人不可编辑或读取私密备注；失败重试不重复创建；版本冲突不覆盖。
- 旧后台页面/直接请求/遗留权限均不可创建和更新内容，也不可直接公开用户私密词表。
- 保留审核、推荐、下架、删除、历史平台阅读、学习来源与投币。
- 契约由后端原生导出再显式同步到前端；删除的后台接口是有意收口。旧前端调用会失败，新前端对旧后端不会恢复该能力，但旧后端仍存在直接 API 绕过风险。需要后端更新才能形成完整权限边界；回滚后端会重新打开权限风险。

主记录仅在前端。两仓同名分支 `codex/wordlist-authoring-to-web`，实施基线前端 `79c1a25e`、后端 `092e492`。实施阶段授权止于本地验证；2026-10-13 用户进一步授权审查、提交、推送并分别开 PR。当前进入两仓 ship 流程，合并和部署仍未授权。
