# 中文释义单选题：跨仓实施

## 目标与范围

交付 C 端可用的“看中文选英文”四选一完整链路：后台选择已发布词义 → 独立 DeepSeek Agent 生成 → 人工修改/审核启用 → C 端创建单选学习任务 → 作答、反馈、刷新续做。

正确答案和三个干扰项全部引用智能词库有效发布词条及具体词义。候选不足时明确失败原因，不使用库外单词凑数。保留现有拼写学习任务；单选证据不更新拼写记忆。

## 必须满足的验收

1. Agent 无业务库权限，内部请求受服务身份和委托操作者/期限/状态限制；生成与审核前复核四个选项来源。
2. 生成仅产生草稿；审核通过才可出题。原释义、题干修订、选项与解析均可查看；编辑不绕过来源校验。
3. 未作答 DTO 不包含正确项、解析或可反推答案的元数据；提交选项 ID，由服务端按题目快照判分，幂等重试不重复计数。
4. 新学习任务支持明确选择拼写/单选；无可用已审核题时显示原因。刷新保持同一批次选项顺序与答题进度。
5. 来源撤回/词义变化、停用、重复生成、审核冲突、取消和服务故障有明确状态；历史答题仍可追溯。
6. 单选成绩不写入 `spelling_zh_to_en` 记忆。奖励规则不得通过混合题型重复发奖。
7. 验证现有拼写用户兼容；新增 wire 字段/枚举按实际严格运行时校验处理。OpenAPI 由后端导出后同步。
8. 使用隔离本地数据库、Redis和Agent数据库，以真实 API 及内置浏览器跑完整链路。真实 DeepSeek调用仅少量验证，不输出密钥；所有本次临时数据与进程自动清理。

真实联调使用本任务独占 PostgreSQL、Redis 和 Agent 数据库。4 个词面/释义来自会话中已核实的词库内容（apple、banana、orange、tomato），在本地经正常 V3 创建和发布 API 建立；管理员使用原生 seed 后正常登录，学生经注册、学习设置和词表 API 准备。短信发送采用项目已有 mock，无 OSS 上传。

已证明的实际链路：

1. 内置浏览器提交两次生成委托，真实 DeepSeek 共 4 次模型请求；所有选项均来自本地有效发布词条。
2. 未审核时，C 端预览为 0 道可用单选题。管理员修改解析、重开确认保存，再审核启用后变为 2 道。
3. 两条审核反馈均成功送达 Agent；第二次生成实际检索使用了第一条已审核案例。
4. C 端创建每日单选任务；键盘方向键仅选择，不自动提交。首题答错、次题答对，完成记录为 2/2、正确 1、正确率 50%。
5. 刷新后第二题顺序与 1/2 进度保持一致；完成后刷新仍能读取正确/错误反馈和人工解析。
6. 未答 API 不返回正确项、解析或内部来源；两次相同答题请求重放仍仅有 2 条答案和 1 条完成记录。
7. 无协商头的旧客户端看不到单选计划，直接访问单选批次返回 409；默认拼写预览、创建、答题成功，响应没有单选新增字段。
8. 在学生正式启用记忆功能后，单选作答产生 0 条拼写记忆，随后拼写作答正常产生 1 条，证明隔离而非仅因功能未启用。

补充边界：新增 Playwright 场景已通过测试收集；本地实际浏览器验收使用内置浏览器，没有将 mock E2E 当作真实联调。模型的风险提示仍可能有噪声，所有题目均经过人工审核。范围不包含合并或服务器部署。

## 提交前深度审查

前后端分别由独立 reviewer 审查完整暂存快照，再复查修复增量。用户要求先审查、修复再提交，因此提交后还需核对 hooks 生成的最终 tree 与已审快照。

- 前端：审查 2 轮；确认缺陷 2，均已修复；阻断 0；关联回归/回退：未知。修复迟到保存响应清除其他题目编辑标记，以及非 active 批次无法重放未确认答案。新增失败复现后，后台编辑器 4 项、练习页 16 项定向测试通过。
- 后端：审查 2 轮；确认缺陷 3，均已修复；阻断 0；关联回归/回退：未观察。修复候选固定截断、编辑后退回反馈案例错版、旧单资源路由放行单选覆盖计划。新增失败复现后，题库 7 项回归全部通过。
- 候选检索按 UUID 分批继续扫描，先筛选词性/级别与排除条件，再按不同词条限量；多义词不再提前占满内部候选池。
- 退回反馈携带当前受审核版本的题干/选项与具体意见，撤销仍不携带有效案例。

以上边界修复通过新增定向回归验证；未重复执行付费模型调用。实现阶段的真实端到端验收保留为核心用户链路证据。

## 配套发布边界

旧协议对候选 API 的拼写调用及单选隔离已通过真实 HTTP 验证；候选前端对旧 API 的能力缺省回退有契约测试。线上已部署前端/API 的精确版本组合尚未核实，不将上述受控验证当作线上验收。

建议先部署后端迁移和内部接口、配置独立 Agent，再开放新版后台和 C 端入口。产生单选学习记录后，down migration 会拒绝直接回退；旧后端不应直接接管包含单选数据的业务，需另行验证数据兼容或恢复方案。
