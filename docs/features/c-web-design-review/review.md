# C 端设计与交互审查

## 目标与范围

用户要求由一个独立子代理持续评审改动，并逐页检查 C 端设计与交互；管理后台明确排除。首页以用户指定的 Apple 官网为参考，功能页沿用 `apps/web/style.md` 的既有组件和阅读规范。

范围：`apps/web/src/app` 的 36 个页面路由，以及直接相关的导航、菜单和表单子状态。跳转入口和共用界面按真实依赖合并验证，不重复重做。

基线：`codex/homepage-design`，HEAD `a981c73c` 加本任务未提交改动。浏览器使用本地生产构建 `http://127.0.0.1:3047`，代理 `https://test.tianshengzhi.com/api/v1`。使用用户主动登录的现有学生测试会话，保留原账户与业务数据。

## 执行方式与验收

- 一个独立审美子代理连续评审各批次；主代理负责采集真实截图、核实意见、最小修复与回归。
- 子代理内置浏览器连接不稳定后，改由主代理统一操作内置浏览器，避免并发控制同一页面；子代理使用真实截图和源码独立判断。
- 静态截图通常启用本标签的减少动态效果，避免入场动画干扰。动效和交互另行检查，不能从静态图推断其通过。
- 至少检查桌面与手机的主要布局，代表性共享组件检查明暗主题。记录真实可见状态，不把仅源码检查或空态当成完整业务状态已验收。
- 不提交表单、验证码、答案，不执行点赞、投币、创建、删除等业务动作。应用既有每日登录奖励可能随已登录访问自动结算，不能宣称所有网络请求均为 GET。
- 截图只保存在当前会话的本地 `aesthetic-review/` 目录。含账户联系方式的截图已在独立复查后移除，只保留脱敏结论和无联系方式的界面证据；报告不记录凭据或完整业务实体 ID。
