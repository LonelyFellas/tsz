# 语音富文本编辑器需求评估

## 背景与目标

管理后台的 V2 单词创编流程已经用 `RichText` 承载语法结构、释义和例句，但当前界面仍是普通 `Input.TextArea`：文本一旦改变，已有标注会被整体清空；“播放 / 获取语音 / 上传语音”也还是 Mock 占位，无法完成真实的语音教学内容制作。

本功能以本地 `laTex` 项目的 `SpeechAnnotationDemo` 为功能参照，在 monorepo 的 `packages/` 下建设独立的语音富文本编辑器包，由智能词库等业务层通过公开 API 调用。管理员应能在一段英语文本上完成重音、停顿、IPA 读音、连读和多色高亮标注，实时查看合成结果，试听语音，并把结构化标注随词条草稿保存。

目标不是照搬参考 Demo 的页面视觉，而是在 admin 的 antd v6 设计体系中做成可嵌入词条创编流程的正式编辑能力。成功标准是：参考 Demo 的核心编辑与试听能力完整可用；标注能安全、无损地落入结构化 wire 数据；含 emoji 或生僻字符时位置不漂移；大量释义/例句同时存在时页面仍可流畅编辑。

## 目标端

- 首期仅 `apps/admin`。
- 接入 V2 单词创编 `/words/:wordId/wizard/meanings`，覆盖：
  - 英语语法结构的各方言文本；
  - 英语释义 / 英语整句释义；
  - 英文例句的当前方言文本。
- 中文释义、汉语译文继续使用普通文本输入；首期不展示英语专用的 IPA、连读和英文 TTS 控件。
- legacy V1 词条编辑器与 `apps/web` 不在首期接入范围，但数据模型与纯渲染逻辑要保留后续复用空间。

## 交付形态与包边界

- 新增独立 workspace 包 `packages/voice-editor`，包名 `@tsz/voice-editor`。
- 编辑器主体、标注命令、TipTap 扩展、V1/V2 转换、只读渲染、SSML 预览、试听状态和 PDF 打印能力由包封装。
- 业务层只负责：选择正在编辑的业务字段、提供 `RichText`、词条读音提示、TTS adapter、保存回调和权限/只读状态。
- 包不能读取词条路由、wizard 状态、admin token、环境变量或 TanStack Query cache，也不能直接调用 `@tsz/api-client`。
- 包的组件 props / 本地状态使用 camelCase；落入 `@tsz/types` 和 API 的 wire 数据继续保持 snake_case。
- 首个调用方是 `apps/admin`，但包公开 API 不出现 `AdminWordV2`、`WordSentenceV2`、`node_id` 等智能词库业务类型。

## 用户与权限

- 使用现有 admin 登录、路由门禁和智能词库权限，不新增一套身份体系。
- 能编辑 V2 词条 meanings 步骤的管理员可以打开编辑器并修改标注。
- 已发布词条的只读预览只能查看标注和播放已有/临时试听音频，不能修改或生成新内容。
- TTS 试听仍受服务端配额、速率限制和供应商可用性约束；前端不能伪造成功。

## 用户故事 / 使用场景

### 1. 从词条字段进入语音编辑

作为词库管理员，我在英语语法结构、英语释义或英文例句字段上点击“语音编辑”，业务页面通过 `@tsz/voice-editor` 打开完整编辑器，我可以在不离开当前词条和当前方言的情况下完成编辑。编辑器清楚标明正在编辑的字段、方言和原文本；取消时不改动词条，应用时才把本次结果写回表单并标记为未保存修改。

### 2. 编辑正文与撤销重做

作为词库管理员，我可以像普通富文本一样输入、删除、选择和粘贴纯文本，并可撤销/重做。编辑器支持多段文本；粘贴外部 HTML 时只保留纯文本和编辑器明确支持的安全标注，不带入任意样式、脚本或未知节点。

### 3. 添加教学标注

选择文本后，我可以：

- 添加或取消强重音；
- 给相邻词或音节添加或取消连读弧线；
- 用黄、绿、粉、蓝、橙五种语义色高亮，重复点击同色可取消；
- 标注或改写 IPA 读音；已有 IPA 优先回填，其次使用当前词条词形/读音数据提供的提示，没有提示时允许手工输入；
- 一次清除选区内的重音、读音、连读和高亮。

光标所在位置可以插入停顿。停顿以不可编辑的行内标记显示，支持 `200ms / 300ms / 500ms / 800ms / 1s` 快捷值、自定义时长、修改和删除。没有选中文本时，依赖选区的按钮禁用，但插入停顿仍可用。

### 4. 配置并试听语音

作为词库管理员，我可以选择发音人、说话风格、整体语速和音高，然后生成试听音频。语音能力以服务端返回的发音人能力目录为准：不支持某种风格或音高时，界面应禁用该选项并解释原因，不能像 Demo 一样静默忽略。

生成期间按钮进入 loading 并防重复提交；成功后自动播放并可重播，显示“新合成 / 缓存命中”等可确认状态；失败时保留全部编辑内容和配置，给出可重试错误。关闭编辑器或生成新音频时停止旧播放并释放临时资源。

### 5. 查看 SSML

编辑器根据正文、标注和语音参数实时生成只读 SSML 预览，供高级排查和与服务端核对。SSML 默认折叠或放在次要面板，不长期挤占正文编辑空间。

前端展示的 SSML 只作预览；真正合成时由后端依据结构化富文本重新校验并生成，后端不直接执行客户端提交的任意 SSML。

### 6. 导出当前标注稿

管理员可以把当前编辑器正文通过浏览器打印导出为 PDF。导出内容保留重音、IPA、连读和高亮的视觉效果，隐藏停顿药丸并让文字自然回流；工具栏、语音设置、SSML 和词条页面其他内容不进入 PDF。

### 7. 保存与恢复

点击“应用”后，正文和标注作为结构化 `RichText` 写回当前 V2 表单；随后仍按现有“保存草稿 / 下一步”流程持久化，不新增绕过 revision/dirty guard 的独立保存通道。保存成功、刷新或重新进入步骤后，标注位置和属性应完整恢复。

从已有 `RichText version: 1` 打开时，编辑器能兼容展示旧的加粗、蓝色和连读点。只有管理员应用了编辑结果才升级为新版格式；取消或只查看不会改写旧数据。

## 功能范围

### 本次包含

- 独立 `@tsz/voice-editor` workspace 包及稳定公开 API。
- 可复用的语音富文本字段、只读渲染器与单实例编辑器抽屉。
- 正文编辑、多段文本、选择状态、撤销和重做。
- 强重音、IPA、停顿、连读、五色高亮、清除标注。
- 发音人、说话风格、语速、音高选择。
- TTS 试听生成、自动播放、重播、缓存/错误状态。
- 实时 SSML 高级预览。
- 当前正文的浏览器打印 / PDF 导出。
- V1 富文本兼容读取、V2 结构化标注持久化。
- 接入 V2 meanings 步骤的英语语法结构、英语释义和英文例句。
- 只读态的标注展示。

### 明确不包含

- 语音转文字、麦克风录音或自动跟读评分。
- 音频文件上传、OSS 永久存储、把本次试听音频写入节点 `audio_url`；这些继续属于后续音频资产模块。
- 多人实时协作、评论和审阅工作流。
- 通用 HTML 富文本能力（标题、表格、图片、链接、任意字体/颜色等）。
- 自动替管理员判断所有单词的 IPA；词条已有读音只能作为提示，管理员对具体语境负责。
- legacy V1 编辑页与学习端展示改造。
- 移动端专门适配；管理后台以桌面端为主，窄屏只要求抽屉全宽可操作。

## 约束与边界

- `@tsz/types` 继续使用 snake_case wire 字段，正文不是 HTML；任何 TipTap JSON 都只能停留在编辑器内部。
- 所有区间和停顿位置均按 Unicode 码点计数，不使用 JavaScript UTF-16 下标。
- 正文最多 5000 码点，标注总数最多 500；输入过程可以就地提示，应用前必须阻止越界数据写回。
- 同类可合并标注应归一化；IPA 标注之间不得重叠，停顿位置必须在 `0..text.length` 的合法码点边界内。
- 停顿自定义值建议限制为 `1–5000ms`，服务端可在对接评审时收紧。
- 复制/粘贴、打印和 SSML 序列化不得形成 XSS 或 SSML 注入。
- 发音人 ID 和能力不能硬编码为 Azure 专用值；前端消费服务端的供应商无关目录。
- TTS 密钥、供应商凭证和缓存路径只存在于服务端，不能下发浏览器。
- 同一词条表单可以有大量 RichText 字段，页面不能为每个字段常驻一个 TipTap 实例。
- admin 禁止引入 tailwind 或 `@tsz/ui`；交互骨架使用 antd v6，编辑区视觉用局部 CSS。
- `@tsz/voice-editor` 不得反向依赖 `apps/*`、`@tsz/api-client` 或具体 data source；网络与业务保存通过显式 adapter/callback 注入。
- 包必须声明清晰的 entry exports，业务层不能深路径 import 包内部文件。
- 包内纯逻辑和 React 组件都属于 `packages/**` 质量门，覆盖率必须达到 100%。

## 验收标准

- [ ] V2 meanings 步骤中的英语语法结构、英语释义和英文例句都能打开同一个语音富文本编辑器；中文字段不会误显示英语语音工具。
- [ ] `apps/admin` 只通过 `@tsz/voice-editor` 的公开 exports 调用编辑器和只读渲染器，不复制 TipTap 扩展或标注逻辑。
- [ ] 包在不传入 TTS adapter 时仍可独立完成正文/标注编辑、SSML 预览与序列化；试听按钮明确禁用。
- [ ] 包源码不 import `apps/*`、`@tsz/api-client`、router、QueryClient 或词条业务 DTO；TTS 与保存均由调用方注入。
- [ ] 打开编辑器时字段、方言、正文和已有标注正确；取消不改变表单，应用后表单变脏并可按现有步骤保存。
- [ ] 选择文本后能切换强重音、连读和五种高亮；同色再次操作能取消。
- [ ] IPA 面板按“已有标注 → 当前词条读音提示 → 空”回填，支持应用、清除和 Escape 取消。
- [ ] 光标处能插入停顿；点击停顿能用快捷值或 `1–5000ms` 自定义值修改，也能删除。
- [ ] 清除标注只影响选区内受支持的标注，不删除正文或选区外标注。
- [ ] 撤销/重做按钮状态准确，常用键盘快捷键保持可用。
- [ ] 发音人目录加载成功时正确展示能力；不支持的风格/参数明确禁用，不静默提交。
- [ ] 生成试听只发起一次请求；成功自动播放且可重播，缓存命中有提示；失败不丢正文、标注和配置。
- [ ] 内容或语音参数变化后，旧音频明确标为已过期，不会被误认为当前版本的试听结果。
- [ ] SSML 随编辑实时变化，正文和属性均经过转义；纯视觉的连读/高亮不进入合成语义。
- [ ] PDF 只包含当前正文，保留重音、IPA、连读和高亮，隐藏停顿与管理界面。
- [ ] 保存、刷新并重新打开后，正文、重音、IPA、停顿、连读和高亮均无损恢复。
- [ ] V1 的 `bold / blue / liaisons` 能兼容显示；取消或只读查看不会把 `version: 1` 改成新版。
- [ ] 含 emoji、组合字符和 IPA 符号的文本经过插入、删除、保存和重载后，标注不越界、不偏移。
- [ ] 5000 码点、500 个标注、非法重叠和非法停顿时长都有明确校验，不能提交坏数据。
- [ ] 打开包含大量释义/例句的词条时只存在一个活动 TipTap 实例；关闭后监听器和音频资源被释放。
- [ ] 已发布只读预览不能修改标注或触发生成；无权限、401/403、限流和 TTS 不可用时沿用统一错误处理并给出可恢复反馈。

## 开放问题（本设计已给默认方案）

1. **接入范围是否确认仅为 admin V2 的英语字段？** 默认是首个业务调用方仅接 admin V2；编辑器本体仍作为独立 `@tsz/voice-editor` 包交付。
2. **试听音频是否要立即成为词条的正式音频？** 默认否；本期只做临时试听和服务端缓存，不写 `audio_url`，避免把音频资产生命周期混进编辑器。
3. **PDF 是否需要整条词义/整页批量导出？** 默认只导出当前编辑字段，与参考 Demo 的“当前讲义正文”能力等价。
4. **TTS 供应商和发音人清单是否固定为参考 Demo 的 Azure 配置？** 默认不固定；由后端返回能力目录，前端不绑定 Azure。
