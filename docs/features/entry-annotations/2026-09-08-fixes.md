# 词条创建与标注修复决策

依据 2026-09-08 本地 dev 联调确认的产品规则。发布与部署证据另见最终交付报告。

## 问题与预期

1. 输入 `center` 后，词典自动补为 `centre / center`；未手动修改却在首次创建时提示匹配结果更新。检测应展示默认将创建的全部词形匹配，首次确认可以直接消费；检测后真实新增匹配、标注或策略变化仍须重新确认。
2. 换账号后他人草稿的角标消失。标注可见范围与管理列表一致，不按创建人隐藏。
3. 创建标注弹窗遗漏他人同原型草稿。弹窗列出完整原型组；普通管理员的他人行只读，超级管理员可修改所有行。
4. 同原型组的非空标注跨账号唯一。只读行仍参与查重，超级管理员也不能重复。沿用数字输入规则，不强制连续编号，不自动分配或改写已有值。
5. 列表标注入口错误依赖已有非空标注。仅当存在重复原型时提供入口，允许补填空标注；普通管理员仅操作自己的，超级管理员可操作任意重复组成员。原型唯一时任何账号都不显示入口。

## 实施取舍

- 复用后端 `annotation_visible` 作为重复原型判定，不新增 wire 字段。显示角标还需要非空值；提供编辑入口不需要已有值。
- 分组范围统一为未归档词条的草稿原型及当前发布原型，包含所有创建人。沿用语言、词条类型、方言和标准化原型的分组键；仅普通变化词形相同不视为同原型。
- 不把权限放宽成普通管理员可修改他人词条。可见性、编辑归属、唯一性分别校验。
- 创建冲突弹窗支持按权限填写整组；列表单条编辑继续使用现有单词条 PATCH，其他成员仅用于比对，不在该入口新增批量编辑协议。
- 不清空归档后留下的标注历史。只剩唯一原型时隐藏角标和入口，重新形成重复组时恢复展示。
- 无数据库迁移、无新增 API 字段。发布先后由最终混合版本验证确认；发布过程中保留真实冲突与权限保护。

## 本地复现证据

- 前端基线 `8c88026`，后端基线 `735c8a0`；后台连接真实本地后端，关闭词库、词性、语音 mock。
- xixi 创建的两条 `center / centre` 草稿标注为 `1`、`2`；普通管理员列表看到词条但不显示角标。
- 普通管理员首次创建未弹标注框，第二次创建才显示其自己的旧词条与新词条；填写 `3`、`4` 后建成。
- 现有代码将他人草稿排除于标注分组和展示；前端入口又要求已有非空角标，解释以上现象。

## 验证原则

测试覆盖首次确认、真实证据变化、跨账号草稿展示、只读行、跨账号重复拒绝、越权拒绝、空标注补填、唯一原型无入口。保留归档恢复、分页和非原型匹配的回归，不以放松令牌验证解决误报。
