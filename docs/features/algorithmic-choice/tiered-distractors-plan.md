# 分层干扰项与严格单选任务方案

状态：2026-10-31 已完成本地实施与验收，现按用户授权进入审查、提交、推送及配套 PR 交付。精确提交、审查和 CI 状态以配套 PR 为准；本次不包含合并或部署。本文延续 [规则单选主记录](README.md)，前后端共用一份方案；主记录中的旧实现与验收不是本方案已完成的证据。

## 1. 目标与已确认边界

用户选择单选任务后，实际题目必须是一个正确答案和三个干扰项。正确答案来自所选词表；干扰项可来自全平台有效发布词库，不限于当前词表。词库少时允许使用语义不相关的其他单词，词库丰富后逐步收紧干扰项质量要求。

答案安全检查从第一天执行，不随词库规模放宽。题型不足时明确提示，不自动转为拼写。保留按需出题、选项快照、刷新恢复、任务内掌握进度和既有成绩规则。

本次不引入 AI、人工题库、审核流程、后台策略配置页面或新的外部词源。自定义词暂不新增自动词义匹配能力：无平台词条身份及可靠语义证据的自定义项，明确列为单选不可用；用户仍可另建拼写任务。

## 2. 现场证据与原因

测试站后端来源为 `97b52b743388f60bd1e5532a34f065c6e95eaedb`。本会话创建的“测试002单选练习”标记为单选，开练首题却为 `verb / 帮助` 的拼写题，正确答案快照为 `help`。刷新保持相同题目，未提交答案。

只读查询发现两个独立限制：

1. `help` 的感叹词义有两条仅含注释、无 `word` 的闽南语翻译记录，派生证据标记 `supported=false`。现有 `Evidence::load` 对全部已知词性/义项检查完整性，因此动词“帮助”在召回前即被拒绝。不能把首个失败原因写成“已经召回但不足三个”。
2. 动词“帮助”的对应义项缺少上位分类、同类词和反义词，反向反义关系也为空。修复解析后，现有强制语义关联规则仍无法形成候选范围。

测试站有效、当前发布、可教学的 A1 / AmE 动词候选有 56 个不同词面；其中 29 个通过现有整词证据完整性检查，27 个未通过，后者中有 2 个动词资料通过但被其他词性资料阻断。这是前置检查统计，不是单选出题率，也不证明新算法已找到三个安全干扰项。该数据仅代表当时测试站样本。

## 4. 出题算法

### 4.1 统一的硬边界

- 使用当前有效发布且可教学、未归档的词条；干扰项不受所选词表成员限制，但不读取其他人的私密自定义词作选项。
- 保持当前英美档位和词性，释义难度不高于学习等级；优先难度接近的词。当前阶段不扩展到更高等级、其他词性或库外单词。
- 排除目标词条、相同/别名拼写、英美拼写变体、已声明同义词；三个干扰项也按词条和可接受拼写交集去重。
- 检查目标及候选的全部已知词性/义项，排除第二答案、中文完整释义重叠、英文等价释义、上下位直接答案等既有风险。不能只检查当前展示义项。
- 缺少可用词义证据、未知结构或截断超限仍拒绝；“没有关联关系”与“无法判断是否有歧义”必须是不同状态。

这些规则排除已知资料表达的冲突，不能证明自然语言不存在任何未收录含义。真实样本需复核答案唯一性，发现错误即修正规则或资料。

### 4.2 优先层与补充层

1. **优先层**：沿用具体共同上位概念、同类/反义关系召回，应用统一硬边界；通用 `entity/thing/person` 等不作相关性依据。
2. **补充层**：优先层凑不齐三个时，从全平台同词性、允许等级和口音的索引分页补充，不要求存在语义关联；仍通过相同安全检查。不得把现有 `quality() == None` 直接解释成安全合格，需先分离义项对应/完整性与关联评分。
3. 优先层合格候选始终排在补充层前，再按难度接近程度及现有稳定次序选满三个；不增加近拼写必须命中的条件。不同层合并后再次去重。
4. 复用索引分页、请求内证据缓存和发布内容缓存。不足三项时继续查找至允许候选穷尽，禁止因首批不足便误报不可用。性能保护若提前终止，应返回明确的计算失败，不能伪装成词库不足。
5. 加入正确答案，沿用开练事务中的随机排序及不透明 ID。答前不返回正确项、解析或内部排名；刷新与幂等重试不重新抽题。

例如 `help` 的补充候选可以检查 `eat/sleep/buy`，但它们只是待验证示例，不是硬编码选项，也未在本方案中认证为最终合格组合。

### 4.3 语义解析修正

先以 `help` 的真实原始结构建立回归样本。对源格式中可识别的纯注释记录显式分类，不将注释拼接成译词，也不把整批 `supported` 强行改为 true。识别标准必须基于实际来源结构，不能把“没有 word”一概视为可忽略。

未知或可能包含未解析词义的结构继续阻断；中文相关词义与全义项冲突信息不得丢弃。修正通过新增迁移更新派生函数并重建受影响证据，不修改已部署的旧迁移，不更改原始词典正文或历史题目。实施时核实重建范围、锁及耗时，验证 down/up 与历史读取限制。

## 5. 严格任务的用户流程

### 创建前

- 选择单选后展示“所选内容、可出单选、暂不可用”的数量，不用混合拼写总数冒充单选数。计数单位为去重后的目标词义/学习单元，与任务实际范围一致。
- 不可用原因至少区分：目标本身不适用、资料不完整/无法对应、安全干扰项不足、自定义来源不支持。逐项展示必须沿用来源权限；只列属于用户所选内容的项，不返回内部词典原文或候选答案解析。
- 部分可用时，显示哪些内容不会纳入，并要求用户确认“仅使用可用内容创建”；零可用时禁止创建。不可用内容不得计入待学、覆盖率、计划天数或完成要求。
- 用户确认部分范围后，创建请求携带范围确认状态并纳入请求哈希、预览指纹。来源、学习设置、策略或候选选择发生变化时要求重新预览，不静默接受扩大后的排除范围。
- 展示文案示例：“4 个目标词义中，3 个可出单选，1 个暂不可用”。如果去重口径有别于词表词条数，分别展示，不混用。

### 开练、重练与后续批次

- 新严格单选任务的题目必须有四个合法选项。任何路径均不得调用拼写兜底，包括 mastery 重练、后续轮次和来源恢复。
- 开练时重检当前来源和策略，按需固定选项。某个已纳入目标失去可用选项时，整次开练原子失败，说明原因并提供重新检查入口；不静默删除目标、消耗当日批次或写入半成品题目。
- 来源重新确认沿用现有权限、预览、确认和幂等协议，但不能自动删除不可用词义；需要缩减范围时通过明确的新范围确认/新任务处理。
- 作答与奖励沿用既有规则。策略层级不写入新的掌握事实，不改变题型成绩隔离，不覆盖原答案或重复奖励。

## 6. 契约、版本与兼容

以下为实施设计字段，不代表当前 API 已支持；最终以同步后的后端 OpenAPI 为准。

- 新客户端显式请求独立于 `practice_mode` 的严格策略，例如 `choice_policy: strict_tiered_v1`。后端将策略持久化到任务；旧任务/缺省策略保留原语义，不能根据 `question_type` 临时推断全部历史任务都严格。
- 扩展预览，返回单选可用数量、不可用原因和权限内的逐项说明；大量明细使用有界分页或受限报告，不无限扩大预览响应。补充层使用量属于质量诊断，不向学生暴露实现术语。
- 策略修订参与预览指纹；实际批次保存算法版本、类别规则版本及每个干扰项的来源层级，作为可复查元数据，不在学生答前响应中返回正确答案信息。
- 复用能力协商，新增严格策略支持标识；新前端连接旧后端时明确告知尚不支持，不能把严格请求降级成旧混合任务。
- 预览响应扩展按能力协商返回，保持旧客户端响应形状。同步 `packages/types`、API client 严格运行时 schema、快照及直接消费者；不能假设新增字段天然兼容。
- 发布前实际验证“旧前端/新后端”和“新前端/旧后端”，再确定顺序。新任务写入后，服务回退须仍能识别其策略；不支持严格策略的旧服务不能接管这类任务。历史已生成选项与判分继续按原快照读取。

涉及后端路径主要为 `src/question_bank/{algorithm,semantics,learning}.rs`、派生证据迁移，以及 `learning_tasks` 的 service/plans/mastery/来源恢复。前端主要为 `LearningPlanCreator.tsx`、`LearningTasks.tsx`、`packages/types` 和 `packages/api-client`。实施时在独立后端任务 worktree 中核对准确文件，不使用落后 main checkout 直接开发。

## 7. 词库成熟后如何退出补充层

### 评估口径

按“学习等级 × 词性 × 英美档位”评估，不按总词量直接切换。每个类别记录目标总数、优先层独立成题数、依赖补充层数、各失败阶段数量和预览/开练耗时。资料不完整的目标不能从分母悄悄排除，也不能把规则检查通过率当作人工确认的答案唯一率。

全平台有效、已发布、可教学的独立词条达到 1 万条时，进行一次专项评估。草稿、归档词及同词条的变形/别名不重复计数；该数字是人工评估节点，不是自动启停开关。本轮不创建监控或承诺未来自动触发。

### 类别切换规则

- 使用统一出题算法；补充层只是一条可退役的召回分支。类别规则存为后端版本化策略，先复用配置/代码评审流程，不新建管理系统。
- 收紧某类前，对其现有有效目标做只读预演，列出失去可用性的目标及原因，并复核真实题目。无新增损失且质量合格的类别可优先关闭补充层；存在损失时先补资料，或明确确认产品可接受的不可用范围。不能用出题率指标压过答案质量。
- 以正常发布切换类别规则，禁止词量在阈值附近变化导致自动来回切换。用户重新预览后才能按变化后的结果创建任务。
- 已保存题目始终使用原快照；类别规则更新影响后续生成。已有任务若在下一批次不满足规则，给出重新检查提示，保留历史和既有进度。
- 退出回执写明类别、证据版本、受影响范围与规则版本。所有受支持类别均退出后，删除补充层实现、专属开关和仅用于补充层的测试；保留统一安全检查、历史元数据读取及选项快照能力。
