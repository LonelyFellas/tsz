# 新版词库复用 V1 拓展词

目标：在新版词义中接入 V1 的派生词、近义词、反义词编辑器，沿用关系分值、搜索、具体义项选择、派生词多义项分组、排序和待关联文本行为。产品依据为用户提供的《智能词库重新设计（第2版）》HTML。

- 已有能力：V1 `V3RelationsGrid`、新版按目标语言/媒介语言筛选的列表、草稿读取与版本保存。
- 前端接缝：为 V1 查询 hooks 增加可选数据源；新版从自身列表/草稿提供候选，不使用 V1 的发布词条 ID。只将当前义项的 relations 通过函数式更新回写，保留其他义项及在途更新。预览使用当前目标方言与媒介语言读取关联展示。
- 后端契约：`NextSense.relations`、`NextSenseView.relations` 复用 `WordRelationWritableV3[]`；`x-tsz-next-relations: v1` 协商能力。未协商的响应隐藏字段，旧客户端按稳定义项 ID 保存时保留原关联。新客户端在能力未确认时拒绝发送关联内容。
- 数据：拓展词随完整草稿版本持久化；relation 节点登记永久 ID。校验类型、分值、重复目标、词条/义项配对、同目标语言/媒介语言及禁止自关联。沿用所有保存和生命周期写入已有的事务 advisory lock，检查当前版本的入站关联，阻止删除被引用义项及归档/删除被引用词条，不额外引入并发锁协议。
- 迁移：仅扩展 nodes 的 kind 约束；down 在存在关系节点或历史扩展快照时拒绝执行，以免损失历史版本。无业务表重建或数据转换。

验收：新版界面操作回写/预览；真实数据库下 PUT → 独立 GET/view；旧客户端隐藏保存保持原值；无权限、异语言目标、无效/重复关联和引用保护；V1 原有搜索及组件回归。前端 API 契约、类型、lint、后台规范与 Rust fmt/clippy 按实际变更验证。
