## 2. 不变量与对象划分

区分三个独立对象：

1. **创编词表**：现有 `wordlists`、`wordlist_items` 和审核流程，仍由作者管理，可以进入回收站、永久删除。
2. **可交付内容**：独立于作者账号和创编行生命周期的公开编排及内容版本，只有公开内容，无私密备注或后台内部信息。
3. **购买资格**：某用户对某词表是否已有成功订单。能读到版本不等于有资格；已有订单仍须检查当前账号资格与内容治理。

必须满足：

- 未购只读取固定前 5 项，无学习权限；有效购买可以查看和学习，无编辑权。
- 作者撤回/删除/注销/停用不删除有效购买的可交付内容；平台治理可以禁止对应内容的读取和学习。
- 本期没有退款撤权或退款后重购状态；作者状态改变不能删除购买事实或其他买方共享的内容版本。
- 订单事实、结算流水不可修改或删除；动态访问状态由账号、内容治理和版本选择共同决定。
- 内容版本不是浏览器缓存。恢复、重登、换设备和作者物理删除后，服务端仍能给出相同的保留内容。
- “永久”不是免除账号与治理校验；所有内容、学习、重试回执均重新授权。

## 4. 版本留存方案

### 4.1 采用不可变编排与按需物化内容

不为每个买方复制整份词表，也不在每次平台词条更新时同步重写所有引用词表。

- 作者成功公开时，在同事务写入 `public_release` 和有序成员，更新阅读资源的当前 release。失败审核不产生可交付版本。
- 词表公开期间，阅读/新出题以当前 release 的编排加平台当前已发布内容解析；正常词条更新无需作者重发。
- 首次成交、已购分页阅读/开轮需要稳定版本，以及撤回/删除/停用时，按选定 release 与 publication 向量物化 `reading_version`；相同内容指纹复用已有版本，publication 内容单独去重。
- 同次物化锁定词表和相关 entry，得到一致成员顺序及 publication 引用。指纹包含 release、publication ID、不可用状态和投影版本；不能用词表 revision 单独判断内容未变。
- 未购预览只解析前 5 项，不下载完整版本给客户端，也不向游客暴露隐藏 entry/publication ID。
- 前端读取按 `reading_version_id` 分页；每页重新鉴权。当前公开内容变化导致分页版本过期时返回明确冲突并重载，不能拼接两个版本。冻结版可保持稳定分页。

版本 ID 本身不授予访问权；用户不可自由枚举历史版本。当前详情只允许当前选定的 live/frozen 版本，既有学习题目按其服务端绑定的版本处理。

### 4.2 撤回、删除与作者账号变化

| 事件                | 同事务要求                                                                              | 对有效买方的结果                                 |
| ------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 主动撤回/进入回收站 | 在清理或改变公开状态前捕获最后实际可见内容并设置 frozen pointer，再更新创编状态         | 查看冻结版、新任务/新轮使用冻结版；原题不改      |
| 永久删除/清空目录   | 已有冻结版则验证完整性；不能在清空成员后再生成                                          | 创编行及恢复入口可删除，阅读资源、版本及订单仍在 |
| 新版公开            | 原子提交新 release 与切回 live 的指针；旧版本仍由已有题目引用                           | 详情和新轮使用新版，不提供历史版本切换           |
| 账号停用            | 账号状态写入路径先保留其已售公开内容；新增购买停止                                      | 已购读保留版，作者编辑不可继续                   |
| 注销到期/物理清理   | 到期逻辑不依赖 worker 速度；物理清理前验证保留资源，且先完成资源锁与留存再关闭钱包/删号 | 已购保留当时版本，不读取注销后发生的普通平台更新 |
| 平台违规下架        | 独立写治理状态，即便创编行已删除仍能命中稳定阅读资源                                    | live/frozen/题目历史均受限；不触发退款           |

不能只修改 `review::withdraw`：目录批量 trash/purge、后台停用、账号最终清理、管理员下架均需接入。当前目录 purge 会删 `wordlist_items`，账号删除会触发原有级联；这些路径必须在新保留边界下重新验证。

**注销 72 小时边界**：不能在申请时提前冻结内容，也不能延迟到 worker 执行时才选择“当时版本”。实施必须记录平台 publication 的正式激活序列和逻辑生效时间，按 `effective_at` 取最后已生效内容；首次到期访问/清理可幂等物化。平台发布与到期留存必须共享 entry 的一致性锁和明确的激活线性化点，等待锁后重新检查时间。不得只用既有 publication 的插入时间倒查。该时序是实施验证重点，未验证之前不得宣称注销边界已完成。

### 4.3 保留内容、资源与治理

- 学习所需的形式/释义结构保留完整公开语义数据，统一送入既有投影和题目生成器；不能只保留已经按某个用户等级筛选后的页面 HTML。
- 内部判题数据不直接返回 Web。保留内容使用明确白名单 DTO，拒绝草稿、管理员 annotation、私密备注或审核信息。
- 治理状态与作者公开状态独立；作者恢复、重新公开或修改价格不能清除平台封禁，解除治理必须走对应管理权限与审计，并递增治理版本。
- 当前 entry/archive 与词表治理状态仍作为动态否决条件；正常更新不修改冻结版，治理撤销也不能被旧版本绕过。保留已删除业务行的最小治理墓碑，不能把“源行不存在”误当成无治理限制。
- 音频/文件若是已承诺阅读功能的必要内容，保留其资源引用并接入现有对象清理的引用判断；不存过期签名 URL，不复制作者头像/认证文件。对象撤销时遵守治理限制。
- 付款流程不做 OSS 网络复制；必须先有可持久交付的内容和资源保留依据，否则拒绝成交。数据库快照不能掩盖文件会被后台立即清理的缺口。
- 活跃资格和已有合法学习引用仍存在时不得垃圾回收版本。首期不实现自动历史版本回收任务，不等于对所有原始业务数据永久留存。

## 5. 统一权限判定

在 wordlists 业务内提供事务级 `resolve_reading_access` 与 `resolve_learning_source`，供公开详情、收藏、购买记录、学习调用；不改成跨业务通用权限引擎。

判定顺序：调用者账号/会话资格 → 平台治理 → 当前有效购买或作者/平台例外 → live/frozen 内容选择 → 条目治理/资源可用性 → 场景能力。

| 身份/状态    | 详情                             | 新学习                              | 既有题目                                     | 编辑              |
| ------------ | -------------------------------- | ----------------------------------- | -------------------------------------------- | ----------------- |
| 游客或未购   | 当前公开的前 5 项；不可读 frozen | 禁止                                | 未购来源内容隐藏，个人统计保留               | 禁止              |
| 有效购买     | 当前完整 live 或合法 frozen      | 可用所选版本，仍需学生资格/学习设置 | 当前资格有效且题目绑定合法版本、治理允许即可 | 禁止              |
| 作者         | 本人当前创编内容                 | 沿用本人学习资格                    | 沿用本人规则                                 | 现有作者/状态守卫 |
| 平台词表读者 | 免费完整查看                     | 沿用现有学习规则                    | 沿用现有规则                                 | 不因阅读开放      |

- 平台管理员读取审核资料须走后台权限，不凭 C 端购买绕过；作者判定不能用 `can_read_full` 替代。
- 失效/伪造 Authorization 返回 401，不能静默变为游客。账号有效但缺业务资格按原门禁处理。
- 私密且未购的对象返回 404，不能泄漏标题；自己已购但治理限制的资源可给最小状态及受限说明，不返回被禁止的内容。
- 冻结版显示的标题/数量来自版本。收藏目录当前将不可公开对象投影成 `wordlist=null`，需新增已购阅读状态查询供 UI 解析，不能因此绕过目录所有权或强行公开所有收藏元数据。
- 个性化内容使用 `Cache-Control: private, no-store`，保留并追加 `Vary: Authorization` 与既有 reading headers；禁止共享 CDN 缓存。API 不接受客户端声称的 purchased/owner 状态。

## 6. 学习来源、轮次与购买资格

### 6.1 新任务和新轮

学习任务仍保存词表 ID；开轮在一个事务内为每个来源解析资格和版本。有效购买选 live 最新或 frozen；未购明确拒绝，不能自动剔除来源凑题量。

新增 `learning_run_sources`，保存 `(run_id,wordlist_id)` 对应的 `reading_version_id`、`purchase_order_id` nullable、授权类型（作者/平台/购买）及必要资格版本。题目绑定来源行与原有 publication/entry/unit_key、prompt/answer 快照。服务端生成关系，不接受客户端提交的任意版本或订单。

正常作者更新/移除条目不使已经合法生成的题目失效；题目依据原快照判题。版本绑定用于证明当时来源合法，**不代替当前资格与治理检查**。

已有 `SourceAccess::available` 的 public_generation、membership、archive 检查不能整体删除：

- 购买路径使用已绑定版本成员关系，忽略作者后续 public/member 代际变化；保留当前治理及原有 archive-generation 安全边界。
- 作者/平台路径保持原有规则，避免顺手改变免费来源行为。
- 新轮仍检查当前可出题数量；不改变日界线、任务到期、首答、完成事实及奖励规则。

### 6.2 各入口重新授权

| 入口                      | 要求                                                                          |
| ------------------------- | ----------------------------------------------------------------------------- |
| 任务 preview/create       | 未购不能取题或创建；购买前可用性走独立聚合端点，只返回数量/原因，无词面题面   |
| start/recover             | 解析新轮版本或既有来源绑定；不能因作者撤回/删除直接 invalidated               |
| questions/get_run/history | 返回本人统计；题面、已提交答案及 accepted_answers 按当前资格/治理决定是否可见 |
| answer                    | 判题写入前重查购买资格、账号和治理；受限时不接受新作答                        |
| 原答案幂等重放            | 可返回已存在的提交事实，但内容投影重新鉴权；不能原样返回曾缓存的完整答案回执  |
| 多来源失权                | 不删除题目缩减目标；停止失权来源继续作答，轮次不可伪造完成，统计保留          |

购买资格成立后不会因本期退款流程被撤销，因为本期不建设该流程。作答与账号停用、平台治理仍需以互斥锁和事务内重查保证一致性；已合法发放的学习奖励不因后来来源受限而倒扣。

权限阻塞不新增一个与旧严格枚举不兼容的 `LearningRunState` 值。增加独立 source-access 结果描述 `purchase_required/account_unavailable/governance_blocked`；未过期原轮可暂时阻塞，不在 GET 中因仅未购就永久写成 invalidated。到期、取消和治理等真正失效继续按现有状态机处理。

### 6.3 历史任务迁移

旧任务不赠送购买资格。旧题已包含 prompt/answer/publication 等证据，不能仅因缺少新 binding 就公开：

- 无有效购买时隐藏内容，保留统计。来源不可售时不给无效购买按钮。
- 有有效购买且可以从原发布/成员证据证明来源时，建立旧轮来源绑定；不能用“当前词表包含同一个词”伪造历史来源。
- 缺乏足够证据时保留历史统计，不补造版本；明确来源不可恢复并引导在合法来源上新开轮。
- 原轮已被旧系统永久标为 invalidated/expired 时不自动复活；新资格允许新轮，不能修改历史完成结果。

## 7. 购买事务与请求重放

输入：`idempotency_key`、`expected_price`、`expected_pricing_revision`。价格按服务端确认值成交，买卖方从身份与资源派生。

1. 认证买方，按原请求键查询已提交结果。同键异载荷返回 409；同键同载荷返回原订单并重新投影当前访问状态，不重新扣款。已成交结果查询不能要求作者仍活跃或词表仍公开。
2. 新请求按稳定顺序锁相关现存账号，再取得 `(buyer_id,wordlist_id)` 事务 advisory 锁，查是否已有订单；不同键也只返回同一原订单，禁止再次收费。
3. 尚无订单时锁资源与价格，确认双方账号/钱包可交易、词表当前公开可售、价格为 1–100 且报价版本一致、全表并非不可用。
4. 同事务准备可交付版本，调用一次 `transfer_in` 全额买方→作者，写不可变订单，提交。失败回滚所有变动，不能扣款后再异步创建资格。
5. 数据库的买方/词表唯一约束是最终防线。结果未知时按原请求键查询或重试，不换键猜结果；原订单存在时任何请求都不能产生第二笔成交。

多个请求键对应同一原订单时，可持久化轻量请求结果映射以保持请求摘要校验一致；本期没有退款、资格清除和重新购买，同一买方/词表的成功订单始终不被替换。请求键与订单/词表绑定，不能通过修改请求路径复用另一词表的成功结果。

## 8. 不退款与交易故障边界

- 本期不创建退款/平台补偿表、预算、权限或 API，不提供 Web 退款申请和 Admin 退款审批/执行入口；不保留“前端隐藏、后端仍可调用”的退款路径。
- 不调用 credit_in 或人工入账冲正退还购买款，不改变现有通用币账户功能。
- 购买失败整体事务回滚；扣款和资格不一致属于必须排查的系统故障，不是不退款规则允许的正常状态。依据账本与订单事实修复交付，不新建隐式退款工具。
- 成交前校验内容可交付，确认页展示不退款说明和学习条件；结果未知时仅查询/重试，不显示虚假成功或引导再次付费。
- 账号暂停/关闭限制新的支付；作者停止使用账号不影响既有买方查询订单、读取保留版和学习。平台治理仍可禁止内容，不触发本期自动退款或补偿。

## 9. 并发与锁顺序

必须与现有 coins“每事务至多一次普通账本操作”、learning 的账号→任务锁序、directory 的目录 advisory lock 兼容。不能只在新函数内部排好锁，忽略外层已经拿到的锁。

统一偏序：

1. 身份域和 ID 排序的相关账号行（现存行），包括学习者/买方、实际收付款作者及操作管理员；认证只读不代替事务锁。
2. 管理权限、相关账号注销请求；目录操作沿用其专用 advisory lock。
3. 新购买使用买方/词表事务 advisory key，按词表 ID 排序；已购读取直接核实不可变订单，不为不存在的退款路径引入资格写锁。
4. 任务→轮次→问题；只拿本操作需要的锁，购买不扫描全量历史轮次。
5. 稳定阅读资源→创编词表→entry/治理行，均按 ID 顺序；追加不可变版本。
6. 账本请求/业务去重锁→wallet ID 排序的钱包锁；最后写账、业务事实及审计。

关键要求：资源/entry 治理读取持有共享锁，治理写入使用互斥写锁；学习等待锁后重读账号与治理状态，持锁至提交。不能仅描述锁顺序而不说明互斥关系；不得为了获取锁改变钱包状态。

作者注销清理当前先关闭钱包再删号，新增留存必须移到关闭钱包之前，避免拿着 wallet 锁倒过来锁词表。字典发布、归档、管理员停用及目录批量删除的外层锁序需逐一验证；不允许在已锁 entry 的事务里反向锁整批作者/词表。

逻辑注销到期需 as-of 激活事件方案，不能让平台 entry 发布事务反向遍历并锁所有引用作者词表。实现阶段以等待锁跨到期、交叉购买/治理、作者互买和批量清理测试验证死锁及错误投影。

## 10. API 与 wire 契约草案

路径均以 `/api/v1` 为前缀，名称在实施导出 OpenAPI 前收口。金额是字符串、字段 snake_case，业务 ID 使用 UUID，版本字段不混用价格 revision、资源访问 revision 和内容版本。

| Method / Path                                 | 用途与主要返回                                                                                                                    |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| GET `/wordlists/{id}/reading`                 | 新阅读入口：最小可见元数据、`access`、选定版本、live/frozen 状态；已购可在创编行删除后读取；未购私密返回 404                      |
| GET `/wordlists/{id}/reading/items`           | `reading_version_id`、page、q、view、sort；仅授权版本内容，未购前 5 项；不允许任意历史版本                                        |
| GET `/wordlists/{id}/access`                  | 资格摘要：`can_read_full`、`can_learn`、`can_edit`、`purchase_order_id`（仅本人）、`access_revision`、price、报价版本、不可售原因 |
| GET/PUT `/me/wordlists/{id}/pricing`          | 作者定价；PUT 携带预期价格版本，1–100；作者已删除不能改价                                                                         |
| GET `/wordlists/{id}/learning-availability`   | 购买前仅聚合数量/原因，受可见性和输入限制；未知学习条件明确说明，无题面/词面/ID                                                   |
| POST `/wordlists/{id}/purchase`               | 幂等请求键＋确认报价；返回原订单及当前访问状态，成功订单不因治理受限被再次收费                                                    |
| GET `/me/wordlist-purchases` 与 `/{order_id}` | 本人订单/当前访问状态及重新打开资源信息，分页；删除作者不影响查询                                                                 |
| GET `/me/learning-tasks/{id}/source-access`   | 现有任务的来源阻塞摘要；不修改旧 `LearningRunState` 枚举来表达临时权限阻塞                                                        |

旧 `/wordlists/{id}/items` 同样必须执行服务端预览/购买校验，不能成为绕过路径。现有 public metadata 仍只用于公共发现；新 Web 的已购读取改走 reading envelope，不要求把旧 `Wordlist` strict DTO 扩成混合权限对象。

主要状态：400 参数/金额不合法；401 会话无效；403 无业务/管理权限；404 对象不存在或不可探测；409 报价、版本、钱包、来源或执行状态冲突。使用明确 Problem Details code（拟 `wordlist_purchase_required`、`wordlist_reading_changed`），详情中不泄漏隐藏词条和内部审核证据。

旧 learning response 保持形状，失权题目已有的 `content_available=false`、prompt/feedback null 用于安全投影；新 source-access 端点用于可操作提示。新 runtime roots 必须从 Rust DTO 正式导出，不手工篡改生成 schema；本轮不执行导出。

## 11. 前端状态和交互

### Web

- `WordListDetail` 区分作者创编与阅读资源，不再以公共 metadata 成功作为所有已购详情的前置条件。共用公开/收藏阅读逻辑，作者编辑仍走原 mine 接口。
- query keys 将 access、reading、items、orders、learning 的个性化数据全部置于用户维度，内容 key 包含 reading version；账号切换取消请求并清除旧缓存，不仅清 metadata。
- 访问状态未确认时不渲染已有完整缓存；账号变化或得知治理限制时取消在途内容请求、清空对应阅读/学习缓存，再拉访问状态。请求回包校验当前账号及访问 epoch，旧响应不能把完整内容塞回来。
- 购买成功刷新 access/orders/wallet，按新版本加载内容；请求超时保留请求键并查询订单。成功购买回执不绕过治理校验，不乐观解锁受限内容。
- 不展示退款按钮或售后进度。返回前台/窗口聚焦时重读访问状态，后端每次读取仍是最终防线，不能宣称撤回已被用户读到的文本。
- 收藏工作区对于已购但当前公开 metadata 不存在的引用，按阅读状态打开 frozen；未购仍不可用。购买记录有独立入口，取消收藏不丢失入口。
- 学习来源选择区分未购、已购可用、已购条件不足、平台免费、保留版和治理阻塞。阻塞时不丢本人统计，不出现无效购买按钮。
- 作者创建/改价限制 1–100，说明已售词表删除后仍保留交付内容；购买确认明确说明本期不支持退款。

### Admin

本期不增加购买退款页面、审批/执行按钮、平台补偿预算配置或相关新权限。现有内容治理仍须覆盖独立保留资源，不能因作者删除导致管理员无法限制违规内容；如需调整页面继续使用现有 antd v6 与权限门禁。

## 14. 与初稿的差异及本轮完成情况

此前初稿只有 price、简单 purchases、公开接口预览和局部页面。它缺少独立保留资源、版本、学习全链路、请求结果查询、1–100 价格约束及账号清理适配。取消退款后，`UNIQUE(payer_user_id,wordlist_id)` 可作为一次购买的最终约束；要求原作者必须活跃才能读取已购内容的方式仍不可照搬。

此前审查中，退款与作答互斥、退款再购旧轮恢复的问题因范围取消不再适用。不同请求键仍须保证只成交一次并返回稳定结果。以下版本/学习问题仍需设计收口，不因取消退款自动解决：

- 注销到期时的实际提交可见边界：激活时间戳不等于提交可见时间，跨到期发布事务的线性化与留存选择仍须明确，不能仅用事件时间倒查。
- 已处于 frozen 的资源后续删除/停用/注销不能覆盖冻结指针；需补齐仅 live→frozen 捕获、重新公开才转 live 的完整状态转换规则。
- 多词表包含同一 entry 的不同保留版本时，来源内容必须按版本与 entry 共同索引，不能复用只按 entry_id 的 map 导致串版；跨版本题目去重和来源选择仍需明确。

本轮仅按“不退款”方向同步需求及技术设计，移除退款、平台兜底、预算、审核入口与退款撤权相关模型、接口和验证。仅检查文档，不修改业务代码、迁移、测试或生成契约，不启动服务；以上保留问题尚未被运行时验证。
