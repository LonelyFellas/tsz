# 细分词性对所有基本词性开放

2026-09-10 定稿。推翻 `pos-catalog-prototype-alignment`（2026-09-06）里「细分词性只能挂在
五个基础词性下」这条口径。

## 背景

原口径把 `noun` / `verb` / `pronoun` / `adjective` / `adverb` 五个编码写死在后端
`catalog::rules`，只有它们的 `sub_parts_extensible` 为 true。当初的动因是本地库出现过
「非基础词性挂了细分词性、词条又引用了它」的脏数据，那次迁移一并删掉了介词、冠词、限定词、
连词、数词、感叹词六个种子及其细分词性。

实际使用中这条规则挡住的只有**管理员自建的基本词性**：自建词性的 `code` 由英文全称派生，
永远不可能落进那个硬编码集合，词性配置页对它显示「不可扩展」。

## 决策

1. **扩展权限全放开**。任意基本词性（含自建）都可以挂细分词性，`sub_parts_extensible` 恒为 true。
2. **释义必填口径不变**。仍然只有那五个编码下的释义必须选中细分词性，其余词性选填。
   这一条单独用新字段 `sub_pos_required` 下发，不再复用 `sub_parts_extensible`。
3. **六个被删的种子不种回来**。需要哪个就用「新增基本词性」自建，放开后建完即可配细分词性。

## 为什么必须拆成两个字段

放开前，「能不能挂细分词性」和「释义要不要必填细分词性」共用同一个判定。若把它一起放开，
新建的词性名下一个细分词性都没有，它下面的词条会永远拿到 `sub_pos_required`，
**词义步完成与发布被永久拦下**（草稿保存不受影响，只有点「完成」和「发布」才暴露）。
所以后端保留固定编码集合，只让它服务于必填口径，并改名为 `requires_sub_pos`。

前端不复制这份编码集合，只读 `sub_pos_required`。字段可选，缺省按 true 兜底，
因此前端先部署或后端先部署都不会坏。

## 放开后新出现的行为

- 自建词性一旦挂上细分词性就删不掉，必须先逐条删掉细分词性（复用既有的
  `part_of_speech_has_sub_parts` 提示）。
- 新建基本词性后一律跳转到细分词性 Tab（原先只有基础词性才跳）。
- 词性配置页「全部」视图按父级逐个拉取细分词性，父级数量随管理员自建增长，请求数跟着涨。
  当前数量下可接受，若自建词性变多需要改成按需加载或服务端分页。

## 不在本次范围

- 例句自动关联的 `associable_pos`（`noun|verb|adjective|adverb`）是另一份白名单，与本次无关，保持原样。
- 旧版建词向导对 `sub_pos` 是无条件必填，与 V3 的口径本来就不一致，本次不动。

## 词形变化按基本词性归属（同批，2026-09-10）

产品口径：细分词性与词形变化都是基本词性下属的类型，两者都在词性下配置。所以词形变化从
2026-09-09 建立的全局目录改为一对多归属，配置页加「所属基本词性」选择栏。

- **原形是唯一的全局项**。它是词形组的技术不变量，编码恒为 `base`，每个词性的词条都引用它，
  不能归属任何一个词性。数据库用 CHECK 约束保证只有原形没有归属。
- **展示字段的唯一性收敛到同一词性内**。否则副词建不了「比较级」，形容词已经占了这个名字。
  编码仍全局唯一（词条按编码引用），新建时由「父词性编码前 8 字 + 英文全称」派生。
- **现有八条按语言学分配**：动词拿四个时态，名词拿复数，形容词拿比较级与最高级。
  副词、代词分配后名下为空，需要哪个自己新建。
- **词条侧不加硬校验**。收窄的只有候选清单，已经用了别的词性词形的存量词条照常保存与发布，
  不会出现「事后收窄导致存量集体失效」。
- **删除基本词性前要先清空它名下的词形变化**，返回 409 `part_of_speech_has_form_types`，
  与细分词性的既有行为对称。
