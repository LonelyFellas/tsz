# 第二批：语言目录与账号偏好兼容契约

状态：本次定稿，作为第二批实现与验收依据；尚未实现接口、wire 类型或迁移，不是当前已导出的 OpenAPI。唯一主记录为[国际化任务](README.md)。

## 1. 范围与不变量

- `InterfaceLocaleV1` 仅接受 `zh-Hans | zh-Hant | en-GB | en-US`，wire 使用 snake_case。
- 支持资源与开放能力分开。第二批初始只开放 `zh-Hans`；Admin/Web 各自在后续完成的批次开放其他语言，不把少量公共资源当成全站翻译完成。
- 界面偏好独立于 `LearningSettings`、管理员 `dialect`、词条语言和语音 locale。不扩展 `PUT /me/learning-settings` 或旧 V3 内容模型。
- API 写入只接受上述精确标签，不把 `zh-CN`、`en`、大小写别名或任意 BCP 47 标签猜测转换后保存。界面匹配方法不能用于绕过写入校验。
- 未设置用 `null` 表示，与用户明确选择简体中文有区别。回退显示不自动写回账号。

## 2. 公共能力目录

`GET /api/v1/i18n/capabilities?surface=web|admin`，无需登录，`surface` 必填。缺失、重复或非法值返回 400 `invalid_query`。

```json
{
  "schema_version": 1,
  "preference_version": 1,
  "default_locale": "zh-Hans",
  "supported_locales": ["zh-Hans"]
}
```

- `schema_version` 和 `preference_version` 固定为整数 `1`；后者声明本文相应身份的偏好读取与写入契约已经可用。
- `supported_locales` 是该 surface 已开放的非空、去重数组；`default_locale` 必须在其中。服务端配置非法时启动失败，不静默开放其他语言。
- 目录不接受 `Accept-Language` 来改变内容，不携带账号、授权或供应商信息；返回 `Cache-Control: no-store`，避免停用语言后沿用缓存能力。后续若引入缓存须另做失效设计。
- 新客户端只使用服务端目录与自身内置资源的交集。V1 未知版本、非法枚举、空交集或默认语言不匹配时关闭新增设置与写入，不猜测后端能力。
- 对旧 API 的明确 404/405视为未提供能力，继续原中文路径、不发偏好写入。网络错误或 5xx 是能力暂不可确认，不能伪报保存成功；已有页面与鉴权继续工作，设置入口可重试。
- 第一批不调用此端点、不发送新协议头。第二批目录通过也不代表第五批后端错误本地化已可用。

## 3. Web 本人偏好

新增 `GET /api/v1/me/preferences` 与 `PATCH /api/v1/me/preferences`。保持现有 `/me`、登录、刷新和学习设置响应形状不变。

读取与更新成功均返回 200：

```json
{
  "preferences": {
    "interface_locale": null
  }
}
```

PATCH 请求：

```json
{ "interface_locale": "en-GB" }
```

- `interface_locale` 必填，可为 `InterfaceLocaleV1` 或 `null`；`null` 仅清除本人显式偏好。
- 非空语言必须属于当前 Web 开放目录。语法正确但未开放返回 422 `unsupported_language`，数据不变；存储过的语言后来被停用时，GET 仍返回原值，由前端按目录回退，不自动清除。
- `{}`、未知字段、非字符串/非 null、非精确标签返回 422 `invalid_request_body`。JSON 语法错误沿用 400 `invalid_json`。
- 目标账号只取认证 subject，不接受用户 ID。要求有效、未禁用的 Web 身份与当前 security_version；不要求学生角色、完成 onboarding 或绑定手机号，教师及尚未完成引导的账号也能设置界面语言。
- 本人响应 `Cache-Control: no-store`。无效会话沿用 401；禁用/撤销会话遵循现有 Web 会话语义，不新增权限豁免。

## 4. Admin 本人偏好

复用 `GET /api/v1/admin/profile` 与 `PATCH /api/v1/admin/profile/preferences`，不修改独立后台身份体系及现有 `disabled / must_change_password` 门禁。

候选后端 profile 的 `preferences` 和 PATCH 成功响应统一为：

```json
{
  "preferences": {
    "dialect": "uk",
    "interface_locale": null
  }
}
```

上例仅展示 profile 的偏好片段；其他身份、权限、版本字段保持不变。PATCH 返回完整偏好对象，profile 仍含原全部字段。

PATCH 请求字段：

| 字段               | 是否必须 | 可接受值                    | 语义                              |
| ------------------ | -------- | --------------------------- | --------------------------------- |
| `dialect`          | 否       | `uk`、`us`，不接受 null     | 仅更新英语方言偏好                |
| `interface_locale` | 否       | `InterfaceLocaleV1` 或 null | 仅更新界面偏好，null 清除显式选择 |

- 至少出现一个字段；空对象、未知字段、错误类型、非法枚举返回 422 `invalid_request_body`。
- 非空界面语言不在 Admin 开放目录时返回 422 `unsupported_language`。
- 一个请求包含两字段时，先完成全部校验，再事务性更新；任一无效则全部不变。
- 服务端必须区分缺字段和显式 null。只更新实际出现的列，不能先读旧整行、修改后全量覆盖。
- 旧请求 `{ "dialect": "us" }` 继续返回 200，只改方言，保留界面偏好；新请求 `{ "interface_locale": "en-GB" }` 不读取客户端旧方言、不覆盖服务端方言。
- 当前 `decodeAdminProfile` 校验授权字段但不拒绝新增偏好字段，旧前端能忽略 `interface_locale`。已用当前请求层测试验证接受该新增字段且旧方言请求仍只发送 `dialect`；这不证明候选后端的持久化行为。第二批仍须保留实际混合版本测试，不能推广为所有响应新增字段均兼容。
- 新前端读取旧 profile 缺少 `interface_locale` 时，按无已保存界面偏好处理；不得因此拒绝或放宽原有权限校验。

## 5. 状态一致性与恢复

- 账号偏好是服务端事实；本机缓存按 `surface + account_id + 缓存版本` 隔离。未登录访客设置使用独立键，不能把上一账号的选择当作下一账号偏好。
- 第三、四批语言选择顺序：已启用的账号偏好 → 当前身份的本机选择/缓存 → 浏览器语言候选 → 服务端默认语言；每一候选先匹配再检查开放目录。未设置和被停用的账号偏好继续后续候选，不把已停用值写回服务端。
- 语言写入只在目录声明 `preference_version: 1` 后执行。保存成功后才提交账号偏好状态；失败保留原值，不宣称已同步。结果未知时回读确认，允许同值重试。
- 同一字段的保存请求串行；不同字段可并发。前端只把本次成功字段的服务端返回值合并进当前身份，不能用迟到的完整 preferences 响应覆盖其他字段的新值。
- 读取和写入都捕获账号及会话 generation。账号切换、退出或会话重建后丢弃旧回调；初始回读不得覆盖已经完成的新保存，也不得用旧 profile 恢复已撤销授权。
- 跨设备同一字段以服务端提交顺序为准，重新读取可见最终值；不增加全量偏好覆盖或客户端时间戳排序。
- 第四批再接入 Web 首屏 cookie；它仅是显示提示，不是授权事实。服务端与水合第一次渲染使用同一已验证输入，账号偏好加载后再协调更新。第二批不改变路由和 SSR 缓存模式。

## 6. 错误与后续本地化边界

第二批新增错误沿用当前 Problem Details 的 `type/title/status/detail/code/field` 等既有结构，不增加 `message_key`、任意 `params` 或新枚举来绕过严格 runtime schema。前端依据稳定 code 提示；非法结构写入定位到相应字段。

第二批不改变现有错误 title/detail/message 的语言，不自动添加 `Accept-Language` 或新的本地化协议头。

第五批后端本地化必须由明确的客户端能力标记与语言协商共同启用；仅 `Accept-Language` 不够，因为旧浏览器也会发送。无能力标记的旧客户端继续原响应。正式头名、适用端点与 `Vary` 在第五批契约中确定，不借本次偏好能力推断；稳定 code、字段定位、枚举和业务数据不随语言变化。

## 7. 迁移、发布与回退

- users/admins 分别新增可空的 `interface_locale` 列及四标签约束；初始 null，不全量回填，不更改现有 `dialect_preference` 默认值。
- up/down 成对，隔离 PostgreSQL 验证约束、本人写入、并发不同字段、失败原子性及回退。已有非 null 偏好时 down 应拒绝丢弃数据；常规应用回退保留新增列。
- 实现后通过 Rust 原生导出 OpenAPI，并按[契约同步技能](../../../.agents/skills/contract-sync/SKILL.md)更新前端快照、snake_case 类型与校验器；本批不提前手改生成文件或发布未来类型。
- 推荐先部署兼容后端（两个 surface 仍只开放中文），再部署前端偏好消费者。第三、四批分别完成对应端验收后，才扩大该 surface 开放目录。
- 候选前端遇到旧 API 关闭新增保存，不阻断登录和旧学习链路；旧前端遇到新 API 保持原路径。应用回退不需要删除新偏好，重新升级后仍能读取。
- 若第三、四批启用非中文，必须具备运行时目录收缩后的重新校验与回退路径；关闭入口本身不代表已恢复当前页面。不得把构建时环境变量声称为即时开关。
