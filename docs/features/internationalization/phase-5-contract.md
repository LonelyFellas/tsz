# 第五批：后端本地化输出

唯一主记录为 [README](README.md)。基线：前端 `d8878bd9`（包含已合入 #704），后端 `617c11d9`。

## 协商与回退

- `/api/v1/` 请求使用 `X-TSZ-Localization: v1` 和 `Accept-Language` 共同启用；没有标记、未知版本或重复标记保持原响应。只发送浏览器默认语言不启用。能力目录本身不参与协商。
- 新客户端发送偏好控制器已经核实的当前界面语言；账号偏好、同身份缓存、浏览器语言、目录默认值的既有优先级不变。目录未知、读取失败或身份已变化时不发送本地化标记；后端不为翻译读取账号或增加 SELECT。
- 后端按 URL 所属 surface 选择目录（`/api/v1/admin` 为 Admin，其余为 Web），不信任客户端指定 surface。支持 HTTP 语言列表和权重；匹配规则沿用四语基础：显式中文文字优先，TW/HK/MO 匹配繁体，其余中文匹配简体；US 英语匹配美式，其余英语匹配英式。非法、缺失、不支持或已关闭候选回退该 surface 默认语言；不返回 406，不修改保存的偏好。
- 协商作用域限本次异步请求，覆盖鉴权、权限与提取器失败；不传递给后台任务，不改变审计/系统日志。健康检查与原文业务正文不翻译。
- 本地化 Problem Details 和通知使用 `Cache-Control: private, no-store`；`Vary` 包含 `X-TSZ-Localization, Accept-Language`，旧响应也声明变体。只有实际渲染了本地化输出才发送 `Content-Language`。目录继续 `no-store`，不新增缓存。

## 输出不变量

- Problem Details 的 HTTP 状态、`type`、`code`、`field`、字段路径、节点 ID、`meta`、重试头和可重试语义不变。不新增问题字段；只翻译登记的固定标题与安全说明。未登记的领域和复杂字段校验说明、用户/供应商原文不按相似文字或关键词猜测翻译，内部错误仍只输出既有脱敏说明。
- 通知仍存结构化 `kind`、关联 ID、金额与原始原因；读取时渲染当前语言，不持久化译文、不回填旧记录。显式协商时可附加可选 `localized`（`locale/title/body`）；未协商完全省略。未知 kind 不猜模板。用户名称、词表名、审核/删除原因、精确金额保持原值。
- 模板范围是现有六种站内系统通知及固定错误说明。当前 OTP sender 只有测试实现，没有可交付的邮件/短信模板或异步投递正文；不新增发送器、不真实发送第三方通知。法律同意文本及已冻结版本不翻译或重写。
- 前端通知按语言隔离查询缓存，切换时不展示旧语言服务器模板；旧 API 缺少 `localized` 时继续第四批模板。服务端错误只显示，不拿译文分类；遗留按错误文案判定的分支改用稳定 code/field。

## 验证与交付

验证四语资源非空与参数、并发请求隔离、旧客户端/无标记/非法协商/目录关闭回退、鉴权前/权限/校验/冲突的稳定结构和重试头、内部诊断隔离，以及通知旧记录、原文、标已读与重新 GET。真实生产预览使用本批后端新构建及私有 PG/Redis，无 mock、真实第三方或 OSS。

两仓无本批新增迁移。旧前端不传标记时，新 API 保持旧 JSON；新前端访问旧 API 时头被忽略、通知使用已有本地模板。已验证的应用回退兼容性仍成立，此前第二批迁移的回退限制继续有效。

正常发布顺序为候选后端 → 前端。前端原生 `deploy/check-api-contract.mjs` 从已部署 API 的清单取精确 SHA，按其 OpenAPI 生成并比较候选前端实际消费的契约；运行时回退兼容不能替代该门禁。先通过后端原生控制器部署并验收包含本批及第二批契约的候选 API，准备认识第二批迁移的兼容回退版本，再让前端原生契约门通过并发布。不放宽 schema 比较、不跳过新增 root，也不以同时发布代替顺序验证。
