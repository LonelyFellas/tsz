# 公开词表互动通知

目标：公开个人词表收到点赞、投币时，作者在现有站内通知与浏览器标签页看到未读提醒。不补发历史事件，不通知平台词表管理员，不扩展收藏通知。

行为与验收：

- 点赞从未点赞变为已点赞时，在同一事务新增 `wordlist_liked`；并发/重复设置不重复通知，取消不通知，再次点赞产生新事件。
- 每笔成功投币在转账事务新增 `wordlist_tipped`，数量使用整数字符串；重试、失败、自投均不新增通知。通知写入失败时业务也回滚。
- 复用本人通知分页、全局未读数与幂等标已读。其他账号不能查看或修改作者通知。
- 通知展示当前操作者昵称、词表名及数量，链接作者词表和收币记录；账号/词表删除后使用缺省文案，不保留名称快照。
- 复用现有 60 秒轮询、窗口聚焦刷新、标题和 favicon 徽标；标已读使共享通知缓存失效并刷新徽标。

依赖：点赞、投币、通知与标签页提示均已在主线；新增通知迁移及响应字段，扩展前端 wire 类型与通知展示。后端实现位于同名 `codex/wordlist-notifications` 任务分支；仅维护本记录。

兼容与发布：新字段按需省略，已有教师通知 wire 保持原状；新前端接受旧 API 不含词表字段的教师通知。旧前端不能呈现新增 kind 的标题/正文，因此应先发布前端，再发布后端迁移与业务。通知请求没有严格 runtime validator。上线后回退前端会失去新增通知内容；回退旧后端仍保留数据库迁移和通知数据。down 在存在词表通知时明确拒绝，避免丢失历史；空数据时支持 down/up。部署和混合版本浏览器验收尚未执行。

验证范围：后端真实隔离数据库 handler 测试覆盖事务、并发、权限、重试与迁移；前端组件覆盖内容、链接、大金额、删除缺省、共享缓存和标已读；同步 OpenAPI 并运行 api-client 契约测试、类型与受影响检查。真实页面验收需生产构建、任务隔离 API/数据库/Redis，无 mock。
