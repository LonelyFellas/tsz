# 词形出题资格、测评审核与学生词表

前端基线 `cf96a690`，Rust 基线 `ad586082`。用户确认本次同步实现新版测评审核和学生词表双题源。

1. 词形配置提供新建默认值。词条按具体词形 ID 覆盖，草稿保存和版本发布分开。关闭词形可以继续查阅。历史词形缺省允许。
2. 后台审核员针对当前不可变发布版本通过或撤销测评资格。重新发布、归档和恢复使旧决定失效。操作在事务内核实权限、发布版本、生命周期和上次决定，持久记录审核人及时间。
3. 学生词表继续接受原平台词条及自定义词。新增经过测评审核的新版词条，按稳定身份同时搜索、收录、展示和练习。拼写沿用原有题型，单选继续校验词典证据和合法干扰项。草稿不直接供题，撤销后的新版来源不得用于新题，已有作答与成绩保留。

验收覆盖两类同拼写词形独立设置、旧写保留、发布回读、审核与撤销、两版来源同一词表、候选和答题快照。本次使用独立 PostgreSQL、Redis 和无业务 mock 的本地前端验收。

## 使用与兼容

- 在「词性配置 → 词形变化」设置默认值。新建、自动铺设或手工添加词形时取该值。词条里的同一具体词形跨组共用开关，共用一份拼写内容的不同词形各自保存。旧草稿与旧快照缺省允许。
- 在「预览并发布 → 已发布版本 → 测评审核」核对词形并通过或撤销。授权键为 `words.review_assessment`，依赖 `words.access`。审核不修改草稿。发布新版本、归档或恢复后须重新通过审核。每次有效决定在同一事务中记录审核人、时间、发布版本和生命周期版本。
- 出题开关仅过滤现有题型。新版与旧版词条按独立 ID 同时进入学生词表，拼写与单选分别按原有词义、原形、地区拼写及干扰项规则选题。词形关闭后仍可查阅；选项不足时沿用现有单选策略。新版提供文本测评资格，审核本身不授权学生播放录音。
- 同名候选可按新版或旧版选择；精确导入遇多个来源返回 `ambiguous`。旧学生客户端继续读取原有候选结构，新客户端通过请求头协商来源。新版发布文档单独存储，审核时生成学生读取所需的数据，不向旧库写入影子词条。

## 配套交付

先升级兼容旧客户端的 Rust API，再启用新版 Admin 和 Web。目录新增列默认为允许；旧编辑器写入不会覆盖已经关闭的词形。新 Admin 连接旧 API 时按能力隐藏词条开关和测评审核。学生端继续兼容缺少来源字段的候选。

两项迁移分别为 `20261126010000` 和 `20261126020000`。存在已设置的关闭值、审核历史、审核授权或新版词表引用时，相应 down 拒绝丢弃数据。出现这些数据后，前端可以回退并保留新 API，后端须使用兼容迁移账本和新数据的版本回退。

## 本地验收记录

- Codex 内置浏览器通过无业务 mock 的 Admin 登录，关闭名词复数默认出题后重开配置，默认模板仍为开。独立 `fish` 草稿的原形与复数共用拼写和读法，初始分别为开、关。只对该词条开启复数，保存、刷新、发布，已发布版本显示两个独立设置。1440px 与 1024px 桌面宽度均无整页横向溢出。
- 独立学生账号在审核前搜不到新版 `fish`。审核员打开已发布版本并通过，学生在 Next 生产构建中将新版 `fish` 和旧库 `shark` 加入同一词表。浏览器拼写答对 2/2；严格单选首题以 `fish` 为正确项，次题以 `fish` 为干扰项。审核员撤销后次题提交被拒，页面保留已答 1/2 和此前成绩。
- 关闭新版原形、保留复数，再发布并重新审核。词表仍可查阅 `fish`，拼写预览降为 1 项，严格单选因干扰项不足降为 0。旧作答保留，数据库中该新版发布的有效单选候选为 0。
- 第二个隔离库同时收录同名同释义的新版和旧版 `fish`。页面可以按来源选择，批量导入返回歧义；已授权接口能将两个不同的发布身份保存在同一词表。
- 以基线客户端的原生 runtime 实际校验旧协商响应；新客户端分别校验新、旧协商响应。每组均通过能力、草稿、已发布状态、候选搜索和批量导入五种响应。后台 OTP 使用本地 Mock 通道；词条、审核、学生词表、出题及作答使用真实 Rust API、PostgreSQL 和 Redis。
