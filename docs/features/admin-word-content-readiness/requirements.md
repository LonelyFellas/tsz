# 词条内容联动生成与真实完成度需求评估

## 背景与目标

管理后台创建词条时，会为每个基本词性初始化一条空语法结构、一个空词义和一条空例句。左侧“完成情况”当前只按数组长度计数，只要空节点存在就显示绿色勾，导致 `centre` 测试草稿在语义区间、双方言语法结构、中文释义、英文例句和汉语译文均为空时，仍显示“语义区间 1、语法结构 3、多维词义 3、多维例句 3”且全部完成。

本功能同时完成两件事：

1. 将左侧摘要改为与保存/发布校验一致的真实完成度，不再把空占位节点当成完成内容。
2. 在词形步骤完成后，自动联动生成并填入语义区间、语法结构、多维词义和多维例句；已有空白草稿可安全补全，任何人工内容不得被静默覆盖。

成功结果是：管理员进入词义与例句步骤时优先得到可编辑、可追踪来源的真实内容；生成缺失或失败时明确显示待完善，左侧状态始终与当前页面内容和最终校验一致。

## 目标端

- admin 管理后台：创建/编辑 V2 词条向导。
- 不修改 web 学习端展示。
- 内容来源、生成策略、持久化和最终校验由 `tsz-rust` 权威负责；前端不硬编码单词数据，也不自行编造语法、释义和例句。

## 用户故事 / 使用场景

1. 管理员完成词形与发音后进入第 3 步，希望系统自动启动内容生成，而不是只看到三组空壳。
2. 生成成功时，管理员希望每个词性获得匹配的语义区间、语法结构、词义、释义和双语例句，并可继续人工修改。
3. 生成只得到部分可靠内容时，管理员希望保留已生成内容，同时明确看到剩余待完善项。
4. 重新打开历史空白草稿时，管理员希望系统能安全补全；若已经手工填写，则只填空字段，不覆盖已有值。
5. 编辑任一字段时，管理员希望左侧“完成情况”实时变化；保存前和刷新后的状态均能区分。
6. 点击左侧未完成项时，管理员希望进入对应词性并定位到第一处阻断字段。
7. 生成服务不可用、限流或返回无可靠内容时，管理员仍可手工填写，且页面不能假装已经完成。

## 功能范围

### 本次范围内

- 对方言识别、基本词性、词形变化、语义区间、语法结构、多维词义和多维例句建立统一 readiness 计算。
- 每项至少区分：
  - `完成`：所有必填内容满足当前客户端校验，并与服务端规则对齐；
  - `待完善`：已存在但仍有必填缺失或非法内容；
  - `未开始`：没有任何对应内容；
  - `生成中/生成失败`：仅用于自动生成过程。
- 数量显示为“有效完成数 / 总数”或明确的待修数量，不再只显示节点数量并据此打勾。
- 当前步骤存在未保存编辑时，左侧基于内存草稿实时计算；离开页面后以服务端已保存版本为准。
- 未完成行可点击，定位到所属步骤、词性和第一处无效字段。
- 新词条：词形步骤完成后自动启动一次内容生成。
- 旧草稿：当 meanings 仍是系统生成的空白骨架时自动补全一次；已有人工内容时仅填空位。
- 生成内容至少覆盖：
  - 双语语义区间名称；
  - 每个词性的双方言/统一方言语法结构；
  - 细分词性、等级、可用词频和至少一条中文释义；
  - 至少一条英文例句及汉语译文；
  - 每条例句唯一且锁定的当前词义 `focus` 关联；
  - 释义与同一词性语法结构的可选绑定。
- 内容生成按“可靠词典优先、获授权的生成服务补缺”执行，并保留 provider/version/coverage/provenance。
- 自动生成只写空字段；覆盖或重生成已有人工内容必须是独立、显式、带确认的后续操作，本次不做。
- partial、无结果、超时、限流、服务不可用和 revision 冲突均有可恢复状态与重试入口。

### 明确不做

- 不在前端按词头或词性写死语法、释义、例句和词频。
- 不把 mock、fixture、占位文案或模型无来源输出当作正式数据。
- 不自动生成近义词、反义词和派生词关系；关系词继续人工选择已发布词条及具体词义。
- 不静默覆盖人工填写、已发布内容或其他会话的新 revision。
- 不改变现有发布、归档、恢复和 publication 生命周期语义。
- 不在本功能中重做语音编辑器、TTS 或音频资产。

## 约束与边界

- `@tsz/types` 继续 snake_case 1:1 镜像 `tsz-rust/docs/openapi.json`。
- 前端客户端校验用于实时反馈，服务端 save-complete、validate、publish 仍是最终权威。
- 自动生成命令必须带 `base_revision` 和幂等键；相同命令可安全重试，不得重复追加内容。
- 服务端必须以稳定 node ID 合并结果，并按字段判断空位；只凭数组是否为空不足以识别人工内容。
- 页面卸载、切换词条或快速重复进入时，旧响应不得写入新词条或覆盖较新的本地编辑。
- 生成失败不能阻止手工录入；生成按钮/重试状态不能把未保存内容误报为已保存。
- admin 使用 antd v6，不引入 tailwind 或 `@tsz/ui`。
- 真实内容来源必须具有许可、版本和审计能力；供应商密钥与内部提示词不得下发前端。

## 验收标准

### 真实完成度

- [ ] 空语义区间显示 `0/1` 或“1 项待完善”，不显示绿色完成勾。
- [ ] 三个空语法结构显示 `0/3`，任一方言文本缺失时对应结构未完成。
- [ ] 三个只有空释义容器的词义显示 `0/3`；缺语义区间、细分词性、词频或中文释义时均未完成。
- [ ] 三个只有 focus link 的空例句显示 `0/3`；英文或汉语译文任一缺失时均未完成。
- [ ] 基本词性、词形变化也按有效性而非节点存在判断；可选且无需派生词形的词性不被误判为未完成。
- [ ] 当前页面编辑后摘要无需保存即可实时更新；刷新后恢复服务端版本对应的状态。
- [ ] 完成状态与当前客户端完成校验一致；服务端返回额外阻断项时以前端展示服务端问题为准。
- [ ] 点击待完善项能进入正确步骤/POS，并聚焦第一处问题。

### 联动生成

- [ ] 完成词形步骤后只启动一次生成；快速连点、刷新和网络重试不会重复追加节点。
- [ ] 生成成功后，语义区间、语法结构、词义和例句出现真实正文，左侧完成度随结果更新。
- [ ] 多词性结果按稳定 `pos_id` 分配，不串词性；释义引用的 grammar 与 sense 属于同一 POS。
- [ ] 例句保留唯一 `{word_id, sense_id, role: "focus"}`，不生成悬空或跨词义主关联。
- [ ] partial 响应保留已生成内容，其余字段继续显示待完善，不把 partial 宣称为完成。
- [ ] 历史空白草稿可补全；已有任意人工正文时只填空字段，不覆盖、不删除、不重排人工节点。
- [ ] revision 冲突拒绝应用旧结果并提示重新加载；用户当前未保存内容不丢失。
- [ ] 生成服务 401/403/409/422/429/503 均给出可恢复提示；手工录入仍可使用。
- [ ] 无可靠来源时保持缺失并说明原因，不能回退到前端猜测或假数据。

### 回归与真实验收

- [ ] 现有方言建议、forms 影响确认、meanings 保存、最终 validate/publish 行为不回归。
- [ ] mock 单测、真实 HTTP 契约测试和已登录 Codex 内置浏览器验收分开报告。
- [ ] 用至少一个多词性英美区分单词验证新建自动生成、局部人工修改、保存、刷新和发布前校验。
- [ ] 用现有 `centre/center` 空白草稿验证安全补全；若后端策略不允许补旧 detection，则明确返回可重建提示，不静默失败。

## 开放问题

1. 语法结构没有现成 Kaikki 权威字段；需要确定获授权的生成服务/provider。建议采用“词典优先、模型补缺、管理员发布前确认”，且所有生成内容记录 provider/version。
2. 当前 OpenAPI 已声明 `suggested_meanings`，但激活数据源把 meanings/examples 标为 `missing`。需要后端确认是先扩展 Kaikki 离线导入，还是同时引入独立生成服务；仅做前端无法满足本需求。
3. 历史空白草稿建议使用独立幂等 enrich 命令补全；若后端只允许重新检测创建，则产品需接受删除旧草稿重建。技术方案默认采用 enrich 命令。
