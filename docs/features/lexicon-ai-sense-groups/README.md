# 语义区间与词义候选

语义区间复用语法结构和词形与发音的候选抽屉。打开时读取同一词条和词义顺序下的缓存。生成后按原始词义索引显示中英文区间，编辑者点击一键配置后才填入当前草稿。配置复用可用的空白占位和相同名称的区间，保留已设置的区间。

词义目录、英文释义、中文解释、多维例句及其译文、常见译词与拓展词采用同一交互。词义目录在服务支持时同时请求方言判断，并在对应词义中显示方言建议。方言手动设置保留在词义内。

新客户端通过 `x-tsz-next-section-candidates: v1` 协商查询和刷新。Rust 转发该协商信号，新 Agent 仅在对应板块已协商且执行计划可以独立复用时使用缓存。词义与方言在同一份候选中缓存。旧服务支持生成后的人工确认回填。整词助手保留原有处理范围。

验收使用本地隔离环境中的 `run`。打开入口与重开缓存均不发起模型调用，重新生成产生新候选，明确应用前保持区间与词义不变。应用后保存并重载，两个词义与各自区间保持正确关联。

## 同词条共享候选

词形与发音、词义目录（含方言建议）、语义区间、语法结构、释义、常见译词、拓展词、例句和译文的独立生成结果支持共享。编辑可以打开对应板块接着确认，也可以重新生成。回填和保存继续由编辑明确执行。整词助手继续使用批次的生成与回填流程。

Rust 每次生成、查询及返回前确认对该词条的编辑权限。例句和译文同时要求例句访问权限。仅通过权限检查的协商请求向 Agent 发送共享能力标记。Agent 依据词条、板块、输入及字典资料匹配候选。前端摘要包括按生成顺序排列的词义和例句 ID，输入相关上下文变化时要求重新匹配。共享候选优先使用最近发起的成功批次，同事的查询会绑定其当前草稿版本。个人缓存仍只供原编辑查询，历史任务记录只保留运行数据。

验收用两个拥有同一词条编辑权限的账号，核实第二人打开板块可回读第一人的候选，查看和采纳前草稿版本一致。只读账号、无他人词条编辑权限的账号以及没有例句权限的账号，不能查看对应候选。相同文本的不同词义或例句、其他词条和变更后的生成范围各自匹配。

Agent 的新增迁移只增加查询索引。旧 Agent 忽略共享标记，旧 Rust 只可读个人候选。功能生效需要 Admin、Rust 和 Agent 都包含本改动。Agent 由原发布流程停服、显式迁移并启动新版本，之后可更新 Rust 和 Admin。Agent 的旧版本要求旧 schema revision，回退前须按原流程核对版本。回退该迁移只移除索引，保留候选记录。

2026-11-26 本地验收中，Admin 候选面板 13 项、Rust 新版词库 69 项和 Agent 430 项通过，Agent 另有 4 项跳过。Agent 的数据库测试覆盖所有独立生成板块的跨账号读取。浏览器通过本地 Admin、Rust 和 Agent 连接专用 PostgreSQL 与 Redis。词条所有者生成 `run` 的两个区间，有他人词条编辑权限的账号直接读取并采纳，保存后重开确认两个区间及其词义归属。数据库只记录一次生成。验收使用本地模型桩和项目短信测试通道。Agent 索引迁移的降级和重新升级均已验证，原候选保留。
