# 短语成分用词 需求评估

## 背景与目标

短语（phrase）由若干单词（或更小的短语）构成。管理员维护短语词条时，需要把短语中的
各个「成分」与智能词库中的词条建立人工关联——即标注「这个短语里的 carry 用的是词库中
carry 这个词条的某个词义/词形」。这份关联数据后端 v3 契约已完整建模
（`component_usages`，挂在词形变体上），发布时会生成对目标词条的引用（引用保护：被
引用的目标不可归档），但**前端一直没有编辑入口**，字段始终为空。

本期目标：在词条编辑器 step3（词义步）为短语补上「成分用词」编辑板块，让管理员能手
动完成成分→词库词条的关联。成功的样子：管理员编辑短语时能看到成分列表、逐个搜索并
关联到词库里已发布的词条、保存与发布均正常，发布后引用关系生效。

## 目标端

admin（平台后台，antd v6）。词条编辑器：`apps/admin/src/features/dictionary/word-creation-v3/`。

## 用户故事 / 使用场景

- 管理员 - 在编辑某个**短语**词条的 step3（词义步）时 - 想把短语中的每个单词与智能
  词库中的词条关联起来 - 从而让短语内容与词库形成结构化互链（发布后目标词条受引用保护，
  C 端未来可按此做成分溯源/跳转）。
- 主流程（2026-09-02 产品图定稿）：进入短语的 step3 → 每个词性 tab 内（语法结构卡下
  方、词义列表上方）看到「成分用词」卡片 → 卡片把短语拼写渲染成一排**可点击的单词**
  （初始零操作：不预查、不预填）→ 点击某个单词 → 该单词下方弹出 Popover，**自动**以
  该词做模糊搜索（无手动搜索框）→ Popover 内是**级联多选面板**（antd Cascader.Panel）：
  第一列候选词条（kind 标签 + 词头）→ 第二列**词形**（该词条的全部词形：原形/三单/现
  在分词/过去式/过去分词等，**不设词性层**；命中形默认展示，管理员可改选其他词形）→
  第三列词义（gloss，勾选多选）→ 勾选词义即完成关联，取消勾选即解除 → 单词按钮变绿，
  多条关联时显示 `×N` 角标；再点绿色单词可回显勾选态并增删。
- 短语目标（后端放开后，2026-09-02 拍板）：候选词条为短语时**与单词完全同构**（同样
  的 词条 → 词形 → 词义 三层），**不加**成分对位列——目标短语自己维护的成分用词直接
  复用（候选数据已携带，关联结果只读带出，无需管理员重复标注）。
- 关键规则：
  - **搜索按词形匹配**：候选命中的是词条的全部词形（比较级/最高级/三单/过去式等屈折
    形都能命中原形词条），词形精确命中排最前；候选行标注命中的词形与类型。
  - **允许多次关联**：同一个单词可同时挂多条关联（多个词条、多个词性、多个词义），
    对应后端 `component_usages` 数组语义。
  - 成分暂不关联（unresolved 概念此版收窄）：未点击/未勾选的单词就是无关联，允许保存
    与发布（不是发布门槛）。
  - 目标词条后续被再发布/归档：已关联数据以发布快照为准；保存时后端校验目标仍有效，
    失效则报 422，管理员需重新选择。
  - 英美分拼（distinguish）的短语：本期只编辑英式（uk）主变体的成分用词，us 变体
    不发字段、存量保留；双行独立维护列为后续扩展。

## 功能范围

**做：**

- step3 新增「成分用词」板块，**仅短语（kind=phrase）显示**，单词不显示。
- 单词级点选关联：短语拼写按空格切成可点击单词；点击弹 Popover 级联面板
  （词条 → **词形** → 词义，不设词性层）多选勾选即关联、取消即解除；literal 即被
  点击的单词文本，按短语拼写顺序保序落库。
- 候选按**词形**解析（屈折形命中原形词条）；级联第二列即词形层——命中词形默认呈现，
  `target_form_id` 等字段由所选词形组装；候选自带全词形清单，命中行标「命中」。
- 已关联单词绿色高亮 + 多关联数量角标，回显勾选态，可增删改。
- 随词形步内容一起保存（数据挂在词形变体上，见 design），保存/发布链路不回退现有功能。
- **迁移 step2 现有入口**：删除词形步 `V3ConcreteFormRow` 内嵌的旧「成分用词」编辑器，
  统一收口到 step3 本板块（避免两处编辑同一份数据）。

**不做（本期边界）：**

- 不做自动拆词之外的任何自动匹配/AI 补全（现阶段无 AI 内容）。
- 不做 C 端消费展示（数据先建起来，C 端另行排期）。
- ~~不做目标为短语的关联~~：后端 2026-09-02 已放开，单词与短语候选同构呈现。
- 不做非 base 词形（如短语的过去式变形）的成分维护——本期只维护 base 词形变体上的
  成分用词（后端模型支持全部词形，扩展留待后续）。

## 约束与边界

- 数据规则（后端已落地，前端须遵守）：
  - 仅 phrase 可有 `component_usages`；word 携带该字段会被 422。
  - 每个词形变体最多 100 条；literal 非空、无首尾空白、≤200 字符。
  - Resolved 目标必须是**已发布、未归档的 v3 单词**，且 pos/词形/变体/方言/词义/词头/
    gloss 全套字段与目标**当前发布快照**精确一致，否则保存整体 422。
  - gloss 取目标词义的第一条中文释义/中文例句文本（前端派生规则须与后端一致）。
  - 省略字段（不发 `component_usages`）后端保留库中现值——存量前端不受影响，可渐进上线。
- 发布语义：unresolved 成分发布时被跳过；resolved 成分发布后生成引用记录，目标词条
  被引用期间不可归档。
- 权限：沿用词条编辑既有权限（创建者/超管），无新增角色规则。
- 兼容性：不改动单词编辑路径；不影响 v2 词条。
- **候选可见性**（遵循全局「词条搜索可见性边界」约定）：归档一律不进候选；本期候选
  只收**已发布**词条（后端要求 Resolved 目标必须已发布）；**若后续放开草稿进候选，
  草稿只能是管理员自己创建的**（超管不豁免），且需要后端先支持草稿预绑定态才能真正
  完成关联。

## 验收标准

- [ ] 短语 step3 每个词性 tab 内出现「成分用词」卡片（语法结构下方）；单词 step3 不出现。
- [ ] 短语拼写渲染为可点击单词；点击弹出级联面板（词条 → 词形 → 词义），按词形命中
      候选（屈折形能命中原形词条）。
- [ ] 勾选词义即关联、取消即解除；同一单词可挂多条关联（×N 角标）；再次点击回显勾选态。
- [ ] 关联落库为该词性 base 词形变体的 `component_usages`，literal 为被点击单词、按短
      语语序保序；目标不变时节点 id 稳定（跨保存不漂移）。
- [ ] 英美分拼短语本期编辑英式（uk）主变体的成分；us 变体不发字段、存量保留
      （双行独立维护列为后续扩展）。
- [ ] 保存成功后重进编辑器数据回显完整；含 unresolved 成分也能保存与发布。
- [ ] 关联目标失效（被归档/再发布导致快照不一致）时保存报错可见、可重新选择后成功。
- [ ] 发布含 resolved 成分的短语后，归档目标词条被后端拒绝（引用保护生效，手测验证）。
- [ ] 单元测试覆盖板块的增删改/关联/解除/回显与保存载荷组装；`pnpm typecheck`、
      `pnpm lint`、`pnpm test` 全绿。

## 开放问题

1. **目标可为短语**：后端校验当前把目标限定为已发布 v3 单词（kind=word，短语目标
   422）；需求要求单词与短语都可作目标。**后端放开中（用户自行开工，2026-09-02）**；
   前端 UI 已按双 kind 设计（候选带 单词/短语 标签），联调时以后端实际放开为准。
2. **只维护 base 词形是否符合预期**：后端模型允许每个具体词形（如短语的过去式变形）
   的每个变体都有独立成分用词；本期只做 base 词形变体的编辑，其余词形变体不发字段
   （后端 PresenceAwareVec 语义会保留存量）。是否可接受？
3. **同名单词的归属**（数据模型限制）：存储里 literal 只有文本无位置，短语中出现两个
   相同单词（如 "day by day" 的两个 day）时无法区分各自的关联，UI 将按「同文本单词共
   享同一组关联」呈现。是否可接受？（若要精确区分需后端加位置/序号字段。）
4. ~~目标词义粒度~~（已由级联交互回答：必须勾选到词义叶子，不设默认。）
5. ~~多词成分圈选~~（定稿交互取消了跨词圈选：literal 恒为单个单词；子短语目标靠候选
   列表里的短语词条承接，如点 give 时勾选「短语 give up」。）
