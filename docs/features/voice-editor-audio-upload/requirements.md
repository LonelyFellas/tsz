# 语音编辑器上传音频持久化 需求评估

## 背景与目标

语音编辑器（`@tsz/voice-editor`）工具栏里的「音频」工具，目前只做到**浏览器本地试听**：
选中的文件以 object URL 存在编辑器内存里，可以按语种/性别归类、试听、移除，但不发任何请求、
不进对象存储、不写进词条，刷新页面即丢。这是当初立项时明确划出去的范围
（`docs/features/voice-rich-text-editor/requirements.md`「明确不包含」；
`docs/features/voice-editor-wire-contract/requirements.md`「变更 4：上传音频持久化——建议单独立项」）。

本次把它做成真的：管理员为一段英文文本上传真人录音（按英式/美式 × 女声/男声归类），
随词条草稿保存、刷新后回显、随发布固化，为后续 C 端播放提供素材。

**成功长什么样**：在 V3 第 3 步语法结构的编辑器里选文件 → 看到上传完成 → 保存草稿 →
刷新页面 → 音频列表原样回来且能试听 → 发布后发布快照里带着这些音频的引用。

## 目标端

admin（`apps/admin` + `@tsz/voice-editor` + `@tsz/api-client` + `@tsz/types`）。
C 端（web）播放不在本期，但发布快照要把音频引用带出去，给 C 端接入留好口子。

## 用户故事 / 使用场景

1. **上传**：词库管理员在 V3 第 3 步某条语法结构变体的语音编辑器里，先选归属（BrE / AmE、女声 / 男声），
   再选一个或多个音频文件；每个文件显示上传中 → 成功后出现在列表里；失败的那条给出原因（格式不支持 /
   超过大小 / 网络失败），可重选重传，不影响已成功的其他文件。
2. **试听与移除**：列表里每条可试听（同一时间只播一条）、可移除；移除前二次确认，确认后只是从草稿里
   去掉引用，保存草稿后才生效。音频不属于文本标注的撤销历史，不进撤销栈。
3. **保存与回显**：保存草稿、刷新页面或重新进入第 3 步后，音频列表按原顺序、原归属回来，仍可试听。
4. **发布**：发布词条时，当前草稿里的音频随发布快照固化；发布后再改草稿里的音频不影响已发布快照，
   激活历史发布也能听到当时的音频。
5. **存储未开通**：所在环境没有配音频存储时，「音频」面板置灰并说明"音频上传尚未开通"，
   其余工具照常可用；已有的音频引用仍能列出（不能试听时给出原因）。
6. **词条归档 / 删除**：随之不再被引用的音频对象由后端回收，前端不感知、不承担清理。

## 功能范围

### 本次包含

- 上传三步流程（申请许可 → 直传 OSS → confirm）在 admin 与 `@tsz/voice-editor` 里的落地，含进度、失败、重试。
- 音频资产引用写入 V3 语法结构变体（`GrammarVariantV3`），随 meanings 草稿保存 / 读回。
- 列表试听走短期签名 URL；URL 过期后自动重取。
- 发布快照携带音频引用（后端职责，前端只需在发布预览里能看到条数）。
- 存储未开通（501）的降级表现。
- `@tsz/types` / `@tsz/api-client` 的契约同步与契约测试。

### 明确不包含

- C 端播放 UI 与 C 端取签名 URL 的接口（另立项）。
- 浏览器内录音、音频剪辑 / 切片 / 逐词对齐。
- 上传音频与 TTS 合成的取舍策略（两者并列保存，播放端自行选择）。
- 把语音编辑器接到英文例句 / 释义字段（`RichTextVariantV3` 只预留同形字段，本期不接）。
- V2 向导（`/words/:id/wizard`）。
- 后端实现（本仓只写对接建议，由用户转达后端）。

## 约束与边界

- **权限**：与编辑该词条草稿同权限；上传许可与 confirm 都要求已登录管理员，走现有 admin 鉴权内核。
- **归属枚举**：语种 `en-GB` / `en-US`、性别 `female` / `male`，与 `/speech/voices` 音色目录的口径一致；
  同一归属允许多条。
- **格式与大小**（默认值，见开放问题）：`audio/mpeg`、`audio/mp4`（m4a）、`audio/wav`、`audio/ogg`；
  单文件 ≤ 10 MiB；每个变体 ≤ 8 条。前端按 `File.type` / `File.size` 预检，后端 confirm 时按对象实际值复核。
- **对象键由服务端生成**：客户端文件名只作展示元数据，绝不成为对象键（对象存储底座约定）。
- **签名 URL 是秘密**：只存组件内存，不写 localStorage / query string / 日志 / 埋点；过期即废弃重取。
- **直传跨域**：PUT 直接打 OSS 域名，不带 Authorization、不带 cookie；bucket CORS 需放行
  `http://localhost:3001` 与测试服 / 生产的 admin 来源（生效有延迟，提前找后端加）。
- **兼容**：存量草稿 / 发布没有该字段，一律按空列表处理；不改动 `voice_profile` 的语义。
- **严格 runtime schema**：前端对 V3 响应 `additionalProperties: false`，后端新增响应字段必须
  前端先同步 `sync:openapi` 并部署（或同批），见 memory「严格runtime schema部署顺序」。

## 验收标准

- [ ] 在 V3 第 3 步语法结构编辑器里选 2 个 mp3（BrE 女声），列表出现 2 条，各自可试听、可移除。
- [ ] 选一个 20 MiB 文件：上传前即被拦下并提示大小上限，不发申请许可请求。
- [ ] 选一个 `.txt`：提示格式不支持，不发请求。
- [ ] 直传 OSS 失败（断网 / 403）：该条显示失败与原因，点重试从申请许可重新走一遍，其他条不受影响。
- [ ] 保存草稿 → 刷新 → 重新进入第 3 步：列表条数、顺序、归属与文件名一致，试听正常。
- [ ] 试听按钮在签名 URL 过期（5 分钟）后再点：自动重取 URL 并播放，不报错。
- [ ] 移除一条：先弹确认；确认 → 保存 → 刷新：那条不再出现；取消确认则列表不变。
- [ ] 发布词条 → 查看发布快照 / 发布历史：音频引用数量与发布时草稿一致；发布后再删草稿里的音频，
      已发布快照不变。
- [ ] 环境未配音频存储：申请许可返回 501，面板置灰并提示，本会话不再反复请求；其他工具不受影响。
- [ ] `pnpm --filter @tsz/api-client sync:openapi` 后契约测试通过；admin / voice-editor 单测通过。

## 开放问题

1. **挂点**：本期只挂语法结构变体（编辑器目前唯一挂点）。例句 / 释义要等它们接入编辑器时顺带，
   还是本期就把 `RichTextVariantV3.audio_assets` 一并放开（后端多校验一处）？
2. **上限**：单文件 10 MiB、每变体 8 条、格式四种——是否合适？真人录音一般 < 1 MiB，
   10 MiB 主要给 wav 留余量。
3. **发布快照与对象的关系**：推荐发布快照**引用**同一资产（不复制对象），删除对象受"任一草稿或
   发布引用"保护；接受吗？还是发布时复制一份到独立前缀？
4. **要不要备注字段**：列表只显示文件名 + 归属；是否需要管理员可编辑的"说明"（如"慢速版"）？
5. **C 端可见性**：存储空间按 `private` + 签名读设计，C 端将来也走签名；如果 C 端要 CDN 直出，
   需要改成 `public-read`，那就得现在定，避免后面迁桶。
6. **删除权**：前端只做"从草稿去掉引用"，不直接删对象；对象回收完全由后端按引用计数处理。
   是否需要一个管理员可见的"回收站 / 未引用音频"入口？本期建议不做。
