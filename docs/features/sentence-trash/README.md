# 例句管理与垃圾桶（禅道 155）

目标：一级「例句管理」包含「多维例句」「垃圾桶」。首版仅从未发布的草稿可移入垃圾桶；已发布/曾发布例句继续使用发布撤回规则。

后端配套：`codex/task-155-sentence-trash`，任务工作区 `task-155-backend-trash/tsz-rust`。前后端共用本文记录。

## 行为与契约

- `POST /admin/lexicon/sentences/{id}/trash` 与 `/untrash`：超管、`base_revision` 校验，成功返回 204。移入与恢复同时递增草稿及生命周期版本。
- `GET /admin/lexicon/sentences?view=draft&trash=true`：需 `sentences.access`，复用列表分页筛选和现有响应结构；公开只读权限不能访问垃圾桶。
- 使用 `in_trash` 区分可恢复草稿和历史删除。垃圾桶同时设置 `deleted_at`，使现有编辑、发布、词条引用及学习链路继续排除它；保留标注、收录和音频引用。
- 恢复时锁定关联词条并重新校验标注、词形/词义与阅读链接；失效则拒绝恢复并完整保留垃圾桶记录。
- 新界面永久删除只在垃圾桶提供。为兼容旧客户端，既有超管 DELETE 接口仍允许直接永久删除从未发布草稿；历史删除不会自动加入垃圾桶。
- 回退迁移在垃圾桶非空时主动拒绝；应先恢复或永久删除这些草稿。不得通过回退丢弃可恢复数据。

## 验收

菜单层级和两种垃圾桶独立；公开只读权限不可进入例句垃圾桶；移入后普通列表/GET/编辑不可访问；垃圾桶能查看且无法编辑/发布；恢复重新 GET 内容及标注一致；过期版本、已发布记录和无权角色拒绝；永久删除清除专属关联；恢复失败保留记录；音频引用不会因入桶被回收。

发布须先上兼容后端（含迁移），再上前端。旧前端可继续访问普通列表和旧 DELETE；新前端访问旧后端的垃圾桶能力不可用，不可先发布新前端。未部署前不得将本地测试视作线上验收。
