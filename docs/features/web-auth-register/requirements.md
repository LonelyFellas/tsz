# C 端注册登录需求

## 范围与授权

本文件在既有手机号注册方案上更新，范围依据 `../../account-identity-permissions-batches.md` 的第二批实施授权（2026-09-25）。

- 包含 #82 注册与登录分离、#76 手机号注册、#77 邮箱注册、#79 手机号密码登录、#80 手机验证码登录、#81 邮箱密码登录。
- 暂缓 #78 海外入口、国际手机号及真实短信／邮件供应商；当前 Mock 仅用于测试，不代表真实送达完成。
- 保留已有邮箱验证码登录；不涉及 admin 账号或第三批绑定、换绑、改密功能扩展。

## 行为要求

1. 注册页和登录页独立；登录失败不能隐式创建账号，应提供对应手机／邮箱注册入口。
2. 用户选择手机号或邮箱，填写联系方式、六位验证码、密码。手机号保持大陆格式；邮箱归一化为 trim 后的小写。
3. 发码用 Register 用途；提交必须使用同一联系方式和用途的验证码，不能跨账号、跨用途或重复消费。
4. 新注册密码沿用 11–20 位字母数字组合、不区分大小写，前后端一致执行并大写存储。
5. 登录不重新执行新注册密码策略；保留历史 API 原串密码和 web 大写密码的有效登录路径，不重置存量凭据。
6. 注册创建用户、student 角色和 refresh session 必须原子完成，失败不能残留半个账号；邮箱大小写变体和并发重复注册不能产生重复账号。
7. 注册成功直接建立会话；等待 me 完整资料后由 GuestGuard 安全跳转。资料加载失败只重试资料，不能重复注册或消费登录验证码。
8. 切换联系方式或注册方式清空旧验证码、错误和前端倒计时；发码／认证在途锁定对应输入和切换，避免请求返回到错误账号。
9. 重复账号、验证码无效、限流、停用与基础设施故障均有提示；密码错误与未知账号仍不可区分，不增加账号枚举接口。
10. 切换注册／登录保留回跳地址；手机号、邮箱、密码、验证码不放进 URL、日志或持久化存储，query 只携带注册方式及回跳路径。

## 验收

- 后端：手机和 email-only 注册成功；联系方式互斥；归一化、冲突字段、并发唯一性、用途隔离、重放拒绝、注册密码边界、会话失败回滚；存量密码、未知账号及停用账号回归。
- 前端：方式切换、六位码、在途锁定、失败恢复、对应入口、安全回跳、原串密码传递；成功后资料失败不重复认证。
- 浏览器：build + next start 下验邮箱注册、email-only 资料、手机／邮箱登录、错误引导、窄屏、SSR 表单与原有鉴权流程。
- 最终执行两仓原生全量门禁；Mock E2E、真实 API 测试与真实服务商送达分开记录。
- 不在未验收前勾选完成；当前命令和结果以六批记录为准。
