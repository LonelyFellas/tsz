## 1. 目标与范围

在管理端提供独立一级菜单「配音中心」，让内容编辑人员集中选择、比较声音，为内容板块维护推荐，并在具体文本中完成配音。

用户提供的《配音中心与文本设置.html》为功能参考。原型有音色目录、分组配音与六处文本编辑入口；正式界面沿用后台 Ant Design 6，不复制原型中的本机账号设置、示例导航或服务地址配置。

目标流程：浏览音色 → 使用相同文本试听 → 调整临时参数或加入分组推荐 → 在文本中保存命名版本并选用 → 生成审听 → 保存并选用正式音频。

首期面向内容管理员，使用后端当前开放的 Azure 英式与美式英语音色。全语种目录、候选模型不因出现在原型中就开放合成。首期不新增声音克隆、第三方供应商接入、收藏系统、批量重做历史音频或学习端选音色功能。

## 3. 全部音色

### 3.1 查找与展示

- 页面依次放置共用试听文本、筛选、音色列表、当前播放器。
- 默认示例为英文短句，试听文本最多 500 个 Unicode 字符；空白文本不能生成。
- 第一批提供名称／标识搜索、英美口音、性别、常用音色筛选与名称排序。
- 资料接入后再加入模型、声音年龄组、个性特点、场景、风格筛选，以及介绍和个人笔记搜索。无资料显示「未提供」，不得从名称推测。
- 同维度多选取并集，不同维度取交集；清空筛选后恢复全部英美目录。
- 原型男女分组需求保留；第一批通过性别筛选和清晰标签浏览，资料批次再完成分组显示与分页，不沿用男女共用页码导致重复展示的行为。
- 列表保留音色名称、口音、性别、常用标记、支持的风格、试听和参数入口。完整技术标识放在次要位置供识别。
- 加载、空目录、无匹配、服务失败分别呈现；失败提供重试，不静默使用原型假目录。

### 3.2 资料归属

- 官方原文与来源只读，中文资料说明是完整译文、概括还是人工改写。
- 中文介绍由有维护权限的管理员共享维护；个人听感仅当前账号可见。
- 听感由服务器按账号保存，刷新／换设备后可读回。试听参数仅在当前页面保留，历史个人参数留存在服务器但不再自动带入；保存听感保留历史参数。
- 官方目录刷新不得覆盖人工介绍或个人笔记。恢复官方介绍不清除笔记。
- 以供应商和完整音色标识区分不同模型版本，不以显示名称去重。

## 4. 参数与试听

### 4.1 参数

常用项为音色、合成语速、音量；更多项为音调、风格、风格强度、角色；特定模型参数仅按真实能力开放。

第一批现有契约只支持 `voice_alias`、`style`、`rate_percent`、`pitch_semitones`。因此先实现语速、音调与风格，不展示不能提交的音量、角色、模型参数。语速倍率显示与百分比请求一一对应，音调明确使用半音，不把原型百分比直接传给接口。

- 参数范围、可用风格从该音色能力读取；固定范围代表不可调，不给出无效控件。
- 中性风格不发送额外风格值；切换音色时使用新音色有效初值。
- 数字必须有效且位于服务范围内；前后端都需校验。
- 个性特点和推荐场景是资料标签，不是合成参数。
- 查看详情与试听不写入配置；点击相应保存／应用操作才改变对应范围。

### 4.2 播放与状态

- 使用真实合成接口，响应失败保留输入并允许重试。
- 同时最多播放一个音频；切换音色、重新生成或离开页面时停止旧播放并取消过期请求。
- 后发请求优先，迟到的旧响应不得替换当前结果。
- 显示音色、口音及生成时参数。文本或参数变更后标记旧结果失效，禁止把它显示为当前配置的结果。
- 音频地址失效或加载失败时提示重新生成。浏览器禁止自动播放时允许手动播放。
- 合成语速影响文件，审听倍速仅影响播放器。试听成功不等于已保存或已发布。
- 后续波形由真实音频计算，支持定位和区间循环。导入音频标明参考用途，不能冒充生成结果。
- 音频下载与 WAV／MP3 输出需要真实服务支持；第一批不承诺目前接口没有返回的格式。

## 5. 分组配音

五个可分组板块：词形拼写、Azure IPA／UPS、词性的语法结构、英文释义语句、多维例句。

初始分组为「词形与发音」（前两项）、「结构与释义」（语法与释义）和「例句」。管理员可新增、重命名、删除分组，调整板块归属。

- 一个板块同时最多属于一个分组；保存前明确提示从哪个分组移入。
- 有效分组至少有一个板块，英美各至少有一个可用推荐；同名分组不能重复。
- 推荐保存名称、音色与完整参数，并可排序。同一音色可有不同参数的多个推荐。
- 首位推荐是尚未独立配置文本的初值，其余推荐供编辑选择。
- 分组以一次保存提交，服务端原子更新归属和推荐；并发编辑不得静默覆盖。
- 删除分组先展示受影响板块；未分组板块使用明确的系统初值，历史文本和音频保持不变。
- 已失效的推荐不能用于新生成，标明原因并由编辑人员选择替代，不静默换声。

## 6. 保存范围与文本接入

| 操作           | 影响范围                                           |
| -------------- | -------------------------------------------------- |
| 调整音色库参数 | 仅本次页面试听，刷新恢复默认                       |
| 保存听感       | 仅当前账号的笔记，保留历史个人参数                 |
| 加入分组推荐   | 复制当前音色及参数为推荐项；以后个人参数变化不联动 |
| 修改分组推荐   | 更新板块推荐，供新配置或主动重新选用时使用         |
| 应用到文本     | 仅当前文本、当前口音，保留另一口音                 |
| 保存文本       | 固定选用配置、读法与音频引用；不反向修改推荐       |
| 使用最新推荐   | 用户主动替换当前文本配置，提示重新生成             |

- 新文本默认读取对应板块与口音的首位推荐；保存后保留配置快照，后续推荐变化不自动重做历史音频。
- 文本独立配置优先于推荐。同一文本可保留多个配音版本，但正式使用版本必须明确。
- 英美参数和发音数据分别保存，缺失时不跨口音回退。
- 字典音标、显示用实际发音与 Azure IPA／UPS 分开，显示符号不反向改写合成源。
- 关联词形、义项、读法与发音来源；关联失效提示修复，不能合成错误的另一词形。
- 需要指定读法时校验音色能力；只有显式选择「自然朗读」才跳过指定发音，并保留原关联数据。
- 特殊读法、停顿、连读标记属于当前文本。修改文字后重新校验标注位置，不携带失效位置生成。
- 正式音频必须经过现有资产保存、发布与读取链路；临时试听 URL 不直接作为长期正式音频引用。

## 7. 权限与数据设计

第一批复用已有目录与试听权限，菜单和直链守卫一致；目录访问与生成权限分别判断。前端隐藏按钮不能代替服务端鉴权。

后续新增独立的音色库查看、共享资料／分组维护权限时，同步后端目录、角色授权、页面守卫和测试，不给现有角色自动增加写权限。个人数据使用服务端当前管理员身份，不接受任意账号归属。

计划新增的业务数据：

| 对象         | 关键内容                             | 归属与约束                                 |
| ------------ | ------------------------------------ | ------------------------------------------ |
| 音色资料     | 官方来源、中文介绍、能力、可用状态   | 音色级；保留来源，未知能力不视为支持       |
| 个人音色设置 | 音色、参数、听感、更新时间           | 管理员 + 音色唯一                          |
| 配音分组     | 名称、板块、版本                     | 平台共享；板块归属唯一                     |
| 推荐项       | 分组、口音、名称、参数、顺序         | 独立参数版本；稳定标识                     |
| 文本配音     | 来源、口音、实际参数、版本、正式音频 | 随原内容保存，复用已有 DTO，避免平行数据源 |

后续接口在对应批次落实，使用 `snake_case`，通过 `@tsz/api-client` 接入。新增存储采用成对迁移、隔离库验证与必要的并发控制。前端不直接访问 Azure，也不携带服务密钥。

第二批接口：`GET /admin/speech/library`、`PUT /admin/speech/library/{alias}/personal`、`PUT /admin/speech/library/{alias}/description`。个人保存只接受参数、笔记与 `base_revision`，归属取当前管理员；共享介绍写入另需 `speech.global_dubbing`。版本冲突返回 409，前端保留输入；记录不存在时版本为 0。迁移 `20261021150000_voice_library` 新增两个独立表，回退会丢失本功能的个人设置和共享介绍，保留原音色目录。

前端已对齐主线 `7d6199fb` 的词形配套实现（#510），与后端 #288 的结构变化一致。使用原生完整 OpenAPI 同步，语音 schema 纳入现有统一快照；不保留独立语音快照或临时同步分支。文本接入将在这组统一基线上继续。

发布依赖：第二／三批的目录、资料和分组接口向前兼容；后端接口与迁移先于前端。新前端遇到旧后端缺少资料接口时显示加载失败、保留基础试听并禁用保存。

第四批文本参数有额外约束：旧后端严格拒绝新字段，旧前端严格 schema 也不接受写入后的新字段。不能让新旧编辑客户端同时写带新参数的文本。部署前必须采用受控编辑窗口／确认全部客户端更新，或另补能力协商与响应兼容；本轮没有部署。写入新参数后不能只回退前端，需同时保证读取兼容或回退参数写入数据。不得把「可选字段」等同于所有版本兼容。迁移 down 会丢失个人资料／分组数据，只有明确放弃这些数据才执行。

- 增加保留分组“全局常用”，不绑定板块，不允许删除；板块归属仍全局唯一。普通分组允许没有已选推荐，此时回退全局；两个层级都无可用推荐时才选择合格默认。
- 推荐保留稳定 ID、完整参数、`selected` 和顺序。同音色不同参数版本不合并。编辑中行位置稳定，完成后稳定地将已选排前，未选收入更多音色。
- 英美分别解析：局部明确已选 → 板块已选推荐 → 全局已选推荐 → 合格默认。合格性检查口音、最终实际标记、模型及服务可用性；不能直接取未选推荐作为默认。
- 文本显式记录继承或局部独立模式，保留所需来源和排序，不靠参数相等推断模式。局部没有已选项时，推荐的局部排序仍能决定默认；未推荐目录项只有明确选择后才参与。
- 同口音允许多个局部已选版本，按稳定顺序生成、审听，首个有效已选作为默认播放；沿用正式音频数组和历史资产保护，逐一检查现有单选消费者。

**读法与能力**

- 关联读取结构化 IPA／UPS，保存词条／发布版本、词形／变体、义项、读法版本、源字段和口音引用。读法已失效或缺字段时提示修复，不固定取第一条、不跨口音猜测。
- 新建直接 phoneme 仅在试听 session 使用；历史正式标注和结构化 IPA／UPS 配置保留，不把这条限制误用于词库正常发音维护。服务端根据请求用途及原记录判断，不能只隐藏前端按钮。
- 词形拼写、Azure IPA／UPS 提供特殊读法；语法、释义、例句同时提供关联单词与特殊读法。特殊读法包括按内容类型读和替换文字读，标注按文本范围校验。
- 严格模式按最终实际使用的 phoneme／say-as／sub／break／style／degree／role 校验；未知能力阻止生成。自然朗读必须显式选择并保留原指定发音引用，不能自动降级。
- style degree、role 及原型中的 temperature／top_p／top_k／cfg_scale／enhancePronunciation 按具体音色的已确认能力分别建模、限幅和生成；后者随相应模型接入，没有真实资源的参数标记待验证，不作为普通音色的通用控件。
- 语速 UI 按 0.3–1.7 倍及原型分段预设统一，支持 0.73；实际可用范围取音色能力交集。保留现有音调半音单位和音量整数精度，指南未要求时不为复制原型小数／百分比而改变存储单位。

**音频更新**

- 配置提交与任务创建同事务持久化，实际 TTS 在事务外执行。默认等待 60 秒，复用后台设置能力维护等待时长；同组再次完成更新 revision 和到期时间，只执行最后有效版本。
- 有效输入 hash 来自最终规范化 SSML、供应商声音／版本、会生效的参数及输出格式；名称、勾选控件状态、无合成作用的教学标记不进入 hash。原始手动 SSML 的试听、复制、下载保留同一原文。
- 依赖只登记实际继承的草稿文本目标，覆盖词条及共享例句的稳定 target；文本保存同步更新依赖，显式局部、上传录音及历史独立快照不自动加入。自动重建只替换草稿音频，已发布内容及其音频引用保持原样，通过正常发布操作更新。
- 执行前与当前有效音频 hash 比较；只改名称、改未选版本、改回原值、依赖已解除时不调用 TTS。板块移组、删除及全局回退变化也重新解析最终来源，不能只扫旧 group_id。
- 取消草稿不影响已提交任务；撤销只作用于待执行任务，不回滚配置。正在调用的请求不承诺能撤回供应商费用；过期结果无权替换音频。
- worker 使用持久任务、租约、有限重试和当前版本校验，进程重启可恢复。成功后对单个文本 target 的同次受影响版本全部就绪再事务替换；失败保留该 target 的原音频，任务展示部分成功及可重试项，不承诺全库一笔事务。
- 替换同时检查组 revision、目标内容版本、继承模式和最终 hash，不覆盖并发编辑。沿用既有资产引用与回收，不创建永久旧音频副本。

### 12.5 契约、文件与迁移落点

以下接口是拟定形状，实施时与现有路由、OpenAPI 对齐；不是现有已实现端点。前端继续使用 `snake_case` wire 与统一 api-client，不直连 Azure。

| 契约范围                                                | 拟定改动及错误语义                                                                                                                                                                                                         |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /admin/speech/voices`、`GET /admin/speech/library` | 返回当前归属及 revision、支持语言完整性／来源、明确的参数和元素能力；保留官方 provider ID。只有来源确认的目录项可生成，原型 653 条不作为上线数量目标。全语种浏览和全语种可生成分别验收。                                   |
| `PUT /admin/speech/library/{alias}/accent`              | 保存三态当前值及 base_revision；共享维护权限；同项冲突 409，非法值 400／422；不修改 locale。                                                                                                                               |

共享资料和分组仍由 `speech.global_dubbing` 维护；个人备注按管理员隔离。自动任务执行须核实适用的生成和内容权限，不从分组维护权自动授予 `speech.generate`。无生成权限时可以保留已提交配置，但明确显示任务未执行原因；队列不能成为绕过内容权限的服务账号入口。

主要落点：

- 前端：`apps/admin/src/features/voices/{VoiceLibrary,VoiceCatalogTable,DubbingGroups,AddRecommendation,SpeechRateInput}.tsx`、字典 `voice-editor` 适配器／数据源、`packages/voice-editor`、`packages/shared`、`packages/types/src/admin-tts.ts`／`admin-word-v3.ts`、`packages/api-client`；Web 的字典音频解析与默认播放。播放器复用现有组件，reader 入口不引入 AntD。
- 后端：`src/speech/{locale,model,ssml,catalog,generated,generated_source}.rs`、`src/speech/library`、词条／共享例句 DTO、读法关联解析、`voice_versions`、资产引用与字典读取；新增限定于配音业务的任务表和 worker。任务不直接改写所有内容 JSON，须经过现有校验与引用维护路径。
- 每批导出任务后端 `docs/openapi.json`，前端显式设置 `OPENAPI_SOURCE` 同步统一快照及 runtime bundle；不手工改生成 schema、不新增平行快照。

迁移按依赖拆为三组：音色归属及资料覆盖 → 单组 revision／全局常用／selected → 文本继承依赖和音频任务。文本 JSON 新字段按真实需要演进，不为规划提前创建空表。每组 up/down 成对，在隔离库验证，并记录新增数据后的回退拒绝条件。

旧数据处理：

1. 已有局部快照、命名版本、音频引用、历史发布全部保留，默认视为独立；没有来源证据时不自动转继承。旧空配置保留其原来语义，不因迁移触发全库 TTS。
2. 已有推荐迁移为 selected=true，保留稳定 ID 和顺序；新增全局常用不改变已有局部声音。普通组清空已选后按新版解析，不丢原候选配置。
3. 音色初赋维持现有 GB/AU/NZ→英式、US/CA→美式、其余不归类；IE 初始保持不归类，不采用原型的美式初值。该规则已于 2026-10-26 经用户确认，之后只保存当前归属，人工修改不被工厂映射覆盖。
4. 历史 phoneme 保留；已有直接正式标注可读取和维持原内容，新增直接标注仅允许试听。不能用前端新建标志作为唯一服务端判据。
5. 在首次启用自动任务前，从明确的继承数据建立依赖；回填依赖不等于创建重建任务。新字段写入后，不能直接切回不理解继承／多选的旧后端。

### 12.7 发布顺序与回退边界

本节记录后续发布边界，本轮实施授权不包含发布。沿用现有语音版本机制进行必要的短期读写协商，不新增永久双协议；实际契约及验收状态见各批实施记录。

1. 先验证新后端能读取旧数据、旧前端能读取兼容响应且不能覆盖新版内容；新增 migration 不自动重建历史音频，自动任务先保持未启用。
2. 后端兼容读取／单组及任务接口就绪后，再升级 Admin 与受影响 Web 读取端。严格 runtime schema 已验证可读新字段前，不开放继承／多选新数据写入。
3. 在真实测试环境验证迁移、五入口、队列恢复、正式音频及发布读取，通过后按已确认的“仅更新继承草稿”范围启用自动任务。启用边界明确到实例与配置，不以“同批快速部署”代替中间兼容验证。
4. 前端回退、后端回退、关闭任务、撤销待更新分别处理：关闭 worker 不回滚配置和已完成替换；不能恢复不理解新数据的旧二进制；down 遇到继承／新读法／任务数据时拒绝自动有损处理。旧资产按引用策略保护。
5. 实际发布时重新记录 API、Admin、Web 各自 manifest、CI 与验收；遵守当时主线的原生 ship/deploy，不沿用本文历史 SHA 当现网版本。

- 建议采用有序的配对推荐数组，单侧对象复用现有参数结构；最终 DTO 名称在实施时与 OpenAPI 一起确定。不能仅让两列视觉并排却继续独立排序和勾选。
- 保留一组一个 revision；完成／取消只作用于该组。新增／复制整套用四列选声；编辑已有某侧只显示该侧女／男两列。“保存配音设置／保存整套推荐”只回写本组草稿，仍须本组完成才持久化。
- 普通分组可共用板块，移除前后端独占限制；保留组内板块不重复、名称与 ID 校验。默认按组顺序查找首个存在合格已选推荐的适用组，再取该组首个合格推荐，最后才回退全局常用。不能遇到第一个空组就直接跳到全局。
- 组顺序使用独立的有版本命令，只传完整有序组 ID 和顺序 revision，不传组内容。校验集合完整、无重复、全局固定末位；和创建／删除并发时明确 409，和其他组未完成草稿互不夹带。
- 推荐套按已提交的人工顺序展示，移除“完成时自动 selected 前置”及原始目录“更多／收起”行为。组编号和上下按钮放框外左侧；英美始终左右同排，各自铅笔、喇叭、名称、语速、音量和对应表头。
- 音色库“加入分组推荐”不能继续只追加单侧。复用整套创建流程，预填当前音色一侧，要求明确选择另一侧；不暗自补默认声、不直接写正式组。

**历史数据**：现有两侧没有稳定关联，不能按名称相同或数组同位置猜配。先做只读盘点；保留旧配置、版本 ID、引用与原播放。只有有证据的关联才自动迁移，其余在编辑时要求人工配对／补齐；未整理的旧配置保留兼容读取与旧播放，不用迁移触发 TTS。新创建／新提交必须完整配对。不能为统一新 UI 删除单侧历史项。

### 13.5 具体改动：局部音色池与逐音色编辑

**当前落点**：`packages/voice-editor/src/editor/next/{VoiceEditor,VoiceVersions,ToolPanels}.tsx`、`core/{dubbing,voice-versions}.ts` 和 Admin 的 `dictionary/voice-editor/dataSource.ts`。当前是推荐下拉＋应用按钮、多命名版本卡片、展开的音色／音频工具；单一音色可有不同版本，身份以 version ID 为主，并非新版按 provider ID 去重的池。

需改为：

- 局部主页依次显示文本与标注工具、已获取音色、适用组全部推荐和完整四列目录。推荐单选，提供“不选择推荐”；显示来源组及双侧参数／试听，不放获取、复制或修改按钮。
- 显式区分“动态继承”“采用了某套推荐的局部副本”“不选推荐的自定义池”。复用 inherit/local，按实际需要增加推荐来源标识；不能用参数相同推断继承，也不能只存一份当前下拉框值。
- 推荐切换替换原推荐贡献的两侧音色，保留额外选择；目录只排除当前推荐的两个 provider ID。选“不选择推荐”将原主音色变为未选缓存并回目录，不自动勾选、不回退其他推荐。
- 已获取池按供应商＋官方标准 ID 去重，保留原始大小写和模型完整后缀。同名的不同模型不能合并；跨候选路径命中同一个声音只能出现一行。两侧分别排序，不能跨侧移动；取消再选恢复该声音已有参数。
- 缓存优先复用 `enabled=false` 的已保存 setting 与当前编辑会话草稿，不另建个人音色配置库；未选项不进入生成、发布必需清单或播放池。推荐副本和额外音色重合时只保留一个已选项，保留已有局部参数并明确反馈，不能隐式覆盖。
- 每行按序号、概率、上下按钮、播放、名称、语速、音量、铅笔排列。概率由当前文本同侧实际可用池归一化，失效项保留说明且不参与；不能改选未选择的声音凑池。
- 原始目录女／男四列各一个滚动区，标题固定在滚动区外；完整列出候选，不分页折叠成“更多”。搜索、勾选、切换编辑对象不重排目录、不重挂列容器，保留各列滚动位置。
- 铅笔打开唯一音色草稿；不显示其他选声列表或切换按钮。保存只替换该声音，取消只丢该草稿，其他已选项不变。音频格式、请求、波形、SSML 与试听记录按文本目标＋正文口音＋声音版本隔离；迟到回包不能写到新对象。
- 常用参数和其他参数直接展开。仅将明确“不支持”的声音参数排除在有效请求外，原值留在草稿／存储供恢复；有效参数投影须前后端共用语义并参与 hash。未知能力、指定音素／停顿等正文标记仍严格阻止，不能借禁用控件静默删标注。
- 语速展示沿用两位小数与分段预设，允许 0.73；可用区间仍取真实音色能力交集。当前后端 `MIN_SPEECH_RATE_PERCENT=-50`、V3 校验及数据库目录约束最低为 0.50 倍，不能把原型 0.30／0.40 当作已支持。只有逐音色证据确认后才成对调整约束、目录、DTO 和严格 schema，否则这些预设置灰并说明范围。音调继续保存半音，不照搬原型百分比；语速乘号、音量单位只改展示。
- 上传、下载、循环审听与 SSML 从局部主页移到具体修改页，复用现有能力。现有上传属于文本／口音资产，不能伪装成 TTS 声音版本；仍沿原资产归属保存，不新增无依据的逐音色录音存储。手动 SSML 只供会话试听。

**历史多版本**：旧文本同一官方 ID 若有多个不同参数／资产版本，继续可读可播；进入新池编辑时展示冲突并让编辑人员明确保留哪份配置，不能按第一条自动删除其他引用。只有用户完成转换并保存后才采用新去重语义；旧发布快照不重写。

### 13.6 具体改动：五入口统一保存与发布衔接

**当前证据**：`V3VoiceTextField.completeEditing` 分别调用正文、音色、音频回调，再完成编辑；默认只是宿主草稿，不能称为已入库。IPA／UPS 设置器“完成”也只回写父候选。`SentenceEditor` 已由外层 finish 统一调用例句 create/update，内部 `showDone=false`。现有服务端聚合保存可复用，但按钮文案不能把本地完成伪装成服务器保存。

- 共用一次编辑结果快照，包含正文、标注／关联、读法、voice_profile、已选顺序和适用音频引用；宿主用一次状态替换和一次有 revision 的业务保存持久化，失败保留全部草稿及错误定位。
- 五入口只保留一个文本保存按钮，放在输入框可见边框内右下角，框外只显示状态；弹层中的参数保存只回局部草稿，不能变成第二个业务保存入口。保留原词条／例句整体编辑、译文、surface 影响确认及权限规则。
- 复用词条向导 `saveFlow.ts`、`api.ts` 和例句 create/update，不为五处分别新增保存 API。若宿主尚无 owner ID，先沿既有新建草稿流程建立身份；必要字段未齐时明确提示，不能先写半份配音。保存范围和其余未保存字段在宿主中明确管理，不以整表单旧闭包覆盖新正文。
- 点击前校验任务要求的每个口音均有实际可用已选项；明确不选推荐且池为空时整次拒绝，移除现有 local 空池继续 fallback 的行为。只要求当前业务目标的口音，不强迫单侧 IPA 额外填写另一侧。
- 词形拼写／IPA／UPS／语法／英文释义／共享例句分别保持已有稳定 target、读法来源和权限；不把显示用实际发音当合成源。读法失效仍提示修复。
- 发布继续消费当前主线的 `/publication-audio/check|confirm` 与集中审听，覆盖新有序已选池。改选、重排或参数生效值变化时旧确认失效；未选缓存不成为发布必需项。草稿保存不等于发布，局部试听 URL 不直接作为正式资产。

### 13.7 具体改动：任务合并、查词与练习播放

**持久任务**：复用 `speech/audio_updates.rs`、`audio_updates/worker.rs`，不重建任务系统。现有 enqueue 按 group ID 合并，worker 按 area 发现继承目标；新版组重排和多个重叠组会影响同一批目标，需要补齐跨提交合并。

- 内容保存／组删除／组顺序提交与任务登记同事务。通过提交前后整体顺序与有效来源确定受影响 area；所有相关提交按最终状态合并等待窗口，不能 A 改组、B 重排仍提前执行 A 的旧效果。
- 保留服务端 due_at、撤销、重试、租约与权限复核。撤销仅取消待执行任务，不撤回配置；取消后续草稿不取消已提交任务。
- 执行时重新解析最新最终声音并比较实际 SSML／生效参数／模型／格式 hash；名字变化、有效来源不变和改回原值不调用 TTS。排序／来源变化不必然意味着声音字节变化。
- 原子更新目标全部新声音就绪后的草稿引用；最终事务复核正文 revision、inherit 状态、组顺序和有效配置。保留已发布引用与旧音频；不绕过新主线的资产复用、回收及发布审听。

**查词与练习**：Web `dictionary/Content.tsx` 当前从返回数组 find 首个口音匹配项；`LearningTasks.tsx` 没有音频入口，`LearningQuestion` 没有音频或同目标题次字段。当前 `position` 是整个批次序号，不能直接当作同一词／文本第几题。

- 查词以已发布正文选用顺序输出同侧可用正式音频；保留 target、source_dialect、原生 locale 与当前 accent。不能只信资产插入顺序，也不能从草稿实时取推荐。
- 单一权重规则 `harmonic_v1`：过滤实际不合格项后，以同侧有效排名计算 `p(n)=(1/n)/Σ(1/k)`；五项约为 43.8%、21.9%、14.6%、10.9%、8.8%。无有效项明确不可播；不调用临时 TTS 或跨口音补位。
- 首题或未传题次固定首项；第 2 题起独立抽样。题次由学习服务按同轮次内同词／文本稳定目标计算，多个词义属于同一词时不能因换义项重新算首题；重练新 question ID 才增加题次，点击播放不增加。
- 抽样选择在服务端按 question ID＋口音首次固定并持久化，重播、刷新、并发重试返回同一结果；下一题才重新抽样。保留来源 publication／target／asset 身份和策略版本，音频引用参与现有保护／回收，不把选声写进判分答案或改变奖励。
- 用户已选择答后播放：新增受学习轮次归属、已作答状态、内容来源可用性保护的音频清单／签名读取，Web 在答案反馈区显示播放。答前无目标资产、URL 或正确词形泄漏；服务端直接请求也必须拒绝。端点在实施时选最小形状，不扩建通用音频服务。
- 学习音频必须读该题固定发布来源，不能拿当前最新词条代替历史题。无正式音频、已撤回／无权限或自定义词无平台配音来源时提示不可用，保留答题和历史成绩；不为满足轮换而另造自定义词合成系统。
- 同一个概率计算规则供 Admin 预览与正式消费核对，接口返回必要的有效排名／策略元数据，不持久化冗余概率数组。Admin 草稿与已发布内容可以不同，但同一配置下过滤和归一化必须一致。

### 13.8 契约、迁移与兼容方案

以下保留原评估设计；第一批已落实的契约与验证见 13.13，其余仍按后续批次实施，不能视为均已存在或完成兼容验证。

| 范围                     | 最小变化及边界                                                                                                                                           |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 分组读取／单组写入       | 新版配对身份与有序推荐；保留组 ID、revision 和单侧历史版本身份。基于现有能力协商升级表示；旧客户端不能拆散新版配对或覆盖共享板块配置。                   |
| 独立顺序命令             | 建议 `PUT /admin/speech/groups/order`，仅包含组 ID 顺序和 base_revision；先验证静态路由与 `/{id}` 路由不冲突。顺序 revision 与组内容 revision 分工明确。 |
| 推荐解析                 | 扩展现有 `POST /admin/speech/resolve`，返回优先级选中的推荐／来源和有效声音；移除两端仅第一个组的假设，以及新版局部无推荐空池的隐式兜底。                |
| 词条／例句 voice_profile | 尽量复用 voices、enabled、version_id 和 inherit/local；仅补无法推导的推荐来源／新语义标识。旧严格 schema、V3 投影、保存与发布同时对齐。                  |
| 参数有效投影             | 保留非生效参数与实际生成参数的边界，现有 preview／audio／SSML／prepare_effect 和发布检查使用同一策略；不增加另一套参数存储或放宽未知标记能力。           |
| 更新任务                 | 扩展现有任务归因／顺序变化和重叠 area 合并，不创建平行 worker。旧任务在迁移和执行时的处理必须明确。                                                      |
| 字典／练习               | 字典证明有序输出足够时不扩 DTO；否则仅补稳定来源／排序字段。学习扩答后音频及稳定题次／选声，沿用当前 learning 能力协商，答前 DTO 不增加答案信息。        |

迁移按依赖实施：

1. 配对／顺序与兼容读取：新增有界结构或版本标记，保留旧数据和引用；盘点并标记无法自动配对的组，不初始化新配置覆盖它们。
2. 局部池语义与任务变化：现有历史配置保持 independent；按显式编辑转换，不用“字段缺省”把旧文本变成 inherit。不因添加元数据自动重建全库音频。
3. 学习选声事实：记录问题、口音、来源与资产引用，唯一约束防重复抽样；旧题没有选声记录时在已作答且来源合法的首次请求中固定。不得绕过来源失效检查。

每组迁移都有隔离 up/down、旧引用及有数据后的回退拒绝测试。有新版配对、多组归属、池语义或学习事实后，不能直接降级到不认识新格式的旧 API；不通过删除业务数据使 down 强行通过。

统一运行原生 OpenAPI 导出，前端显式 `OPENAPI_SOURCE` 同步 endpoint 与 runtime schema；检查 `_source_sha256`，wire 仍是 snake_case。不会在评估阶段修改生成物或扩大 PENDING 白名单。

建议发布方向为先增加兼容读取和旧写保护的 API，再升级 Admin／Web，最后开放新版写入；这是待验证方向，不能提前承诺“两边都兼容”。发布前必须分别证明旧前端＋新 API、新前端＋旧 API、新前端＋新 API，以及回退组件＋新数据。无安全过渡组合时提交具体受控写入窗口方案；不默认停止共享服务。API、Admin、Web 的 manifest、候选 SHA 和精确 CI 分别记录。
