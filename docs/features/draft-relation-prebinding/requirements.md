## 背景与目标

当前最新词条功能的「词义与例句」中，关联词目前只能从 `related-search` 返回的当前发布词条中选择。管理员已经
创建了目标草稿、但尚未创建任何词义时，搜索看不到它；即使通过词面录入 pending，系统也只记
`pending_target_headword` 与可选 `pending_target_gloss`，没有记住“就是这个草稿”。这会产生两个
问题：

1. 同一词面只能表达模糊意图，无法证明后续绑定的是管理员当时选中的目标草稿；
2. 目标草稿补上第一条词义后，来源词条不会因目标保存而自动转正，仍要重存来源词条。

本功能要让管理员能在关联词搜索中发现目标草稿；目标草稿尚无词义时也能选中并形成带稳定目标
身份的预绑定。目标第一次成功保存词义后，系统在同一业务动作中自动把符合条件的预绑定转为
正式绑定。正式绑定始终依赖稳定的词条 ID 与词义 ID，不依赖会变化的词面或释义文本。

## 目标端与参与对象

- 目标端：Admin 当前最新词条创建/编辑器的「词义与例句」步骤。
- 来源词条：持有关联词 relation 的当前最新模型草稿。
- 目标词条：管理员从搜索候选中明确选择的当前最新模型草稿。
- 本轮不改变例句 `sentence associations` 的 pending/claim 模型；它与普通关联词 relation 是两套数据。

## 已确认的产品规则

1. 关联词搜索返回未归档的草稿候选，并在候选及选中态明确显示「草稿」。
2. 目标草稿没有词义时仍可选择；选择结果必须锁定目标草稿 ID，不能只留下同名词面。
3. 预绑定阶段没有 `target_sense_id`，但必须保留目标草稿身份、待关联词面与可选
   `pending_target_gloss`。
4. Admin 关联词表格第三列只显示现有 `pending_target_gloss` 输入，不新增稳定 ID 的可见输入；稳定目标
   草稿 ID 只由候选选择写入 wire/DB，用于身份与外键约束。
5. 目标草稿从 0 条有效词义变为至少 1 条时，无需管理员确认，自动把“等待第一词义”的预绑定转为
   正式绑定。
6. 正式绑定写入稳定的 `target_word_id + target_sense_id`；之后修改释义文本不改变绑定身份。
7. 已绑定词义被删除时，原关联立即失效并退回预绑定，保留目标草稿身份、词面与 pending gloss。
8. 删除后新建出来的词义即使排在第一，也不得被原关联静默采用；管理员必须显式选择新词义。
9. 当前最新词条模型的每条词义都可删除，包括第一条；本功能不得依赖“首条不可删除”的保护。

## 产品状态机

| 状态                                        | 稳定目标词条 | 稳定目标词义 | 词面 / pending gloss           | 自动动作                       | 发布含义                             |
| ------------------------------------------- | ------------ | ------------ | ------------------------------ | ------------------------------ | ------------------------------------ |
| `text_pending` 文本待建                     | 无           | 无           | 必有词面，gloss 可选           | 保持现有发布时物化能力         | 沿用现有规则                         |
| `prebound_waiting_first_sense` 等待第一词义 | 有           | 无           | 必有词面，gloss 可选           | 目标首次保存有效词义时自动转正 | 来源发布前必须先转正                 |
| `bound` 正式绑定                            | 有           | 有           | pending 字段不参与正式绑定     | 释义改文不换 ID                | 可按现有 relation 发布规则处理       |
| `prebound_detached` 已绑定词义被删除        | 有           | 无           | 保留绑定前快照形成的词面/gloss | **禁止**自动跳到别的或新建词义 | 来源发布被阻断，需显式重选或删除关联 |

目标 lifecycle 是与上述四态正交的可用性维度：目标一旦归档，原来的 `waiting_first_sense`、
`bound` 或 `detached` 身份均原样保留，只额外显示 `archived`。恢复后回到归档前的核心状态；归档和
恢复都不能清掉稳定 ID 或改绑同名词。

状态转移规则：

- 管理员搜索并选择一个 0 词义草稿：`text_pending/空行 → prebound_waiting_first_sense`。
- 管理员搜索并选择已有词义草稿，再明确选某个词义：`→ bound`。
- `prebound_waiting_first_sense` 的目标在一次成功保存中从 0 条变成 N 条：选择该次提交的产品顺序
  第一条，`→ bound`。
- `bound` 的目标词义只改文本、CEFR、排序或所在 POS 顺序，但 ID 不变：仍为 `bound`。
- `bound` 的目标词义被删除：`→ prebound_detached`；即使同一次保存里还有其他词义，也不自动改绑。
- `prebound_detached` 后又创建新词义：状态不变；只有管理员明确选择某个 sense 才回到 `bound`。
- 目标归档：保留稳定目标身份并显示不可用；不得退化成可能命中同名其他词条的文本 pending。
- 目标恢复：保留原身份。若原 sense 仍有效则可恢复正式可用；若原 sense 已删除则仍是 detached。
- 目标永久删除：存在任一预绑定或正式入站 relation 时禁止删除，避免稳定身份被物理抹除。

## “第一条词义”的产品权威

“第一条”不是最小 UUID、最早创建时间或最早发布时间，而是**目标这次成功保存后的 canonical 最新词条
内容顺序**：先按 `meanings.pos[]` 的产品顺序，再按各 POS 内 `senses[]` 的产品顺序；数据库等价
排序应为 `entry_pos.sort_order, senses.sort_order, senses.id`，最后的 ID 只用于异常并列的确定性
兜底。

如果一次保存从 0 条直接增加多条，按上述顺序只选择一条。之后重排不改变已写入的 sense ID。

## 用户故事与关键场景

### 主流程：选择零词义草稿

1. 管理员在来源词义中输入目标词面。
2. 下拉同时展示发布候选和草稿候选，每项有状态标识；同一候选仍以稳定 entry ID 去重。
3. 管理员选择“草稿 · 暂无词义”的候选。
4. 关联行进入预绑定，显示目标词面、「草稿 / 等待第一词义」和可选预定义词义；保存刷新后身份不丢。
5. 另一位管理员在目标草稿保存第一条词义。
6. 系统自动转正所有仍处于 `waiting_first_sense` 且指向该目标的 relation；来源词条出现未发布改动，
   重新打开可看到稳定的目标词条和词义。

### 目标已有词义

草稿候选仍带「草稿」标记，并列出其当前有效词义。管理员必须显式选择具体词义，直接形成正式
绑定；不能因为候选是草稿就默认取第一条。

### 已绑定词义删除

目标管理员删除任意已绑定 sense（包括第一条）并保存时，所有来源草稿中的对应正式绑定退回
`prebound_detached`。关联行说明“原词义已删除，请重新选择”，保留目标 entry ID、目标词面与
pending gloss。目标随后新增或重排词义都不能自动修复该 relation。

### 来源词条发布

- `bound`：沿用现有稳定 relation 发布与引用校验。
- `prebound_waiting_first_sense`：返回可定位到 relation 行的校验错误，不得为它另建同名占位词条。
- `prebound_detached`：返回“原目标词义已删除，需重选”的校验错误。
- 目标已归档：返回“目标已归档”的校验错误，指引恢复目标；不得改绑同名词。
- `text_pending`：本功能不取消现有“发布时物化未入库词条”的行为。

### 目标词条发布

- 发布不改变 entry ID 或 sense ID，因此已正式绑定 relation 不需要重绑。
- 目标发布版本包含已绑定 sense 时，relation 继续有效。
- 若目标已删除某个被其他来源当前 publication 引用的 sense，目标发布继续受现有入站 publication
  引用门禁约束；历史/current publication 不被本功能改写。管理员需先在来源草稿重选/删除关联并
  发布来源的新版本，再发布目标。

## 功能范围

### 本次范围内

- related-search 纳入未归档的当前最新模型草稿候选及明确状态。
- 0 词义草稿的选择、保存、GET round-trip 与 UI 常驻状态。
- 独立于文本 pending 的稳定预绑定身份。
- 目标首次保存词义时自动转正。
- 已绑定 sense 删除时退回不可自动转正的 detached 预绑定。
- 来源 revision、未发布改动、并发冲突、归档/恢复/永久删除及发布门禁的一致语义。
- wire、OpenAPI、数据库约束与索引、迁移/回滚、前后端测试和真实 API 验收。

### 明确不做

- 不给目标草稿自动创建词性、词义或默认内容。
- 不把当前最新模型草稿降级/转换成旧词条模型，也不复用“发布时创建旧模型 noun 占位”的路径处理已选目标草稿。
- 不修改历史 publication snapshot 或历史 `entry_publication_sense_refs`。
- 不因目标释义文本变化自动换 sense ID。
- 不为 detached relation 自动挑选新第一词义。
- 不改变例句关联、sentence discovery 或 pending sentence claim。
- 评审通过前不写业务代码、迁移、接口或测试代码。

## 约束与边界

- 预绑定身份必须是数据库外键保护的真实 entry，不能只是客户端缓存或词面解析结果。
- 状态转正/退回、目标 meanings 保存、来源 relation/投影更新、来源 revision 增量与审计必须原子；
  不允许目标保存成功而只转换部分来源。
- 自动跨词条写入后，已打开的来源编辑页必须因 revision 变化在下一次保存得到 409，而不能覆盖自动结果。
- 重复执行同一转正/退回动作必须是幂等的：第二次匹配 0 行，不重复 bump 来源 revision，不重复审计。
- 搜索游标必须感知草稿创建、词形/展示变化、词义变化、归档/恢复和删除；旧游标在数据集变化后拒绝。
- archived 候选不进入新搜索结果；已有预绑定不得因搜索不可见而丢身份。
- 正式 relation 与预绑定 relation 都要继续保持 relation UUID 稳定。
- 所有错误都要能锚定来源 relation 的 `node_id` 与具体字段，前端按当前最新词条功能的 issue 路由定位。
- 同步 reconciliation 每次最多处理 **500 条 eligible relations**；第 501 条起必须整体拒绝并返回稳定
  409，不得分批后让目标保存出现部分成功。

## 验收标准

- [ ] 精确/包含搜索均能返回未归档的当前最新模型草稿，响应明确区分 `draft` 与 `published`。
- [ ] 草稿候选在下拉、选中行、重新打开后的关联行都显示草稿状态。
- [ ] 0 词义草稿可选；保存后稳定目标 entry ID、词面与 pending gloss 均可 round-trip。
- [ ] 同词面文本 pending 与“已选择某个草稿”的预绑定可被后端严格区分。
- [ ] 目标从 0 条成功保存为 1 条时，所有 eligible 预绑定原子转为相同稳定 sense ID 的正式绑定。
- [ ] 一次新增多条 sense 时，以 canonical POS/sense 顺序的第一条为唯一目标。
- [ ] 并发创建第一词义时只有一个 revision 胜出；不存在两次转正、不同 sense 或部分成功。
- [ ] 转正使每个受影响来源 revision 恰好加 1，并设置 `has_unpublished_changes=true`（如有当前发布）。
- [ ] 释义文本修改、目标发布、词义重排均不改变已绑定 sense ID。
- [ ] 已绑定 sense 删除后原 relation 退回 detached 预绑定，保留目标身份、词面、gloss。
- [ ] 删除后新增新 sense 或把其他 sense 调成第一，均不会静默重绑。
- [ ] 来源发布遇 waiting/detached/archived 预绑定时给出稳定、可定位错误且不建新词条。
- [ ] 目标有预绑定/正式入站 relation 时永久删除返回 409；归档保留身份，恢复后可继续处理。
- [ ] 目标删除 sense 后若仍有来源 current publication 引用，目标发布继续被现有入站引用门禁阻止。
- [ ] 重复转换调用或重复内部事件不产生额外 revision/audit/outbox。
- [ ] 草稿搜索数据变化后旧 cursor 返回稳定的 400 `invalid_query`（field=`cursor`）。
- [ ] 旧的纯文本 pending 和正式 bound relation 数据迁移后行为不变。

## 成功指标

- 预绑定转正没有人工重存来源词条步骤。
- 不出现同名误绑、自动跳 sense、半成功转换或来源编辑覆盖自动转换。
- 已有 published-only 搜索、文本 pending 发布物化和正式 relation 发布行为无回归。

## 评审结论

1. detached 首期保留当前关联行，允许在同一目标词条内显式重选 sense 或删除关联；不做批量修复入口。
2. 采用选项 A：Admin 关联词第三列只显示 `pending_target_gloss` 输入，但 wire/DB 新增稳定目标草稿 ID。
   `pending_target_gloss` 继续只是可选释义文本，不承担身份语义。
3. 产品层统一称“当前最新词条功能/最新词条模型”；代码中的 `V3`、`v3`、`schema_version = 3` 仅为
   技术标识，不进入产品文案或功能分层。
4. 同步 reconciliation 硬上限为 500 条 eligible relations；发现第 501 条时整个目标保存返回 409 并
   全事务回滚，不允许前 500 条部分成功。
