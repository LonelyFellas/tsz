# 禅道 #88：用户管理权限细分

来源：<http://47.121.142.19/zentao/index.php?m=task&f=view&taskID=88>，以 2026-10-11 激活说明及附件为准。

## 范围与确认

- `users.access` 改为「查看全部用户名单」，说明为「查看平台内所有用户的昵称和注册时间」。响应保留 ID 作为定位用户的技术标识。
- 新增基本信息、余额、账单、身份证件四项权限；复用联系方式、封禁和编辑权限，不改变已有编辑功能。
- 用户已确认身份证件仅指教师认证中上传的身份证正反面，不新增普通用户身份采集。
- 用户已确认保留旧授权的可见范围，以一次性迁移补齐对应细分授权，后续各项独立授权与撤销。

## 依赖与方案

已有：用户目录、联系方式脱敏、封禁、天生币钱包与账单、教师认证私有文件。
新增：用户维度的受限钱包、账单、身份证件入口；按权限裁剪基本资料。
关键路径：后端权限/迁移 → API 契约 → 前端展示 → 隔离环境验证。

权限键：`users.read_basic`、`users.read_coin_balance`、`users.read_coin_entries`、`users.read_identity`，均依赖 `users.access`；已有 `users.read_sensitive` 和 `users.set_status` 保留键名；封禁依赖基本信息权限，以便操作前确认账号状态。
名单的头像、角色、认证状态、账号状态、更新时间仅在基本信息授权下返回；电话和邮箱继续独立控制。无基本信息权限不允许用角色筛选推断身份。
余额与账单使用独立请求；账单在无余额权限时不返回逐笔余额。身份证件仅返回最新已提交申请的身份证正反面，读取原件核验用户、材料类别、申请归属与当前权限。
天生币管理和教师认证模块的既有权限仍保留原有业务范围，新用户权限不会授予这些模块的管理能力。

## 迁移与兼容

旧 `users.access` → 补 `users.read_basic`；同时有 `users.access` 与 `coins.access` → 补余额、账单；同时有 `users.access`、`teacherapply.access`、`teacherapply.read_sensitive` → 补身份证件。授权版本递增，使客户端刷新权限。标签按相同规则补齐。
回滚如会使仅名单授权恢复为可读基本信息，必须拒绝，先人工核对。新权限随回滚删除。
后端先发布时，迁移后的旧用户字段保持可见；启用新细分授权前需完成前端更新，避免旧客户端假定基本字段必填。新前端连接旧后端时，新权限不存在，不请求新接口。
