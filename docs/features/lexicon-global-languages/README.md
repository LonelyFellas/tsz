## 账号存储与接口

复用 `GET /api/v1/admin/profile` 和 `PATCH /api/v1/admin/profile/preferences`。

- `preferences.lexicon_languages` 是完整组合 `{ target_language, target_locale, medium_locale }`。新后端恒返回该字段，`null` 表示尚未设置；旧后端省略该字段。
- PATCH 仅提供时更新，不接受 `null` 或部分组合，按现有词库语言能力验证。`lexicon_languages_if_unset: true` 仅用于旧缓存首次导入，不覆盖账号已有值。
- 目标始终是 token subject，继承 active session / security_version 守卫，不接收管理员 ID。其他偏好字段独立原子更新。
- 数据保存在 `admins.lexicon_languages` JSONB；新增迁移 `20261114120000`。up 不改旧偏好或词条；down 删除新语言偏好，不能当作无条件无损回退。

## 恢复、同步和并发

1. 每次进入词库先重新读取账号值，再补齐缺少的 URL 参数，之后才加载业务数据。账号值优先于本地旧缓存。
2. 账号尚未设置且旧浏览器缓存有效时，用条件初始化导入；另一个设备已保存的选择不会被旧缓存覆盖。无缓存的新客户端使用账号值或目录默认值。
3. 显式链接和历史只临时覆盖当前视图，不自动反写账号。主动切换顶部选择且导航真正生效后才保存；取消未保存离页会取消本次保存意图。
4. 同一会话的写入串行执行，离开页面后继续完成。旧账号/旧 generation 的排队请求不发送，迟到结果不回填；只合并当前 profile 的语言字段，保留并发更新的其他偏好和授权事实。
5. 晚到的读取不能覆盖后续主动保存。保存失败保留当前选择及未同步提示，可重试；再次进入不会把失败误判为已同步。新读取确认账号已是目标值时清除未确认状态。
6. 旧 API 未提供字段时保留原浏览器模式并说明限制；读取失败可重试，尚未确定范围时不加载错误范围的数据。

词条 `medium_locale` 归属保持不可变，英美目标变体仍共享英语词条。现有初始归属迁移规则不变：仅繁体内容归繁体，其余归简体；所有正文和历史保留。

## 可观察验收

- 无缓存客户端从账号恢复，首个列表请求就使用正确范围。
- 两个独立登录会话各有独立浏览器存储，一端主动选择后，另一端重新进入可读取并恢复；旧标签刷新不能覆盖新账号值。
- 快速连续切换最后得到最新完整组合，离开页面后完成保存；跨账号迟到响应和旧排队请求不串用。
- 取消跨媒介离页不写账号，确认离页后才写。读取/保存失败均能重试，保留输入和原业务状态。
- 真实 PostgreSQL 验证账号持久化、自身权限、原子部分更新、条件导入及迁移 up/down 的影响。
