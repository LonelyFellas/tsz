# 连读弧微调

后台的「微调连读弧」独立于连读添加和清除模式。进入时默认选第一条弧；有多条时可点弧腹或用列表选择。碗形弧线只有一个滑杆，默认调整条弧的深浅。点端点或选择「左端点 / 右端点」后，滑杆只调整该端的高度，不改变横向锚点或另一端的位置。端点能到达墨迹时，最低档为「贴字」；没有墨迹或受其他字形限制时不标为贴字。

拖动时按实测字形预览，松开才提交一次编辑，整次手势可一步撤销。「当前弧回到推荐」同时恢复这条弧的整弧和两个端点，可撤销，不影响其他弧。软换行显示默认半弧，保留原调整，回到同一行后再使用。编辑器和只读视图共用布局，字体、字号和可用行距决定最终像素。

## 富文本契约

通用富文本 V2 和 V3 DTO 的 `liaison` 注解使用可选的 `bowl` 对象。下面三项均为 `[-100, 100]` 的整数，缺省为 `0`，序列化时省略零值。对象不能为 `null`，未知键或越界值无效。

| 字段                 | 含义                                               |
| -------------------- | -------------------------------------------------- |
| `bowl.curve_pct`     | 负值更平，正值更拱，0 为依据跨度和字形得到的推荐弧 |
| `bowl.left_tip_pct`  | 左端在本地字形允许范围内的上下位移，正值向上       |
| `bowl.right_tip_pct` | 右端在本地字形允许范围内的上下位移，正值向上       |

`bowl: {}` **需要保留**：表示使用推荐碗形。没有 `bowl` 的存量弧继续用既有算法绘制，原 `left_offset_pct` / `right_offset_pct` 仍表示左右半弧高低，不会被解释成端点位移。新建连读使用推荐碗形；打开、选中旧弧不会改数据。首次实际调节或点「使用推荐碗形」才转换这条弧，并移除它的旧偏移。若输入同时带有两种配置，显示优先使用 `bowl`。

`start`、`end`、`start_len`、`end_len` 仍决定锚点和去重。展示配置不参与语音合成、音频来源、试听缓存身份或重复弧排序。V3 草稿和发布快照保留 `bowl`；无需数据库迁移。

## 配套发布

后端先上线：没有 `bowl` 的旧数据输出仍兼容现网前端。全部后端实例接受该字段后，再发布 Web/Admin。新前端可以读取旧后端的数据，但新建或转换碗形后向旧后端保存会被拒绝。开始写入前，严格 schema 消费者（含旧后台标签页）需更新；首次写入后，不能直接回退到拒绝 `bowl` 的旧程序，须保留兼容读写能力或另行准备经授权的数据恢复方案。前端发布契约钉点在配套后端合入后更新，不指向未提交的候选。

## 验收路径

使用隔离 `intermediate` 副本的四条原音标，并存放无配置旧弧、有旧偏移的弧、推荐碗形和调整后的碗形。检查选中不改数据、单条转换、整弧深浅、两端分别贴字、一次拖动一次撤销、恢复推荐、保存与刷新后的独立 GET、实际字号只读路径和跨行设置保留。不得向测试服原词条写入本地验收数据。

本地真实后台已用同一草稿混合四条新旧标注验证：仅选中旧弧不改路径，主动转成碗形后保存并刷新，两端 `-100` 与整弧 `100` 原样回读，其他旧偏移和明确的空碗形配置均保留。双弧编辑中单条选择、端点命中、375px 宽跨行禁调及展开恢复已验证。
