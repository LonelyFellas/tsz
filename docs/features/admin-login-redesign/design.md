## 用户的选择原话

> 「你根据你的审美，你推荐一个吧」

用户把选择权交回，要求给出推荐。随后追加一条要求：

> 「可能需要带一点响应式吧」

看到混版三档截图后：

> 「开工」

## 推荐的方向与理由

**标杆版骨架 + 设计师版色阶的一条残留**。

推荐理由：这道门每天被同一个人穿几百次，成功标准是不被注意到。轮盘版的巨字与
设计师版的整张色阶表都是「要被看」的设计，第三百次会烦。三版里只有标杆版把自己
做成了通道而不是展品。

但标杆版缺身份——抠掉「天」字标记，它可以是任何一家 SaaS 的登录页。所以补一条
六段色阶线：难度级阶是这个产品唯一独有的视觉资产，但它该是签名不是主体。

## 落地范围

- 保留：三要素 2FA 的全部逻辑、60s 倒计时、423 锁定置灰、must_change_password
  跳转、redirect 参数安全校验、原生表单提交（密码管理器识别）、inFlight 竞态防护。
  **这些一行都不改。**
- 改动：仅 UI 结构与样式；撤掉组件里手写的圆角与阴影，改由 token 承担。

## 第二轮：按商业标准重做（2026-09-11）

第一轮的读者假设「每天穿门几百次的自家编辑」被用户推翻。用户明确：这个后台
「可能内部广泛的给 C 端用户用，不只是为了卖给谁」，因此不押注单一买方，
按「对内部编辑 / 采购方 / C 端用户三类都成立」重做。

### 触发重做的三个实测指标

第一轮交付版本实测：视口占用 20.9%（空场 79.1%）、页面动效 0 个、
字号跨度仅 2.1 倍（最大 25px）。用户评价「比之前好看很多，但对于一个商业产品
来说差的有点远」，三项数据正是差距所在。

### 零编造铁律

用户回答可展示的真实素材时是「什么都没有」：无客户 logo、无合作机构、
无可公开的词条总量。因此三版一律禁止机构数、用户数、词条量、logo 墙、评价、
伪图表。填版面只用产品自身真实结构（词性分裂、英美双拼、国际音标、CEFR 六级色阶、
标记语言）。**一个编的数字比空着更伤。**

### 用户的选择原话

> 「设计师版」

### 选定方向：字典样张

整页是一张字典对开样张：通栏天头版压顶，下面白底三栏配栏线，**登录表单是这张页的
中栏**，与左右两栏共用同一根左轴、同一套栏线与注记体系。三个字段排成三个义项
（1 手机号 / 2 验证码 / 3 登录密码），复用左栏词义的蓝色义项号。

选 Typotheque 的理由：字体样张是唯一一种不靠数据完成销售的版面——不放销量、
不放客户 logo、不放推荐语，只把真语言按真尺寸摆出来。这正面回应了零编造铁律。

### 已知取舍（落地时需复核）

设计稿自陈：输入框边框用品牌色板的蓝灰 `#BFC0CA`，对白纸对比度仅 1.81:1，
低于 WCAG 1.4.11 对非文字控件的 3:1 要求。这是「不发明新颜色」与无障碍规范之间的
取舍，稿子选了前者并靠 `#EAF9FF` 底色补足可见性。**落地前需用户裁定。**
