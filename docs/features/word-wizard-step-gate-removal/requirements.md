# 创建单词向导取消步骤顺序门禁：需求评估

## 背景与目标

创建单词向导有四步：创建新词条 → 词形与发音 → 词义与例句 → 预览并生效。当前**必须逐步完成才能进入下一步**：词形与发音没做完，顶部的「词义与例句」是灰的，点了完全没反应。

这个限制在实际录入中不合用。管理员的工作方式并不是严格线性的：

- 词形与发音要查词典、补音标、逐个词形填读音，是**慢活**；而词义与例句往往是他手上现成的资料，想先录进去。
- 音标一时查不到、或要等别人补，整条词条就卡住，后面什么都干不了。
- 想先看看第 3 步长什么样、要准备哪些材料，现在连看一眼都不行。

目标：**四个步骤之间自由跳转，任何一步都能随时进入、随时保存草稿**。完成度由「完成情况」面板如实呈现，不用导航权限来强制顺序。

成功长什么样：一个只填了词性、音标还没查的草稿，管理员可以直接切到词义与例句把释义和例句录进去并保存；回到词形与发音继续补音标；两边都齐了再发布。

## 目标端

**admin**（管理后台，antd v6）。web 端不涉及。

需要**后端配合**：当前拦截是双层的，后端在保存词义步时会直接拒绝（详见技术设计文档的「后端对接建议」）。

## 用户故事 / 使用场景

1. **先录词义**：管理员在词形与发音只添加了「名词」、音标还没查，想直接切到词义与例句录入释义与例句 → 点顶部第 3 步能进去、能填、能「保存草稿」，完成情况里词形相关项照旧显示未完成。
2. **来回补录**：管理员在第 3 步录完释义，切回第 2 步补音标，再切回第 3 步继续 → 两边内容都在，互不干扰。
3. **只想看看**：管理员想确认第 3 步需要准备什么材料 → 直接点进去浏览，不填任何东西离开，不产生任何写入。
4. **发布仍然守门**：管理员在有内容缺失时点「提交生效」 → 被完整性检查拦下，明确列出还差什么；补齐后才能发布。
5. **从完成情况跳转**：管理员在完成情况面板点「多维例句 0/1」 → 直接跳到第 3 步对应位置（今天越界会静默失效）。

## 功能范围

**做**：

- 取消向导顶部步骤条的顺序禁用，四步随时可点。
- 取消直接输 URL 时被弹回 `max_reachable_step` 的重定向。
- 取消「完成情况」面板跳转的越界拦截。
- 让任意步骤都能「保存草稿」（`intent: "save"`）。
- **补第 3 步的零词性空态**：词义按基本词性组织，没有词性时给出说明与跳回第 2 步的入口（决策 1）。

**不做**：

- **不放宽发布门**。「提交生效」仍然必须通过完整性检查，`validate_forms` + `validate_meanings` 一条都不少。
- **不放宽「完成并进入下一步」的校验**。该按钮语义是「把这一步标记为完成」，仍然要求这一步内容合格（`intent: "complete"`）；只是它不再是进入下一步的**唯一**途径。
- 不改「完成情况」面板的计算口径，也不改各步骤内部的表单校验。
- 不改已发布词条的只读/编辑模式规则。
- 不新增「跳过本步」之类的显式操作，也不做引导性提示。

## 约束与边界

- **发布安全不能降级**：发布时后端会独立重跑 `validate_forms` 与 `validate_meanings`（不依赖 `completed_steps`），这是防止不完整词条上线的真正门禁。本次改动不碰它。
- **词义内容依赖词形的词性列表**：词义按 `pos_id` 组织，语法结构挂在词性下。因此**结构上的前提是「至少有一个基本词性」，而不是「词形与发音已完成」**——这是本次放宽的关键区分。
- 已有的下游影响机制不变：在词形步删除某个词性时，仍走「下游内容影响」确认流程。
- 已发布词条（`published` 且非显式编辑模式）仍固定停在预览步，本次不动。
- 权限不变，不引入新角色或新接口鉴权。

## 验收标准

- [ ] 一个只有词性、词形与发音未完成的草稿，点顶部「词义与例句」能进入。
- [ ] 在该状态下第 3 步能编辑并「保存草稿」成功（不是 409）。
- [ ] 完成情况面板如实显示词形相关项未完成，不因为进入了第 3 步而变绿。
- [ ] 从第 3 步切回第 2 步，两步内容都还在。
- [ ] 直接在地址栏输入 `/words/<id>/wizard/meanings` 不再被重定向回 forms。
- [ ] 完成情况面板点击未完成项能跳到对应步骤（含越过当前进度的项）。
- [ ] 内容有缺失时「提交生效」仍被完整性检查拦下，并列出缺什么。
- [ ] 「完成并进入词义与例句」按钮行为不变：内容不合格仍然报错、不放行。
- [ ] 词形步没有任何基本词性时，第 3 步显示空态说明并能一键跳回第 2 步，不是空白页。
- [ ] 除该空态外，不新增任何「你跳过了未完成步骤」类的常驻提示。

## 决策记录

原开放问题 1–3 已评估并定案（2026-08-21）：

### 决策 1：零词性时，第 3 步显示空态 + 跳回第 2 步的入口

**做法**：`content.pos.length === 0` 时，在词性 Tabs 之上显示一条 `Alert`（`type="info"`），说明「词义按基本词性组织，请先在词形与发音添加第一个基本词性」，并提供跳回第 2 步的按钮。只读态用不同文案（陈述事实，不催办）。

**理由**：

- **这是必须补的，不是锦上添花**。第 3 步现在**完全没有零词性处理**（第 2 步有，`FormsAndPronunciationStep.tsx:2777`）。门禁拿掉之前这条路径进不去所以不暴露；拿掉之后就变成一个真空白页。
- 镜像第 2 步已有的写法（同样的 `Alert type="info" showIcon` + 只读/可写两套文案），不发明新模式，视觉与措辞自然一致。
- 给按钮而不是只给一句话：门禁拿掉后跳转本来就可行，能让用户就地闭环，不用自己去找顶部 Tab。

### 决策 2：不做通用的「正在跳过未完成步骤」提示

**做法**：除决策 1 的结构性空态外，不加任何常驻横幅。

**理由**：

- **这件事已经有人在做**——「完成情况」面板常驻左侧、逐项显示进度，再加一条横幅是重复催办。
- **正常录入过程中「上游有未完成项」几乎恒为真**，横幅会变成永远存在的噪音，反而稀释真正需要注意的提示（例如「英式暂无可用发音人」那条）。
- 真正该拦的是发布，而发布有完整性检查并会**列出具体缺什么**，反馈比一句泛泛的横幅精确得多。
- 唯一值得单独提示的是结构性阻塞（零词性），已由决策 1 覆盖。

若日后产品仍想要，建议做成「离开向导时」或「点提交生效时」的一次性确认，而不是常驻横幅。

### 决策 3：保留 `max_reachable_step`，前端 `wordRouting.ts` 不动

**做法**：字段保留，后端推导逻辑不动；前端只是不再拿它做导航判断。

**理由**：

- 本次之后它在前端只剩一个消费方——列表「继续创建」的落点（`wordRouting.ts:28`）。那个用法**仍然正确**：落到第一个未完成步骤是合理的续做默认值，不是门禁。
- 字段名与新语义已不吻合（不再是「最远可达」而是「续做落点」），但重命名/废弃属契约变更，由后端单独评估，不夹带进本次。
- 改 `wordRouting` 去自行从 `completed_steps` 推导没有用户可见收益，只增加回归面——违背外科式改动。
