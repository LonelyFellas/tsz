本次经验：

- **没有外部调用不等于死代码。** 要继续查同文件内部调用、barrel、包 exports、框架入口和测试辅助；扫描结果只能提供候选。
- **删实现时迁移测试要一起完成。** 旧详情 hook 只有测试在使用，而旧缓存键还藏在创建页测试里；定向测试与全仓类型检查各自发现不同问题。
- **复用必须保持副作用范围。** 删除和归档都失效词条数据，但删除只触及集合，不能因共用 helper 而重取仍活动的 V3 详情。
- **测试应证明结果。** 列表、统计、创建人实际更新和详情不重取，比 `invalidateQueries` 调了几次更接近真实风险；重复场景合并后仍保留请求身份与幂等语义验证。
- **全绿不抹掉历史失败。** 当前通过与近期多次超时可以同时成立；失败、后续通过、未复现根因分别记录。
- **清理不扩大到他人工作树。** 未提交源码、设计和部署回执都可能有价值，先确认版本和归属，再由原任务处理。
- **查询方式需要实测。** 角色、标签和值查询各有适用位置；本次标签关联扫描是热点，但不能据此全仓替换。缓存 DOM 节点后要确认未被重建，否则可能在断开节点上得到假阳性。
- **对照试验要移除探针。** CPU profiler、额外查询和打印本身会增加开销；只有撤回探针后同模式完整运行的结果用于最终性能对比。
