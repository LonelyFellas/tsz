## 清理经验

- **判断是否保留看实际调用链。** 只有测试引用的业务函数应检查是否退役；既有测试数量和覆盖率不能证明用户还在使用它。
- **删掉旧入口后继续查间接依赖。** Web 不再使用 Zod，不代表工具链不再安装 Zod；完整审计和生产审计都要重跑。
- **保留有效行为的回归。** 删除死函数的专属测试；混合测试拆掉对死函数的依赖，继续保护现行功能，不为测试减量删除业务断言。
- **重构按职责与状态边界推进。** 先确定数据所有权、请求入口和可观察结果，再处理大文件，避免只搬动代码却保留重复模型。
- **证据绑定版本和环境。** CI 绿、构建绿、standalone 启动成功、真实后端联调各自证明不同层面；历史报告和基线 CI 不代替本次变更验证。
