# CI 等待与续跑

仅在用户已经要求部署、目标 CI 正在运行时读取本文件。

优先创建或复用绑定当前线程的 heartbeat；先发现可用 automation 工具并按其实际 schema 调用。
查找同线程、仓库、目标组件已有监控，避免重复；提示词需保存绝对 checkout、目标环境、组件、SHA 与已完成阶段。

每次运行：

1. fetch 并核对 GitHub 最新 main；若 SHA 前进，重新检查新 SHA 的最新 CI，不使用旧结果。
2. CI 仍在运行时保持等待；状态未改变不重复通知。
3. CI 非成功终态、无记录或查询异常时停止监控并说明，不部署。
4. CI completed/success 后按 SKILL.md 继续原部署任务；不能再次要求用户发部署指令。
5. 成功、失败、部分部署或需用户决定时结束监控，保留各组件完成状态与失败阶段，防止下轮重复部署。

短时间等待可使用可中断、单次不超过 60 秒的工具等待；不要无限 shell 轮询。
只有工具确认创建成功后，才能承诺自动续跑。工具缺失时准确报告限制与当前 CI 链接，不虚构后台任务或改成另一个独立 cron。
