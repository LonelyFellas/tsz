# 真实后端验收

当用户要求前后端联调、真实 API 验收，或本次风险无法由 mock/契约测试证明时读取。
现有 `e2e/playwright.admin.config.ts` 下的 admin 测试通过 `page.route` 模拟 API，不能作为真实服务验收证据；保留这套快速回归，不直接移除它的拦截。

## 验收前固定环境

- 从可用技能定位 `dev-env`，核实本次前后端 checkout、实际构建/进程版本、URL、代理和数据库/Redis 隔离。若该个人技能不可用，按下面的必要条件检查，不跳过环境核实。
- 后端进程必须确实加载目标代码；本地 HEAD、导出的 OpenAPI 或 health 返回成功都不能单独证明这一点。
- 启动后端会自动跑 migration；先确认隔离数据目标和迁移影响。仅要求验收设计时不启动服务、不写数据；已明确要求在指定隔离环境完成联调时，必要登录与测试数据操作沿用该授权。
- 使用现有测试账号或授权凭据，记录 fixture 归属与清理方式；缺少凭据时完成无需登录的检查，准确标注其余未验证，不索取明文密码到报告中。
- web 使用生产构建加 `next start`；admin 按实际 launch mode 核实代理。Vite dev 的路由配置不能作为 preview/生产路由已正确的证据。

## 建立一条真实请求链

关闭目标路径的 mock：检查构建时开关、请求 client 装配、Playwright route、service worker 与 fixture。
admin 相关的 `VITE_ADMIN_WORDS_MOCK`、`VITE_ADMIN_PART_OF_SPEECH_MOCK`、`VITE_ADMIN_TTS_MOCK` 应为 false；用实际 Network 响应确认。
web placement 等直接创建 mock client 的路径即使开关关闭也仍是假数据，应报告接线缺口；不能在验收任务里顺便实现整套后端。

根据改动选最小有效链路，不要求每次穷举：

| 改动                  | 真实路径与证据                                                                                                  |
| --------------------- | --------------------------------------------------------------------------------------------------------------- |
| 登录/refresh/路由守卫 | 浏览器登录 → 同源代理 → 正确角色 API；检查 cookie path/domain/Secure、刷新与页面跳转，报告脱敏结果              |
| 词条/标注编辑         | 创建或选择本任务 fixture → 编辑保存 → 独立 GET/刷新重新加载；核实保存字段、服务器持久化结果与 UI 一致           |
| 搜索/关联/发布        | 选目标路径及必要开关，验证真实返回、权限和失败表现；发布等状态变更只在已授权测试数据中执行                      |
| 契约/异常处理         | 实际状态码、Problem Details、nullable/枚举与 runtime validator 相符；保留被拒字段和错误位置，不泄漏原始敏感响应 |

记录浏览器入口、method/path、状态码、必要的脱敏响应与关联日志。后端 handler 测试可补充存储/并发证据，但不能替代页面实际走通。
需要区分缓存/乐观更新时用重新请求或重新打开页面确认，不只看「保存成功」toast。

## 工具选择与结束

一次性验收可用可用浏览器工具并记录步骤；反复发生的真实路径再考虑独立 Playwright 项目/fixture。
确需自动化时先检查现有 e2e 配置，不把原有 mock 测试全局改成连真实库；新模式显式选择环境，并验证复用 server 的来源。
浏览器工具不可用时报告只完成 HTTP/契约验证，不能写成浏览器已验收。

恢复本次修改的测试状态、清理确属本任务的数据/进程，保留用户要求继续使用的环境。不能批量删除共享数据或杀掉原有服务。
报告实际版本组合、真实链路、通过/失败/未验证、fixture 与清理结果。前端、后端分别通过测试不等于真实联调通过。
