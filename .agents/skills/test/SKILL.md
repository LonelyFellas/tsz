# 测试：先确定要证明的行为

## 1. 复用已有证据

读取相关设计、改动、调用链和附近测试。先明确目标行为、可能的回归与已有证据。
简单改动用短清单，复杂流程再用「场景 / 输入与前置 / 预期 / 现有证据 / 待补验证」矩阵；不要求固定行数。
只选择本次真实涉及的权限、异常、边界、状态流转或并发风险。一个测试可以证明多个相关行为。

Bug 回归先证明旧实现失败，再证明修复后通过。纯文案、静态样式等可逆低风险变化可用直接检查，不为流程额外造测试。
仅要求测试设计时，完成设计就交付，不擅自写实现或运行会修改真实数据的操作。

## 2. 选择最低成本且有效的层

| 层   | 适用证据                                               |
| ---- | ------------------------------------------------------ |
| 单元 | 纯函数、校验、mapping、状态与 token 逻辑               |
| 集成 | 组件与 Query/store/请求交互、表单、路由守卫            |
| 契约 | method/path、wire 结构、枚举、可选性、状态码与 OpenAPI |
| e2e  | 关键跨页用户路径；复用现有 mockApi 支持                |
| 手测 | 视觉、真实服务、浏览器或存储行为，记录步骤与结果       |

不把 mock 自洽当成真实 API 正确。后端契约有疑点时读取 tsz-rust 对应实现与测试；
需要跨仓修改则遵守用户范围和该仓约定，用 Rust 原生命令验证后端，不套前端覆盖率规则。
明确要求联调、真实 API 验收或 mock 无法覆盖本次风险时，读取 [真实后端验收](references/real-backend-acceptance.md)。

## 3. 实现有价值的测试

- 沿用邻近测试的 providers、fixture 与 mock 位置；web 的 Next 路由和 admin 的 React Router 不混用。
- admin 保留 antd 的 matchMedia/ResizeObserver 垫片；两字按钮允许空格，大表格避免昂贵的 role 查询。
- 断言用户可观察结果、请求契约或公开行为；异步等待最终状态，不断言私有实现，不弱化输入来变绿。
- API 变化读取本仓 [contract-sync](../contract-sync/SKILL.md)，核实两仓 checkout 后按原生流程同步并验证契约；只读核对请求不执行生成。
- `PENDING` 只记录后端确实尚未提供的端点及原因，不能掩盖已实现端点的不一致。

## 4. 验证与交接

迭代使用单文件或受影响包的测试；共享包变化检查相关下游。
没有紧接 ship 时，代码/测试变化在完成前跑一次 `pnpm test:cov`；紧接已授权 ship 时由其原生 pre-push 承接，不在两个技能中各跑一次。
已通过的检查在代码、配置、依赖或环境未变化时可复用；修复后先跑受影响检查。hooks 始终正常运行。

覆盖率要求读取当前 Vitest 配置；不写死会过期的应用百分比。不降低门槛、不 exclude 有分支逻辑、不跳过失败测试。
本地 e2e 仅在用户要求或关键风险需要时运行，其余由 CI 承接；未运行的检查明确标注。

报告已证明的行为、命令与结果、仍未验证的风险；不要把计划中的测试写成已通过。
