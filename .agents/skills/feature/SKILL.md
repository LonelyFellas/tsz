# 新功能：查清依赖，实施到约定终点

通用分档、任务记录、分支、授权与验证复用遵循 [AGENTS.md](../../../AGENTS.md)，不在各阶段重复评估或确认。

## 1. 查清剩余工作

- 核对当前 checkout、相关源码与测试，把已有能力和未就绪依赖分清；已有本任务方案、分支和记录直接复用。
- 接口以选定 tsz-rust 的 `docs/openapi.json`、实际实现、`docs/frontend-integration.md` 与前端快照为依据；旧 tsz-go 文档只作参考。
- 跨仓目标查清两端实际消费者与版本，先确定契约/权限/迁移和兼容策略，再处理依赖的实现。跨仓记录集中在任务主仓，另一仓引用。

## 2. 必要设计后直接实施

按项目分档记录目标、范围、主流程与关键异常、可观察验收、文件/接口影响及剩余依赖；涉及配套发布再写兼容、顺序和回退限制。已有记录补缺项，不重新写一套需求/设计。
需求明确且在授权内就实施；只把影响范围或产品行为的未决取舍交给用户，不要求单独批准常规技术方案或更换会话。

按实际依赖修改类型、请求、共享逻辑和页面。保持 snake_case wire、鉴权内核及 web/admin UI 分工；后端配套在其任务 checkout 按该仓规则处理。

## 3. 验证并连续交付

使用 [test](../test/SKILL.md) 选择最小有效验证，边实现边运行定向检查；接口变化使用 [contract-sync](../contract-sync/SKILL.md)。同状态结果及最终门安排按项目规则共享，不每个技能各跑一次。
跨仓功能按 [真实后端验收](../test/references/real-backend-acceptance.md) 验证相关用户链路；接口未实现或环境不具备时明确缺口，mock 不算真实联调。web 使用生产构建与 `next start`。

当前 Agent 对照验收标准核对结果和未验证项，不另加独立 reviewer。已授权交付就继续 [ship](../ship/SKILL.md)；配套发布复用 [配套发布清单](../contract-sync/references/paired-release.md)，部署按目标仓技能执行。
报告达到的约定终点、实际验证、剩余依赖与各仓状态，不自动扩大交付范围。
