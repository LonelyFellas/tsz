# Admin 智能词库 Agent：编辑体验与首轮生成质量

2026-11-26｜本地隔离实测｜英式英语 → 简体中文

**判断：保留为编辑起稿工具；不把「生成完成」当作「词条完整」或「可发布」。** 实测三个新词条，两个有可用草稿，一个没有任何候选；没有一条达到本次的「无需实质返工」标准。强项是按已有词义写例句和译文，弱项是发现漏义、异读、细分词性、拓展词关系，以及在上游失败后指导编辑恢复。

## 怎样评

- 从 Admin「创建词条」进入，检测词面、确认创建空白草稿，在「词形与发音」打开「词条助手」，各点击一次「生成整个词条」。三条均不手工预填答案，不重新抽样、不发布。
- 样本事先选择：`lantern`（普通可数名词），`lead`（多词性、同形异音、不规则过去式），`take off`（短语动词、及物/不及物用法）。评的是编辑可用性，不是登录用户满意度调查，也不是全词库准确率。
- 评分：**5** 可直接采用；**4** 轻微润色即可；**3** 多数内容可复用，但须纠正实质问题；**2** 有可用局部，核心覆盖要补建；**1** 无可用草稿。用同一把尺评首轮，不以条数、HTTP 200 或模型自评分代替质量。
- 环境：Admin `582f1ba1`、Rust `3358ef9`、Agent `2311d56`、实际模型 `deepseek-flash`。专用账号、独立业务库和 Agent 库；开始时没有已有词条或内置词典语料，短语有项目原生词性目录。在线词典按当次返回记账，不把来源标签当作取证成功。3 个整词 run 共 23 个带供应商 token 回执的板块，输入 19,718、输出 3,240 tokens；未推算金额。

| **lead**     | 2 个词性、7 个词形项、11 个词义、11 对英中释义/解释、22 对例译。拓展词为 0。                 | **2/5。** `lead–led–led` 正确；比赛领先、线索、主角、狗绳等义可用，`Poor planning led to serious delays across the project.` 很适合作“导致”的例句。但两个词性下的原形都只有 `/liːd/`，没有金属“铅” `/led/` 的词义或异读提示。参考面板显示还有形容词，候选未涵盖。词义及例句已有 _lead to + 结果_，语法候选却没有相应的不及物结构。若同形异音需拆条，编辑仍需要系统明确提示另建，而不是无声遗漏。 |
| **take off** | 10 个板块中 2 个显示“已完成（0 项）”，另 8 个失败；所有板块合计 0 候选。空草稿仍是初始版本。 | **1/5。** 既没有“飞机起飞”，也没有“脱下衣物”，无法评语言准确性，只能判本次起稿不可用。直接证据：词形为空、词义返回校验失败，随后依赖词义或例句的板块连锁失败。当次也没有取得在线词典正文；未通过重试或更换目录做因果对照，不能断定唯一原因，更不能推出所有短语都失败。                                                                                                                           |

来源：`lantern` 取到牛津、剑桥正文；`lead` 仅剑桥；`take off` 四家均未提供正文。有道三轮都未配置，韦氏三轮都不可用，智能词库三轮均无内部匹配。因而本抽检**不评**已有海量词库时的命中率、已发布词义关联质量、音频听感或其他语言组合。

## 设计与交互

| 编辑动作       | 观察到的行为                                                                                                                                                                        | 对编辑意味着什么                                                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 从零开始录入   | 创建页区分「已有词条」与「内置词典」，无命中也可确认创建。新草稿页头有「词条助手」，先展示生成范围，再单独确认整词生成。                                                            | 从空白到生成的路径清楚，不会误创建后直接消耗额度；此处值得保留。各字段的单板块生成主要是星光图标，初次使用不容易知道可以只补一项（源码走查）。            |
| 查看、采用结果 | 整词有有效候选时会自动回填本地草稿；单板块有单独的「一键配置」。整词结果主视图展示词形，其他板块主要看进度和数量；没有仅撤销本批的动作。                                            | 单词 `lead` 十个板块都显示完成，仍漏掉核心异读。建议显示「增加／保留／待核查」的逐板块差异，允许编辑按板块采纳或撤回本批。完成是技术状态，不是质量结论。  |
| 审核词典依据   | 面板区分词典来源，也能显示“未配置”“未命中”“不可用”；但资料属于整批，候选释义没有逐项引用。                                                                                          | 可以核对“查过哪本书”，不能直接判断“这条释义是否有依据”。优先给异读、冷僻词和拓展关系标明直接依据或「模型推断」。                                          |
| 遇到失败       | `take off` 的可重试按钮分布在多个失败板块；缺词义时重试下游并不能补齐前置条件。源码还显示：关闭抽屉并不等于停止；局部重新生成失败时，上一批候选仍可能可用。                         | 将一个原始失败和若干“因依赖跳过”分开，优先给出能解锁后续的动作，例如「先添加/补齐短语词性，再生成词义」；回退候选标注「上次成功结果」。关闭与停止应区分。 |
| 保存并离开     | `lead` 在有 22 条例句的情况下点击「保存草稿」，`POST /api/v1/admin/speech/audio` 返回 503，页面保留本地草稿。独立 GET 核实服务器仍是 revision 1、0 个义项。重新打开能恢复本地草稿。 | 一项语音依赖会阻止所有文字保存。不能把「回填成功」写成「已存入词库」。优先提供真实可用的「先保存文本，配音待补」路径，并明确区分本机恢复与服务器已保存。  |

### 草稿回读对照

没有重跑模型、没有改候选，也没有模拟配音成功。在同一评估环境关闭已有的 `VITE_VOICE_PREVIEW` 开关后，分别恢复已有本地草稿并点击保存。独立重新请求词条和各例句：`lantern` revision 2、2 个义项、3 条例句均有译文；`lead` revision 2、11 个义项、22 条例句均有译文；`take off` revision 1、0 项。三条状态仍是 `draft`。这证明文本链可以持久化，**不代表默认配音链通过，也不代表发布校验通过**。

## 优先顺序与可验收目标

1. **先让文字能保存。** 配音不可用时，编辑可以保留所有生成文本到服务器；重新登录后可读回，音频明确为待处理。
2. **修空白短语的起步和错误恢复。** 新建 `take off` 时，要么能生成词义并体现 `The plane took off.` / `Take off your coat.` 的不同用法，要么在开始昂贵的生成前，指出唯一必要的目录补充；不再把依赖缺失显示为多项独立故障。
3. **给编辑一份可审核的批次差异。** `lead` 能识别 `/liːd/` 与 `/led/` 的覆盖或提示分条；`lantern` 不接受循环释义，把上下位与近义区分。保留人工内容，让编辑能只采纳好例句、撤回错误词性，而不必丢弃整份草稿。
