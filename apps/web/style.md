# C 端设计风格

本文件是 `apps/web` 的统一视觉与交互规范，也约束 Web 专用的 `@tsz/ui`。管理端继续使用 antd，不套用本规范。

整体方向：清晰、克制、留白充足。沿用现有落地页的 Apple 风格，以中性背景、品牌蓝、圆润控件和轻层级呈现内容。业务原型用于确认功能和信息层级，不照搬原型的配色、后台布局或标注元素。

## 1. 规范与实现来源

- 颜色与动效值：[globals.css](src/app/globals.css)。组件引用语义 token，完整色值只维护在这里。
- 字体：[共享字体](../../packages/shared/src/fonts.css)。沿用现有字体及中文系统回退，不为单个页面引入新字体。
- 已适配的基础组件：[Button、Input、Label、FormField、Select、Tabs、DropdownMenu](../../packages/ui/src/components/ui/)。从 `@tsz/ui/components` 导入，沿用 Tailwind 与 shadcn/Radix，不复制一份基础样式或引入另一套 UI 库。
- 主题行为：[useTheme](src/features/theme/useTheme.ts)、[主题内核](src/lib/theme.ts)。页面通过 hook 使用主题，不自行操作存储或 `<html>`。
- 品牌来源仍为配套总文档仓库的 `visual.md`；本文件规定 C 端的落地方式。

本规范用于新页面与正在调整的组件；存量页面按实际任务逐步接入。调整公共组件时应核对所有消费者，不为局部视觉修改影响其他页面。

**组件适配边界：** `@tsz/ui` 根出口仍有旧 Button/Card，其中 className 直接拼接，可能产生圆角、颜色等冲突。新增或调整按钮使用 `/components` 出口。该出口的 Card 家族目前仍使用未适配的 `bg-card`、`text-card-foreground` 等 token，且未纳入 C 端 Tailwind 扫描；不要将其当作已完成的 C 端卡片直接接入。卡片目前使用语义化原生容器和下文统一样式，复用同一业务内已有的合适组件。

## 2. 颜色与主题

| 用途                   | Tailwind token                  | 使用原则                         |
| ---------------------- | ------------------------------- | -------------------------------- |
| 页面底色               | `bg-background`                 | 整页统一底色                     |
| 卡片、弹层表面         | `bg-surface`                    | 承载主要内容                     |
| 次级区域、轻反馈       | `bg-muted`                      | 区分层级，避免大面积强调色       |
| 标题、正文、可用菜单项 | `text-foreground`               | 主要可读信息                     |
| 补充说明               | `text-foreground-muted`         | 次要信息，不把正常操作写成禁用灰 |
| 占位及弱辅助信息       | `text-foreground-subtle`        | 不用于重要规则或唯一操作提示     |
| 描边、分隔线           | `border-border`、`bg-border`    | 轻描边，少用分隔线               |
| 主操作、链接、选中强调 | `primary`、`primary-foreground` | 默认品牌蓝                       |
| 蓝色浅底、选中背景     | `bg-primary-muted`              | 小面积强调                       |
| 成功反馈               | `text-success`                  | 配合明确文案                     |
| 错误、危险操作         | `danger`                        | 不用于普通提醒或整个页面染红     |
| 当前学习/教学角标      | `role-student`、`role-teacher`  | 蓝色“学”、绿色“师”，白字         |

- 品牌蓝沿用浅色 `#0071e3`、深色 `#0a84ff`。不要在页面写另一套 `blue-*`、`gray-*` 或十六进制配色。
- 普通卡片和表单正文使用主题文字色；实色主按钮使用 `text-primary-foreground`，实色危险按钮可用白字。
- 认证页品牌区在浅色下使用 `primary`，深色下使用 `primary-muted`，避免暗色模式大面积亮蓝。
- 浅色和深色均检查正文、表面、边框、占位、聚焦、错误和禁用状态。普通文字对比度目标为 4.5:1，大字为 3:1；信息不能只靠颜色表达。
- 主题持久化、跟随系统和水合后恢复由现有主题模块负责。切换主题、刷新页面后不得出现颜色与状态不一致。

## 3. 排版与信息层级

| 层级               | 默认样式                                | 用途                           |
| ------------------ | --------------------------------------- | ------------------------------ |
| 功能页标题         | `text-3xl font-semibold tracking-tight` | 每页一个主标题                 |
| 内容区标题         | `text-xl font-semibold`                 | 钱包、列表、表单分区           |
| 紧凑标题、字段标签 | `text-sm font-medium`                   | 设置项、菜单用户信息、表单标签 |
| 普通正文           | `text-base leading-7`                   | 较长的阅读内容                 |
| 表单、操作、说明   | `text-sm leading-6`                     | 功能页面的主要信息密度         |
| 辅助说明、时间     | `text-xs leading-5`                     | 提示和元信息                   |

- 不把所有文字加粗。同组导航项使用一致字重；主要按钮沿用共享组件的字重，不逐页覆盖。
- 使用真实 `h1/h2/h3` 表达标题层级，不能只靠字号模拟标题。
- 英文词汇与音标沿用 `.tsz-words`、`.tsz-phonetics` 及对应字体变量，不按普通 UI 字号强行覆盖已有阅读规范。
- 长段说明分为短段，数字、单位和时间关系清楚。长昵称、邮箱、流水金额允许截断或换行，不挤坏操作区。

## 4. 页面布局与间距

| 场景                         | 默认容器                                        |
| ---------------------------- | ----------------------------------------------- |
| 账户资料、安全等设置页       | `mx-auto max-w-2xl px-6 py-10 sm:py-14`         |
| 钱包、邀请、学习任务等列表页 | `mx-auto max-w-3xl px-6 py-10 sm:py-14`         |
| 认证表单                     | 最大宽度 400px，输入框与主按钮占满表单宽度      |
| 落地页主体和导航             | 沿用现有 `max-w-5xl` 等分区布局，不套窄表单宽度 |

- 功能页顺序：返回入口 → 标题 → 必要的简短说明 → 内容。页头左对齐，避免同类页面随意切换居中/左对齐。
- 间距以 4px 为基础，优先使用 8、12、16、20、24、32px。同层级间距一致。
- 页头到内容、主要内容区之间通常留 24–32px；相关信息之间留 8–16px。
- 移动端保持单栏、24px 页面边距；密集练习区域可按阅读需要使用 16px。桌面并排的内容和操作在小屏自然换行或纵向排列。
- 认证页桌面使用品牌区与表单双栏，小屏隐藏品牌区。不得靠整体缩放适配手机。
- 验证码输入框使用 `min-w-0 flex-1`，操作按钮不收缩；长提示自然换行，页面不得横向溢出。

## 5. 卡片、圆角与层级

| 元素                                | 默认圆角       | 说明                           |
| ----------------------------------- | -------------- | ------------------------------ |
| 页面内容卡片                        | `rounded-3xl`  | 24px，承载一个清楚的内容组     |
| 菜单、选择弹层、内嵌提示            | `rounded-2xl`  | 16px                           |
| 菜单项、紧凑选择项                  | `rounded-xl`   | 12px                           |
| 标准按钮、单行输入框、Select 触发器 | `rounded-full` | 胶囊形；多行输入区使用容器圆角 |

- 普通卡片使用 `border border-border bg-surface p-6 sm:p-8`；通常靠边框和留白区分内容，不为所有卡片叠加阴影。
- 阴影主要用于菜单、弹层等浮动层，使用轻阴影；避免强阴影、重描边和高饱和背景同时出现。
- 不为一行文字嵌套多层卡片。相关设置项可共用容器，必要时使用内部细分隔线；最后一项下方不保留多余分隔线和空白。

## 6. 按钮与链接

统一使用 `@tsz/ui/components` 的 Button，通过 `variant` 和 `size` 表达层级，不通过追加相互冲突的背景色和圆角拼样式。

| variant       | 用途                                       |
| ------------- | ------------------------------------------ |
| `default`     | 当前步骤的主动作，如登录、下一步、领取奖励 |
| `outline`     | 获取验证码、刷新、翻页、取消等次要动作     |
| `secondary`   | 需要轻填充的不强调操作                     |
| `ghost`       | 返回、密码显隐等轻量操作                   |
| `link`        | 文本型操作                                 |
| `destructive` | 最终提交注销等有破坏性的确认动作           |

- 标准按钮至少 48px 高；`size="sm"` 至少 40px，用于紧凑场景；纯图标按钮触控区域为 44px。同一操作组保持一致高度。
- 简单表单只保留一个主要提交按钮。进入危险操作的前一步仍可使用品牌蓝，红色留给最终危险确认。
- 页面导航使用 Link；需要按钮外观时用 `<Button asChild><Link ... /></Button>`。保留 Button 的 `variant`、`size`、`asChild` 和原生属性；非提交按钮显式设置 `type="button"`。
- 轻量行内操作可用文字链接风格，但必须保留清晰的聚焦和悬停反馈。同一列表中的操作样式一致。
- 禁用使用真实 `disabled`，默认沿用组件的透明度与鼠标状态；不要只变灰却仍可提交。
- 请求中使用具体文案，如“发送中…”“领取中…”，锁定必要控件。客户端防止重复点击，不能代替服务端的幂等和权限校验。
- 倒计时不挤压输入框或导致按钮频繁跳宽；悬停不能作为唯一反馈，键盘焦点必须可见。

## 7. 表单与选择控件

- 简单表单沿用原生 `<form>`、React 状态和已有业务校验，不另引入表单状态框架。组件负责展示、可访问属性与原生行为，不承担请求和权限规则。
- 使用共享 Input 和 FormField。标签始终可见，`htmlFor` 与控件 id 关联；标签和字段提示相对输入框外边缘内缩 16px，与输入文字对齐。
- 输入框高度至少 48px；字段间距通常 20px，标签距控件 8px，提示距控件 8px。
- 字段提示 id 为 `<控件 id>-message`，输入框通过 `aria-describedby` 关联；无效字段设置 `aria-invalid`，同时使用错误描边和文案。
- 字段错误出现在字段下方，并替代普通帮助提示；接口或整张表单错误放在主要操作上方，使用 `role="alert"`。
- 聚焦无效字段仍使用错误色；保留 `type`、`inputMode`、`autoComplete`、ref 和原生禁用属性。
- 密码显隐操作使用共享 Button、明确的“显示密码/隐藏密码”名称和 20px 图标，不触发表单提交，密码状态仍由页面控制。组件迁移保持原有校验时机，登录不套用设置新密码时的长度规则。
- 互斥表单使用共享 Tabs，保留底边线、选中下划线和各状态的主题语义色。表单 Tabs 显式设置手动激活：方向键只移动焦点，回车/空格才确认切换，点击直接切换；仅移动焦点不能清空输入。实际切换按原业务规则清空目标账号和验证码。
- 保留全部 tab/panel 关联，包括非激活面板；只渲染当前表单，避免重复控件 id，请求中锁定切换。

## 8. 账户菜单与图标

- 账户菜单使用共享 DropdownMenu，以当前 [AccountMenu](src/features/home/components/AccountMenu.tsx) 为具体参考。
- 桌面鼠标悬停 120ms 展开，头像在固定触发区域内平滑放大，中心落在浮层顶部边缘，上下各占一半；昵称和身份居中排在头像下方，并为头像预留空间。浮层避让视口时头像同步对齐。移入菜单保持打开，离开后延迟 160ms 收起。
- 头像缩放、位移和阴影使用 300ms 缓出过渡，移开时从当前状态平滑还原；菜单内容以 180ms 淡入、150ms 淡出衔接。过渡必须覆盖实际改变的 CSS 属性；Tailwind 的 `scale`、`translate` 不能只依赖 `transform` 过渡。
- 点击与键盘仍可直接展开/关闭，触摸不依赖悬停。悬停展开不抢占当前输入焦点，开始键盘操作或异步操作后不因鼠标离开而自动收起；头像放大不挤动导航布局，减少动态效果模式下取消过渡。
- 默认宽度 224px、外层内边距 8px；导航菜单项至少 44px 高、12px 圆角、普通字重，正常态统一 `text-foreground`。头部余额用 12px 辅助文字和至少 28px 的紧凑点击行，与昵称靠近排列。
- 用户昵称适度加重，下方用“天生币：5”这样的纯文字展示可进入钱包的余额，不加独立底色和币种图标，不重复标注“学生身份/教师身份”；当前场景通过“学习工作台/教学工作台”表达，教师认证另用徽标表示。余额随菜单展开读取，失败不显示成零。账户菜单仅保留用户信息下方和退出登录上方两条分隔线。
- 展开后的头像右下角显示当前工作台角标：学习为蓝色“学”，教学为绿色“师”，使用独立语义色并加表面色细环。角标随当前工作台变化；认证徽标表示教师资格，不代替当前工作台判断。
- 普通项悬停/键盘高亮使用 `primary-muted`；退出登录正常态沿用正文色，高亮时使用危险色与浅危险背景。
- 菜单导航统一使用 18px 线性图标、1.5px 线宽、同色描边，图标与文字间距 10px。不要同一组中混用 emoji、实心图标和不同线宽。
- 装饰图标设置 `aria-hidden`，图标按钮有可读名称。认证徽标等有独立含义的图标保留必要的可访问名称。
- 菜单和 Select 内容通过 Portal 放到 body，通用弹层沿用 `z-50`；账户资料浮层用 `z-40`，触发头像用 `z-50`，保证头像跨在卡片边缘且不被遮挡。浮层避让视口边缘，超高时可滚动；不在动画容器内自行绝对定位。
- 支持方向键、Esc、Tab 离开和焦点返回。异步动作期间保留必要状态并阻止重复操作，成功关闭、失败展示可操作提示。

## 9. 反馈与文案

- 短句说明动作、结果和下一步。按钮使用明确动词，同一动作保持同一名称。
- 用户界面不展示接口字段、幂等策略、内部状态码、开发测试说明或未来实现方案。调试信息留在开发工具和文档中。
- 帮助文字只说明当前操作需要知道的内容，不在标题、卡片底部和按钮周围重复同一句规则。
- 重要业务限制必须保留，例如注销生效时间、可撤销范围和资产影响；详细规则在确认步骤展示，不能为了简洁删掉风险说明。
- 成功说明实际完成的事情；请求已受理不等同于业务已完成。网络失败或结果不确定时重查服务端状态，不展示虚假成功或把未知余额显示为零。
- 空态说明如何开始，错误态说明如何重试；加载态占位应尽量保持布局稳定。
- 密码的常驻提示为“密码至少 15 位”，具体拒绝原因在错误时说明；简化提示不能改变校验规则。账号安全错误不暴露账号是否存在。

## 10. 动效与验收

- 功能页可沿用 `animate-in`，交互反馈优先使用颜色变化；不要为输入框和常规按钮添加位移、闪烁或循环动画。
- 较复杂的滚动与插画动效限定在落地页等适合的场景，并尊重 `prefers-reduced-motion`；不支持动效时直接显示内容，不隐藏关键操作。
- 改动后核对默认、悬停、键盘聚焦、禁用、请求中、空态、失败和成功状态；纯视觉调整不改变请求、权限或业务规则。
- 检查浅色/深色、手机窄屏和桌面布局，特别是长文案、大金额、验证码按钮及浮层边界。
- 运行与改动相关的检查；页面验收按项目约定使用生产构建和 `next start`，用实际截图与 computed styles 验证尺寸和颜色，不以测试通过替代视觉检查。
