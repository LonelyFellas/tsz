# Admin 界面规范

适用于 `apps/admin` 和 `packages/ui/src/admin`。目标是在现有排版上形成稳定、精细的工具体验：信息易扫读、操作可预期、状态可恢复。保留品牌蓝 `#2053FF`、既有导航和专业编辑器布局。

## 修改前先找依据

1. 读本规范，再看目标页面和下表中最接近的实现；同时核对页面的权限、数据量和异常状态。
2. 优先调整共享变量和已有控件。页面只定义业务结构、响应式排列和业务语义；不要复制组件样式建立另一套按钮、输入框或弹窗。
3. 小改动保持当前页面结构。新增页面复用下述模式；改变导航、业务流程或专业编辑布局需要明确需求。
4. 通用设计技能的审美建议服从本项目规范。不要引入另一套配色、字体或营销式排版。

| 依据                         | 实现位置                                                                                                            | 使用方式                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| 颜色、尺寸、间距、焦点、动效 | [tokens.css](../../packages/ui/src/admin/tokens.css)                                                                | 设计值的唯一来源；页面引用 CSS 变量           |

## 视觉尺度

### 颜色和层次

- `--ui-color-primary`：主要动作、当前选择、可操作链接、键盘焦点。普通容器和大面积背景不用品牌蓝。
- `--ui-color-primary-bg`：选中项的浅底。悬停使用 `--ui-color-fill-secondary` 或组件已有规则，不把 hover 与选中做成相同状态。
- `--ui-color-text`：正文、标题、主要数据；`--ui-color-text-secondary`：说明、字段标签、次要数据。辅助文字仍需可读，不靠低透明度制造层级。
- `--ui-color-bg-layout`：工作区；`--ui-color-bg-container`：内容面；`--ui-color-fill-alter`：表头和轻量分区。
- `--ui-color-border`：可交互控件边界；`--ui-color-border-secondary`：容器和内容分隔。普通内容面使用细边框；浮层使用共享阴影，不给每张卡片增加阴影。
- 错误、成功、警告使用对应语义变量，并有文字或图标表达，不能只靠颜色。
- 允许口音、权限标签、图表序列等业务配色；它们表达业务含义，不能拿来替代品牌色。不得仅为统一而修改现有业务颜色的含义。

### 文字、尺寸与间距

| 角色                 | 默认值                               | 规则                                                                 |
| -------------------- | ------------------------------------ | -------------------------------------------------------------------- |
| 字体                 | `--ui-font-family`                   | 词条与音标使用 Andika；正文和指定字符沿用各自字体                    |
| 页面标题             | `--ui-font-size-title`，24px / 650   | 普通页面使用 `PageHeader`；复杂编辑器保留既有标题层级与结构          |
| 分区标题             | `--ui-font-size-section`，16px / 600 | 标题说明该区内容，避免与页面标题同样突出                             |
| 正文与字段           | `--ui-font-size`，14px               | 表格主要内容与表单使用这一层级                                       |
| 辅助信息             | `--ui-font-size-sm`，12px            | 日期、编号、解释；不可把主要内容全部缩到辅助字号                     |
| 默认控件             | 32px 高、7px 圆角                    | 使用共享默认值，不逐页覆盖                                           |
| 紧凑 / 宽松 / 大控件 | 24 / 36 / 40px                       | 紧凑用于行内操作；词库现有搜索使用宽松尺寸；不因主次等级改变按钮尺寸 |
| 内容面圆角           | `--ui-border-radius-lg`，12px        | 编辑器已有大容器可保留现有圆角与结构                                 |
| 间距                 | `--ui-space-1` 至 `--ui-space-6`     | 4 / 8 / 12 / 16 / 20 / 24px；相关控件紧凑，区块之间留足间隔          |

词条拼写、词形和语法结构使用 `--tsz-font-words`（Andika），首次输入、编辑与回显保持一致；通用控件的默认字体不得覆盖专用字体。

所有音标（含字典音标、实际发音、IPA / UPS 音素）的输入、编辑、预览、列表及下拉选项统一使用 `.tsz-phonetics` / `--tsz-font-phonetics`（Andika）。混排时只标记音标内容，中文标签保留界面字体；共享语音编辑器的输入层与绘制层保持相同字体。

紧凑工具栏与说明可使用 `--ui-font-size-compact`（13px）。共享标题控件明确提供 24 / 20 / 18 / 16px 层级，避免依赖浏览器默认字号。

首页、登录与改密页保留现有专用结构，使用共享标题尺度；登录页宽松控件与品牌插画、词条内容字体和专业编辑网格不改成普通列表模板。

新增样式使用上述变量；列宽、文本测量、拖动手柄和专业编辑网格按业务需要设定，不强制落在间距刻度上。不要把尺寸、颜色或文案逐个抄进单元测试。

## 页面和操作模式

### 列表

- 标题靠左，页面级主要动作靠右。面包屑只表示上层位置，不再重复当前主标题。
- 筛选保持既有提交时机：搜索提交、重置清空并恢复列表；不能仅为统一外观改成逐键请求。
- 表格工具栏左侧放视图、选中状态或批量动作，右侧放列设置等辅助操作。筛选条件、选中数据和分页的关系由既有业务实现决定，不在样式任务中改写。
- 列表使用 `AdminTable`；分页为 1 基。数字使用等宽数字；文本左对齐，需要比较大小的数值列右对齐。
- 长文本只在明确约束的单元格中截断，同时保留既有查看全文的入口。编号、时间和操作不要挤压主内容；横向滚动限制在表格中。
- 无数据与筛选无结果分开表达：前者按权限给已有新建入口，后者给清除筛选入口。请求失败不得伪装成无数据，保留重试。

### 编辑、弹窗和抽屉

- 简短、独立编辑沿用弹窗；需要保留列表上下文的详情沿用抽屉；长流程、多步骤和复杂草稿沿用独立页面。不要在视觉统一时切换承载方式。
- 普通表单用 `@tsz/ui/admin/forms`；复杂草稿继续由业务模型持有，不能更换持久化格式或请求时机。
- 字段标签在对应控件附近，错误放字段旁；错误聚焦真实输入控件。错误焦点保持错误语义，同时保留清晰轮廓。
- 默认底部操作顺序为「取消」「保存」。破坏性动作明确命名并用危险样式，确认文字说明实际影响。
- 英美内容合并复用原编辑面板，在两侧提供「采用此侧」，标明选中侧并显式确认；确认前保留原值，取消不覆盖内容。若合并会舍弃正文、标记、配音或关联，不得默认取一侧。转换覆盖展示当前值与转换结果；已有完整撤销的一键填入沿用撤销交互。
- 提交中保持按钮宽度和文字，展示加载状态并阻止重复提交。提交失败保留输入、选中项和当前步骤；成功后沿用现有关闭、刷新或跳转方式。
- 取消、遮罩关闭、Esc、关闭按钮、未保存内容和请求进行中的规则以业务状态为准。不要全局改写这些行为；修改时同时核对所有退出入口。
- 日期范围只在完整有效或明确清空时提交；隐藏面板保留 `hidden` / `aria-hidden` / `inert` 约定。
- 配音中心采用 1200px 定宽工作区，词条内配音音色池采用 1120px 定宽；音色参数与推荐编辑区按各自宿主保持固定列布局。窄窗口通过外层横向滚动访问，不随窗口缩放或改列；弹层标题、关闭和底部操作保持可达。

### 共用状态

- 按钮使用共享默认、hover、focus、disabled、loading 与 danger 表达。链接型操作的 hover 不变成实体主按钮。
- `Card` 标题栏由共享样式保持垂直居中；业务增加最小高度时沿用此规则，不逐页补对齐样式。
- 输入框使用共享边框和焦点轮廓。禁用区别于只读；禁用原因影响操作时保留可访问说明。
- `Select` 默认下拉菜单最小宽度为 128px（显式自定义宽度除外），并受视口宽度约束；普通选项单行省略，保留悬浮全文，选中图标不挤压文本。倍速、分页等紧凑触发器不能把菜单压成逐字换行；确需多行的业务选项由自定义内容明确设置换行，并单独验收。
- 同一字段的播放、输入、转换、编辑等连体控件使用 `Space.Compact`，由共享样式统一外侧圆角、单线接缝和焦点层级，不逐页拼边框。自定义输入包装层标记 `data-ui-compact-item`，让内部 `.ui-input` / `.ui-input-affix-wrapper` 继承组员圆角；长文本撑高时两侧操作随组拉伸，独立删除操作留在组外。
- `Input` 的 `addonBefore` / `addonAfter` 沿用同一接缝规则。`Space.Compact size` 统一组内按钮、输入、数字输入和下拉框的尺寸，子控件显式指定的尺寸优先；搜索框的尺寸与错误态覆盖整组，聚焦后仍保留错误色。
- 输入即过滤使用带搜索图标的 `Input type="search"`；需要提交时使用 `Input.Search` 并绑定 `onSearch`。启用 `allowClear` 后由共享样式隐藏原生清除按钮，同一输入只保留一个清除入口；未启用时保留原生能力。
- `Radio.Group optionType="button"` 使用连体按钮组；普通单选项、卡片式偏好选项及 `Segmented` 保留各自布局。
- `Radio` / `Radio.Group` 统一封装 shadcn/Radix RadioGroup，保留现有值类型与 `onChange` 接口。圆环和圆点使用控件的 `color`；口音等业务色只作用于实际 Radio，不给外层容器涂选中背景。键盘操作、禁用和表单提交使用同一共享实现。
- 按钮式 Radio 的完整外框和内边距均可点击；候选列表使用同一个 `Radio.Group`，支持方向键切换并跳过禁用项。
- 键盘焦点可见，Tab 顺序跟随阅读顺序；只含图标的操作需要可访问名称。浮层保留既有焦点管理和返回焦点。
- 标签页的选中状态与键盘焦点分别表达；焦点框仅在键盘导航时显示，并贴合标签圆角。词性拖动预览使用实底标签，只显示名称与数量，结束或取消后移除。
- 保留加载时的上下文，刷新不把已有内容瞬间清空。加载、空、错误是不同状态。
- 过渡由 `--ui-motion-duration` / `--ui-motion-easing` 控制；遵守减少动态效果偏好。工具页不做入场编排。

## 响应式与文案

- 页面边距沿用现有外壳，窄屏先让工具栏换行、筛选纵排，表格内部滚动。不要靠无限缩小字号塞下桌面布局。
- 按 1440px 桌面和较窄桌面窗口检查主要动作、长文本、弹窗和滚动，不专门适配或验收手机尺寸。编辑器按自身容器断点检查，不强改为普通表单。
- 中文、英文及较长翻译都不能遮挡操作。使用已有 i18n 模块，保持日期和数字的既有本地化约定。
- 标题说用途，按钮说动作。只保留影响理解、决策、输入或纠错的说明；不加欢迎语、口号、设计说明和泛化安全背书。

## 防止后续偏离

- 根 [AGENTS.md](../../AGENTS.md) 是 AI 的读取入口；本文件维护规则，变量文件维护值，组件维护行为，避免多处复制。
- `pnpm check:admin-ui` 自动扫描 `apps/admin/src` 与 `packages/ui/src/admin` 的全部 CSS，仅排除设计变量定义文件；检查重复品牌色、覆盖共享设计变量及无 fallback 的未定义设计变量。新增页面和共享样式自动纳入，无需维护样板名单。
- 检查接入 `@tsz/ui` 的 lint，因此仓库 `pnpm lint` 和既有 CI 会执行。admin ESLint 同时禁止重新引入 AntD、MUI、Emotion。
- 全部后台样式已接入共同变量和检查；口音、权限标签、图表及品牌插画等业务配色保留其含义。自动检查不证明视觉一致，页面修改仍需浏览器验收，不为通过检查追加忽略名单。
- 修改公共视觉规则时，规范、变量和受影响样板一起更新。页面确有例外时在对应规则旁说明业务原因；一次局部试验不自动升级为全局标准。

## 验收

按改动风险选用，已验证且输入未变的结果可复用：

1. 代码：格式、受影响 ESLint / 类型检查通过；共享控件变化运行已有表单、浮层、表格与业务回归。
2. 视觉：对照以上样板，检查桌面与窄屏、真实长度内容、主次动作、控件对齐、颜色与焦点。
3. 交互：检查此次影响的加载、空、错误、权限、提交和取消；重试后不丢失输入，浮层可以按业务规则退出。
4. 数据：样式验收可用明确标记的本地 fixture；涉及真实接口和持久化时，另按项目真实后端验收要求执行并清理临时数据。
5. 交付：分别报告代码检查、浏览器核验、真实后端、PR / CI 和部署状态；未运行的阶段明确标记。
